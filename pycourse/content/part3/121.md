# 12.1 SQL на собеседовании

## В каком порядке выполняется запрос:
```sql
SELECT category, SUM(qty * price) AS revenue     -- 5. вычислить выражения
FROM orders o                                    -- 1. откуда
JOIN order_items i ON i.order_id = o.id          --    соединить
WHERE o.status = 'paid'                          -- 2. отфильтровать строки
GROUP BY category                                -- 3. сгруппировать
HAVING SUM(qty * price) > 1000                   -- 4. отфильтровать группы
ORDER BY revenue DESC                            -- 6. отсортировать
LIMIT 10;                                        -- 7. обрезать
```
Отсюда объясняются почти все «почему не работает»: агрегат нельзя использовать в `WHERE` (группировки ещё нет), алиас из `SELECT` нельзя использовать в `WHERE`, а в `ORDER BY` — можно; оконные функции считаются после `WHERE` и `GROUP BY`, поэтому фильтровать по ним можно только во внешнем запросе или CTE.

## Соединения:
| JOIN | Что остаётся |
|---|---|
| `INNER JOIN` | только пары, где условие выполнилось |
| `LEFT JOIN` | все строки слева; справа — `NULL`, если пары нет |
| `RIGHT JOIN` | зеркально: все справа (то же, что LEFT с переставленными таблицами) |
| `FULL JOIN` | все строки с обеих сторон |
| `CROSS JOIN` | декартово произведение |

Классика «кто без заказов»: `LEFT JOIN … WHERE o.id IS NULL` или `NOT EXISTS`.

::: quiz output q121-1 собес
Что выведет программа?
```python
import sqlite3
c = sqlite3.connect(":memory:")
c.executescript("""
CREATE TABLE users(id, name);
INSERT INTO users VALUES (1, 'ann'), (2, 'bob');
CREATE TABLE orders(user_id, status);
INSERT INTO orders VALUES (1, 'paid'), (1, 'new');
""")
q1 = """SELECT u.name, COUNT(o.user_id) FROM users u
        LEFT JOIN orders o ON o.user_id = u.id AND o.status = 'paid'
        GROUP BY u.name ORDER BY u.name"""
q2 = """SELECT u.name, COUNT(o.user_id) FROM users u
        LEFT JOIN orders o ON o.user_id = u.id
        WHERE o.status = 'paid'
        GROUP BY u.name ORDER BY u.name"""
print(c.execute(q1).fetchall())
print(c.execute(q2).fetchall())
```
--- answer
[('ann', 1), ('bob', 0)]
[('ann', 1)]
--- why
Условие на правую таблицу в `WHERE` превращает `LEFT JOIN` во `INNER`: у bob нет пары, `o.status` равно `NULL`, и `NULL = 'paid'` — не истина, строка отфильтровывается. Чтобы сохранить всех слева, условие на правую таблицу пишут в `ON`. `COUNT(o.user_id)` не считает `NULL`, а `COUNT(*)` посчитал бы для bob единицу.
:::

## NULL — трёхзначная логика:
- `NULL = NULL` — не истина, а `NULL` (неизвестно). Проверка — `IS NULL`
- агрегаты (`SUM`, `AVG`, `COUNT(col)`) пропускают `NULL`; `COUNT(*)` считает строки
- `COALESCE(x, 0)` — подставить значение вместо `NULL`

::: quiz output q121-2 собес
Что выведет программа?
```python
import sqlite3
c = sqlite3.connect(":memory:")
c.executescript("""
CREATE TABLE a(x); INSERT INTO a VALUES (1), (2), (3);
CREATE TABLE b(y); INSERT INTO b VALUES (2), (NULL);
""")
print(c.execute("SELECT COUNT(*) FROM a WHERE x NOT IN (SELECT y FROM b)").fetchone()[0])
print(c.execute("SELECT COUNT(*) FROM a WHERE NOT EXISTS (SELECT 1 FROM b WHERE b.y = a.x)").fetchone()[0])
print(c.execute("SELECT COUNT(*), COUNT(y), AVG(y) FROM b").fetchone())
```
--- answer
0
2
(2, 1, 2.0)
--- why
Самая коварная ловушка SQL: `x NOT IN (2, NULL)` — это `x <> 2 AND x <> NULL`, а второе всегда `NULL`, поэтому условие никогда не истинно, и результат пуст. `NOT EXISTS` с `NULL` работает как ожидается. Правило: для «нет в другой таблице» используй `NOT EXISTS` или `LEFT JOIN … IS NULL`.
:::

## Оконные функции — их спрашивают почти всегда:
`функция() OVER (PARTITION BY … ORDER BY … [рамка])` считает значение для каждой строки по «окну» связанных строк, **не схлопывая** строки, в отличие от `GROUP BY`.
| Функция | Для чего |
|---|---|
| `ROW_NUMBER()` | номер строки в группе: 1, 2, 3, 4 |
| `RANK()` | с пропусками при равенстве: 1, 2, 2, 4 |
| `DENSE_RANK()` | без пропусков: 1, 2, 2, 3 |
| `SUM(x) OVER (ORDER BY day)` | нарастающий итог |
| `LAG(x)`, `LEAD(x)` | значение из предыдущей и следующей строки: рост к прошлому периоду |
| `AVG(x) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` | скользящее среднее за 7 дней |

::: quiz output q121-3
Что выведет программа?
```python
import sqlite3
c = sqlite3.connect(":memory:")
c.executescript("""
CREATE TABLE s(name, dept, salary);
INSERT INTO s VALUES ('a', 'x', 300), ('b', 'x', 200), ('c', 'x', 200), ('d', 'x', 100), ('e', 'y', 50);
""")
rows = c.execute("""
    SELECT name,
           ROW_NUMBER() OVER w, RANK() OVER w, DENSE_RANK() OVER w
    FROM s
    WINDOW w AS (PARTITION BY dept ORDER BY salary DESC, name)
    ORDER BY dept, salary DESC, name
""").fetchall()
for r in rows:
    print(*r)
```
--- answer
a 1 1 1
b 2 2 2
c 3 3 3
d 4 4 4
e 1 1 1
--- why
Ловушка в определении окна: в `ORDER BY` окна добавлено `name`, поэтому равных строк нет — и все три функции совпали. Ранги различаются только тогда, когда значения `ORDER BY` окна равны. Если оставить `ORDER BY salary DESC`, получится `b 2 2 2` и `c 3 2 2`, а `d` — `4 4 3`. Для «топ-2 зарплаты в отделе с учётом равных» берут `DENSE_RANK` по одной зарплате.
:::

## Топ-N в группе — каркас:
```sql
WITH ranked AS (
    SELECT department, name, salary,
           DENSE_RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS r
    FROM employees
)
SELECT department, name, salary FROM ranked WHERE r <= 2;
```

::: quiz choice q121-4 собес
Чем `WHERE` отличается от `HAVING`?
- [ ] ничем, это синонимы
- [x] `WHERE` фильтрует строки до группировки и не видит агрегатов, `HAVING` фильтрует группы после `GROUP BY` и работает с агрегатами
- [ ] `HAVING` быстрее
- [ ] `WHERE` нельзя использовать вместе с `GROUP BY`
--- why
Условие на обычные столбцы лучше писать в `WHERE`: строки отбрасываются до дорогой группировки, и может использоваться индекс. В `HAVING` — только условия на агрегаты: `HAVING COUNT(*) > 5`.
:::

## Вопросы с собеседования по уроку:
::: quiz open q121-5 собес
Чем LEFT JOIN отличается от INNER JOIN? Что такое оконные функции и чем они отличаются от GROUP BY?
--- answer
`INNER JOIN` оставляет только строки, для которых нашлась пара по условию соединения. `LEFT JOIN` оставляет все строки левой таблицы; если пары нет, столбцы правой — `NULL`. `RIGHT JOIN` — зеркально, `FULL` — все с обеих сторон. Ловушка: условие на правую таблицу в `WHERE` после `LEFT JOIN` отбрасывает строки с `NULL` и превращает соединение во внутреннее — такие условия пишут в `ON`. Оконные функции (`… OVER (PARTITION BY … ORDER BY …)`) вычисляют значение для каждой строки по набору связанных строк, не схлопывая их, тогда как `GROUP BY` превращает группу в одну строку. Применения: ранжирование (`ROW_NUMBER`, `RANK`, `DENSE_RANK` — различаются обработкой равных), топ-N в группе, нарастающие итоги, `LAG`/`LEAD` для сравнения с предыдущим периодом, скользящие средние с рамкой `ROWS BETWEEN`. Окна вычисляются после `WHERE`/`GROUP BY`/`HAVING`, поэтому фильтровать по их результату можно только во внешнем запросе или CTE.
--- points
- INNER против LEFT, NULL справа
- условие в ON против WHERE
- окна не схлопывают строки, в отличие от GROUP BY
- ROW_NUMBER / RANK / DENSE_RANK и равные значения
- нарастающий итог, LAG/LEAD
- порядок выполнения: фильтр по окну — во внешнем запросе
:::
