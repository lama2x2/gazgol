# 11.3 Код-ревью и поиск ошибок

## Формат:
Всё чаще вместо «напиши» дают «вот код, что с ним не так?»: Сбер, Wildberries, Ozon. Проверяют внимательность, знание подводных камней языка и инженерный кругозор. За 20 минут нужно найти как можно больше проблем **и расставить приоритеты**.

## Чек-лист ревьюера — иди сверху вниз:
1. **Корректность**: граничные случаи (пусто, один элемент, границы диапазонов), ошибки на единицу, неправильные условия, забытый `return`, изменение коллекции при обходе
2. **Ловушки Python**: изменяемые аргументы по умолчанию, позднее связывание в замыканиях, `is` вместо `==`, общий список через `*`, мутация входных данных, `except:` без типа, `return` в `finally`
3. **Безопасность**: SQL-инъекции (f-строки в запросах), секреты в коде, пароли без хеширования, `eval`/`pickle` на недоверенных данных, отсутствие проверки прав
4. **Ресурсы и надёжность**: незакрытые файлы и соединения (нет `with`), отсутствие таймаутов у сетевых вызовов, ретраи без backoff, проглоченные исключения
5. **Конкурентность**: гонки check-then-act, блокирующие вызовы в `async def`, общее изменяемое состояние
6. **Производительность**: N+1 запросы к БД, O(n²) там, где можно O(n), загрузка всего в память
7. **Дизайн и читаемость**: имена, длина функций, дублирование, жёсткие зависимости, тестируемость

::: py Как подавать замечания
Начни с самого опасного («здесь SQL-инъекция — это блокер»), отделяй блокеры от стиля, к каждому замечанию — **почему** это плохо и **как** исправить. «Здесь `requests.get` без таймаута: если сервис повиснет, повиснет и воркер. Добавить `timeout=5` и ретраи с backoff».
:::

::: quiz review q113-1 собес
Найди проблемы в Django-представлении:
```python
def order_list(request):
    orders = Order.objects.filter(user_id=request.GET["user"])
    result = []
    for o in orders:
        items = [{"name": i.product.name, "price": i.product.price} for i in o.items.all()]
        result.append({"id": o.id, "total": sum(x["price"] for x in items), "items": items})
    return JsonResponse(result, safe=False)
```
--- answer
- **N+1 (и даже N·M+1) запросов**: на каждый заказ — запрос `o.items.all()`, на каждую позицию — запрос за `product`. Исправление: `Order.objects.filter(...).prefetch_related("items__product")` (или `Prefetch` с `select_related("product")`) — три запроса вместо тысяч
- **нет проверки прав**: `user` берётся из параметра запроса — любой может смотреть чужие заказы (IDOR). Нужно `request.user` и `@login_required`
- `request.GET["user"]` бросит `KeyError` → 500 вместо 400
- **нет пагинации**: у пользователя с 10 000 заказов ответ огромный
- сумма считается в Python, хотя можно `annotate(total=Sum("items__product__price"))`; к тому же цена берётся **текущая** из продукта, а не цена на момент заказа — бизнес-ошибка: цену нужно хранить в позиции заказа
- денежные значения — `Decimal`, а `JsonResponse` не сериализует `Decimal` без настройки
- сериализация вручную → DRF-сериализатор или схема pydantic
--- points
- N+1 и prefetch_related / select_related
- проверка прав, IDOR
- KeyError → 500, валидация входа
- пагинация
- цена на момент заказа, Decimal
:::

::: quiz review q113-2 собес
Найди проблемы в асинхронном коде:
```python
import asyncio, requests

cache = {}

async def get_rate(currency):
    if currency not in cache:
        resp = requests.get(f"https://api.example.com/rate/{currency}")
        cache[currency] = resp.json()["rate"]
    return cache[currency]

async def convert_all(amounts):
    result = []
    for cur, amount in amounts:
        rate = await get_rate(cur)
        result.append(amount * rate)
    return result
```
--- answer
- **блокирующий `requests.get` в `async def`** замораживает цикл событий: все остальные запросы сервиса ждут. Нужен асинхронный клиент (`httpx.AsyncClient`, `aiohttp`) или `asyncio.to_thread`
- **нет таймаута** — зависший API повесит обработчик навсегда
- **нет обработки ошибок**: не проверяется статус ответа (`raise_for_status`), нет ретраев
- **кэш без TTL и ограничения размера**: курсы устаревают, а память растёт
- **cache stampede**: при одновременных запросах одной валюты все пойдут в API (после перехода на асинхронный клиент между проверкой и записью появится `await`) — нужен `asyncio.Lock` на ключ или общая задача (singleflight)
- **последовательные запросы** в `convert_all`: разные валюты можно запрашивать конкурентно — `gather` по уникальным валютам с семафором
- `float` для денег → `Decimal`
- клиент создаётся на каждый запрос (в случае httpx) → один клиент на приложение с пулом соединений
--- points
- блокирующий вызов в async
- таймаут и обработка ошибок
- кэш без TTL и stampede
- последовательные запросы → gather с семафором
- Decimal для денег, переиспользование клиента
:::

::: quiz bug q113-3
Что не так с этой функцией?
```python
def add_tag(tag, tags=[]):
    if tag not in tags:
        tags.append(tag)
    return tags

user1 = add_tag("python")
user2 = add_tag("go")
```
- [ ] `in` для списка не работает со строками
- [x] список по умолчанию общий для всех вызовов: у `user2` окажутся и `python`, и `go`
- [ ] `append` возвращает `None`
- [ ] всё правильно
--- why
Повторение урока 2.1 — на ревью эту ошибку ищут первой. Исправление: `tags=None` и `tags = [] if tags is None else tags`. Плюс вопрос к дизайну: функция и мутирует аргумент, и возвращает его — лучше выбрать что-то одно.

## Вопросы с собеседования по уроку:
::: quiz open q113-4
Что ты проверяешь в первую очередь, когда ревьюишь чужой код?
--- answer
Сначала понимаю задачу — что изменение должно делать (описание, тикет, тесты), иначе невозможно судить о корректности. Дальше по приоритету: корректность и граничные случаи; безопасность (инъекции, права доступа, секреты, недоверенные данные); надёжность (обработка ошибок, таймауты и ретраи у внешних вызовов, транзакции и атомарность, идемпотентность фоновых задач); данные и миграции (обратная совместимость, блокирующие миграции на больших таблицах); производительность (N+1, лишние запросы, сложность алгоритмов, загрузка в память); конкурентность; затем — читаемость, дизайн и тесты: покрыты ли новые ветки и граничные случаи. Замечания формулирую с причиной и предложением, отделяю блокеры от необязательного («nit»), не спорю о вкусе там, где есть линтер и автоформатер. Большой пулл-реквест прошу разбить.
--- points
- понять задачу изменения
- корректность и граничные случаи
- безопасность
- надёжность: ошибки, таймауты, транзакции, идемпотентность
- миграции и производительность
- тесты; формулировка замечаний и приоритеты
:::
