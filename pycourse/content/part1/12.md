# 1.2 Как решать задачу на лайвкоде

## Алгоритм на каждую задачу:
1. **Перескажи условие своими словами** и разбери пример из условия руками
2. **Уточни ограничения**: размер входа, диапазон чисел, могут ли быть пустые данные, повторы, отрицательные. Что вернуть, если ответа нет?
3. **Предложи простое решение** (часто перебор) и назови его сложность. Это страховка: тебе уже есть что писать
4. **Улучши**: где лишняя работа? Что можно запомнить в словаре? Можно ли отсортировать? Назови новую сложность
5. **Договорись** с интервьюером и только потом **пиши код**, проговаривая крупные шаги
6. **Проверь сам**: прогони пример строка за строкой, затем граничные случаи. Только после этого скажи «готово»

По времени на секции в час с двумя задачами: первая задача должна быть решена к 25–30-й минуте.

## Граничные случаи, которые надо проверять всегда:
- пустой ввод: `[]`, `""`, `0`
- один элемент
- все элементы одинаковые
- уже отсортировано и отсортировано в обратном порядке
- отрицательные числа и ноль
- ответ в самом начале или в самом конце: здесь живут ошибки «на единицу» и «забыл последний отрезок»

## Сложность: что нужно уметь
**O-большое** описывает, как растёт время или память при росте входа n. Константы и младшие слагаемые отбрасываем: `3n² + 5n` → O(n²).

| Сложность | Пример | n = 10⁶ — успеет за секунду? |
|---|---|---|
| O(1) | доступ по индексу, `x in set` | да |
| O(log n) | бинарный поиск | да |
| O(n) | один проход по списку | да |
| O(n log n) | `sorted()` | да |
| O(n²) | два вложенных цикла | нет: ~10¹² операций |
| O(2ⁿ) | все подмножества | только при n ≤ 20–25 |

Прикидка для Python: **~10⁷ простых операций в секунду**. Если n ≤ 10⁵, O(n²) уже не годится.

## Стоимость операций Python, которую спрашивают:
| Операция | list | dict / set |
|---|---|---|
| `x in c` | O(n) | O(1) в среднем |
| `c[i]`, `d[k]` | O(1) | O(1) в среднем |
| `append` / `add` | O(1) амортизированно | O(1) в среднем |
| `insert(0, x)`, `pop(0)` | **O(n)** — сдвиг всех элементов | — |
| `pop()` с конца | O(1) | — |
| срез `a[i:j]` | O(j − i) — это **копия** | — |
| `sorted`, `list.sort` | O(n log n), Timsort, стабильная | — |
| `"".join(parts)` | O(общей длины) | — |

::: warn Скрытые O(n) в «одной строчке»
`if x in lst` внутри цикла — это уже O(n²). `s += ch` в цикле для строк — может быть квадратичным (строки неизменяемы; CPython иногда оптимизирует, но рассчитывать на это нельзя). `lst.pop(0)` в цикле — O(n²), для очереди нужен `deque`.
:::

::: quiz choice q12-1 собес
Какая сложность у этого кода?
```python
def has_common(a, b):
    for x in a:
        if x in b:
            return True
    return False
```
- [ ] O(n) всегда
- [x] O(n·m), если `b` — список, и O(n), если `b` — множество
- [ ] O(log n)
- [ ] O(n + m) всегда
--- why
`x in b` для списка — линейный поиск, O(m), и он повторяется для каждого из n элементов `a`. Для множества `in` — хеш-поиск за O(1) в среднем. Правильный ответ на собесе — `set(b)` заранее (O(m)) и итог O(n + m). Можно и короче: `not set(a).isdisjoint(b)`.
:::

## Разбор задачи — как это звучит вслух:
::: solve Сжать список чисел в диапазоны (VK)
**Условие:** `[1, 4, 5, 2, 3, 9, 8, 11, 0]` → `"0-5,8-9,11"`.

*«Уточню: числа могут повторяться? Пустой список — пустая строка? Хорошо. Идея: отсортировать, затем один проход, в котором я держу начало текущего отрезка. Когда следующее число не продолжает отрезок — закрываю его. O(n log n) из-за сортировки, O(n) памяти на результат».*
```python
def compress(nums):
    if not nums:
        return ""
    nums = sorted(set(nums))
    parts = []
    start = prev = nums[0]
    for x in nums[1:]:
        if x == prev + 1:
            prev = x
            continue
        parts.append(f"{start}-{prev}" if start != prev else str(start))
        start = prev = x
    parts.append(f"{start}-{prev}" if start != prev else str(start))  # последний отрезок!
    return ",".join(parts)
```
*«Проверяю на примере: после сортировки 0,1,2,3,4,5,8,9,11. Отрезок 0–5 закрывается на восьмёрке, 8–9 — на одиннадцати, 11 добавляется после цикла. Граничные: пустой — ""; один элемент — "7"; повторы убрал через set».*
:::
Типичные ошибки на этой задаче из реальных собесов: забыли отсортировать, потеряли последний отрезок, оставили лишнюю запятую, упали на пустом списке. Чистое решение за 12 минут — высшая оценка.

::: quiz bug q12-2
Кандидат решил задачу «найти максимальное число в списке». Что не так?
```python
def max_value(nums):
    best = 0
    for x in nums:
        if x > best:
            best = x
    return best
```
- [ ] цикл пропускает последний элемент
- [x] для списка из отрицательных чисел вернётся 0, которого в списке нет; а пустой список молча даёт 0 вместо ошибки
- [ ] `>` надо заменить на `>=`
- [ ] всё правильно
--- why
Начальное значение «0» — классическая ошибка. Нужно начинать с первого элемента (`best = nums[0]`) или с `float("-inf")`, а пустой список явно обработать: вернуть `None` или бросить `ValueError`, как это делает встроенная `max([])`. Об этом и стоит спросить интервьюера.
:::

::: hw 12
* `compress_ranges` — сжать числа в диапазоны: `[1,4,5,2,3,9,8,11,0]` → `"0-5,8-9,11"` (VK) {test_compress_ranges}
+ Отсортируй уникальные числа, иди одним проходом, держа начало и конец текущего отрезка. Отрезок закрывается, когда число не равно `prev + 1`. Отрезок из одного числа пишется без дефиса.
! Не потеряй последний отрезок после цикла. Пустой список → `""`. Отрицательные числа: `[-3,-2,-1]` → `"-3--1"`.
* `longest_non_decreasing` — длина самого длинного неубывающего непрерывного отрезка (первая задача Яндекса) {test_longest_non_decreasing}
+ Один проход: текущая длина `cur` растёт, пока `a[i] >= a[i-1]`, иначе сбрасывается в 1. Ответ — максимум `cur`.
! Пустой список → 0. Равные соседи не обрывают отрезок: `[2, 2, 2]` → 3.
* `clock_angle` — меньший угол между стрелками часов в градусах (h от 0 до 23, m от 0 до 59) {test_clock_angle}
+ Минутная стрелка: `6 * m` градусов. Часовая: `30 * (h % 12) + 0.5 * m` — она тоже движется в течение часа. Разница по модулю, затем `min(d, 360 - d)`.
! В 3:30 ответ 75, а не 90: часовая стрелка уже ушла с тройки. В 12:00 и 0:00 — 0.
* `is_monotonic` — проверить, что список монотонный: неубывающий или невозрастающий (Ozon) {test_is_monotonic}
+ Один проход с двумя флагами: `inc` становится False, если встретили спад, `dec` — если подъём. Ответ — `inc or dec`.
! Пустой список и список из одного элемента — монотонные. Не сортируй ради проверки: это O(n log n) вместо O(n).
* `max_dist_to_closest ★` — в ряду кинотеатра (1 — занято, 0 — свободно) найти место, максимально далёкое от ближайшего зрителя, и вернуть это расстояние (VK, LeetCode 849) {test_max_dist_to_closest}
+ Пройди и запомни позиции единиц. Ответ — максимум из трёх величин: число нулей до первой единицы (сесть у стены слева), число нулей после последней единицы, и `(разрыв между соседними единицами) // 2` для мест в середине.
! Края считаются иначе, чем середина: в `[0,0,0,1]` ответ 3 (сесть у стены), а не 1. Гарантируется хотя бы одна 1 и хотя бы один 0.

## Вопросы с собеседования по уроку:
::: quiz open q12-3 собес
Ты написал решение. Как ты его проверишь, если код нельзя запустить?
--- answer
Сначала прохожу пример из условия строка за строкой и записываю значения переменных на каждом шаге — так находятся ошибки на единицу и перепутанные условия. Затем проверяю граничные случаи: пустой ввод, один элемент, все одинаковые, ответ в начале и в конце, отрицательные числа, максимальный размер (влезет ли по времени и памяти). Отдельно смотрю места, где обычно ошибаются: границы циклов и срезов, обновление переменных после цикла (последний отрезок), деление на ноль, изменение коллекции во время обхода. Называю итоговую сложность по времени и памяти. Если нашёл баг — говорю об этом вслух и исправляю: найти ошибку самому — это плюс, а не минус.
--- points
- трассировка примера из условия по шагам
- граничные случаи: пусто, один элемент, повторы, края
- типичные места ошибок: границы, последний элемент
- итоговая сложность
- найденный баг исправляешь вслух
:::
