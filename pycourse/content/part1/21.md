# 2.1 Всё — объект: имена, ссылки, изменяемость

## Переменная — это имя, а не коробка:
В Python у каждого значения есть **объект** с тремя свойствами: `id` (адрес, не меняется), `type` (не меняется) и значение. Переменная — это **имя, привязанное к объекту**. Присваивание `b = a` не копирует объект, а привязывает второе имя к тому же объекту.
```python
a = [1, 2]
b = a           # одно и то же: id(a) == id(b)
b.append(3)
print(a)        # [1, 2, 3]
b = [9]         # перепривязали b; a не изменился
```

## Изменяемые и неизменяемые:
| Неизменяемые (immutable) | Изменяемые (mutable) |
|---|---|
| `int`, `float`, `bool`, `str`, `bytes`, `tuple`, `frozenset`, `None` | `list`, `dict`, `set`, `bytearray`, объекты своих классов |

«Изменить» неизменяемый объект нельзя: `s += "!"` создаёт **новую** строку и перепривязывает имя. Но `tuple` неизменяем только поверхностно: если внутри список, сам список менять можно.

## `is` против `==`:
- `==` сравнивает **значения** (вызывает `__eq__`)
- `is` сравнивает **идентичность**: это один и тот же объект? (`id(a) == id(b)`)
- `is` используют для синглтонов: `x is None`, `x is True`. Для чисел и строк — только `==`

CPython заранее создаёт целые от −5 до 256 и переиспользует их, а короткие строки-идентификаторы интернирует. Поэтому `a is b` для малых чисел иногда «работает» — но это деталь реализации, а не гарантия языка.

::: quiz output q21-1 собес
Что выведет программа?
```python
a = int("256")
b = int("256")
print(a is b)
c = int("257")
d = int("257")
print(c is d, c == d)
```
--- answer
True
False True
--- why
Числа от −5 до 256 CPython берёт из заранее созданного кэша, поэтому `a` и `b` — один объект. 257 создаётся заново при каждом вызове `int()`, и `is` даёт False. Если написать литералы `c = 257; d = 257` в одном файле, компилятор может слить одинаковые константы, и результат будет другим. Именно поэтому на `is` для чисел полагаться нельзя.
:::

## Как передаются аргументы:
Ни «по значению», ни «по ссылке», а **по соиспользованию (call by sharing)**: функция получает ссылку на тот же объект. Изменение объекта видно снаружи, а перепривязка параметра — нет.

::: quiz output q21-2 собес
Что выведет программа?
```python
def f(lst, n):
    lst.append(1)
    lst = [0]
    n += 1

a, k = [], 5
f(a, k)
print(a, k)
```
--- answer
[1] 5
--- why
`lst.append(1)` меняет тот же список, что и снаружи. `lst = [0]` перепривязывает локальное имя — список снаружи не трогается. `n += 1` для int создаёт новый объект и перепривязывает локальное `n`.
:::

## Изменяемый аргумент по умолчанию:
Значения по умолчанию вычисляются **один раз — при выполнении `def`** и хранятся в `f.__defaults__`. Список по умолчанию общий для всех вызовов.
::: quiz output q21-3 собес
Что выведет программа?
```python
def add(x, items=[]):
    items.append(x)
    return items

print(add(1))
print(add(2))
print(add(3, []))
print(add(4))
```
--- answer
[1]
[1, 2]
[3]
[1, 2, 4]
--- why
Все вызовы без второго аргумента делят один список из `add.__defaults__`. Вызов с явным `[]` работает со своим списком. Правильный идиоматичный вариант: `items=None`, а внутри `if items is None: items = []`.
:::

## Ловушки с копированием:
::: quiz output q21-4 собес
Что выведет программа?
```python
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)
```
--- answer
[[1, 0, 0], [1, 0, 0], [1, 0, 0]]
--- why
`[row] * 3` создаёт список из трёх ссылок на **один и тот же** внутренний список. Правильно: `[[0] * 3 for _ in range(3)]` — новый список на каждой итерации. С числами `[0] * 3` проблемы нет: они неизменяемы, и «изменение» ячейки — это перепривязка.
:::

- **поверхностная копия** (`lst[:]`, `list(lst)`, `lst.copy()`, `copy.copy`) — новый внешний контейнер, но внутри те же объекты
- **глубокая копия** (`copy.deepcopy`) — рекурсивно копирует всё и правильно обрабатывает циклические ссылки (хранит словарь `memo` с уже скопированными объектами)

::: quiz output q21-5
Что выведет программа?
```python
t = (1, [2])
try:
    t[1] += [3]
except TypeError:
    print("TypeError")
print(t)
```
--- answer
TypeError
(1, [2, 3])
--- why
Знаменитый пример из «Fluent Python». `t[1] += [3]` выполняется в два шага: сначала `list.__iadd__` расширяет список **на месте** (успешно), затем результат присваивается в `t[1]` — и это падает, потому что кортеж неизменяем. Ошибка есть, но список уже изменён. Мораль: не кладите изменяемые объекты в кортежи, если от кортежа ждёте неизменяемости.
:::

## Хешируемость:
Объект **хешируемый**, если у него есть `__hash__`, хеш не меняется за время жизни и согласован с `__eq__`: равные объекты имеют равные хеши. Только такие объекты могут быть ключами `dict` и элементами `set`. Встроенные неизменяемые типы хешируемы; `tuple` и `frozenset` — если хешируемо всё внутри. `list`, `dict`, `set` — нет.

::: quiz choice q21-6
Какие из этих выражений упадут с `TypeError: unhashable type`? Отметь все.
- [x] `{[1, 2]: "a"}`
- [ ] `{(1, 2): "a"}`
- [x] `{(1, [2]): "a"}`
- [ ] `{frozenset({1, 2}): "a"}`
- [x] `{1, 2, {3}}`
--- why
Ключ должен быть хешируемым целиком. Кортеж со списком внутри не хешируется, потому что список может измениться и сломать хеш. Множество внутри множества — нельзя, а `frozenset` — можно.
:::

+ Стандартная идиома: `items=None`, внутри `if items is None: items = []`. Затем `append` и вернуть список.
! Не пиши `items = items or []`: пустой список, переданный явно, тогда заменится новым, и изменения не дойдут до вызывающего.
* `make_grid` — сетка rows × cols, где у каждой строки свой список {test_make_grid}
+ Генератор списков: `[[fill] * cols for _ in range(rows)]`.
! `[[fill] * cols] * rows` проходит проверку на вид, но все строки — один объект. Тест меняет одну ячейку и смотрит на остальные.
* `deep_copy` — глубокая копия вложенных list / dict / tuple / set без модуля `copy` {test_deep_copy}
+ Рекурсия по типу: для `list` — `[deep_copy(x) for x in obj]`, для `dict` — копия ключей и значений, для `tuple` и `set` — аналогично, всё остальное (числа, строки, None) возвращай как есть.
! Ключи словаря и элементы множества — хешируемые и, значит, обычно неизменяемые. Копировать их не обязательно, но и не вредно.
* `dedupe` — убрать повторы с сохранением порядка за O(n) {test_dedupe}
+ Множество `seen` для уже встреченных и список результата. `x in seen` — O(1), поэтому весь проход O(n).
! `if x not in result` — это O(n) на каждую проверку, итого O(n²). Тест подаёт 200 000 элементов, и квадратичное решение не уложится по времени.
* `freeze ★` — превратить вложенную структуру из list / dict / set в хешируемую, чтобы использовать её как ключ кэша {test_freeze}
+ Рекурсивно: `list` и `tuple` → `tuple(freeze(x) …)`, `set` → `frozenset(…)`, `dict` → `frozenset((k, freeze(v)) for k, v in d.items())`. Остальное — как есть.
! Для `dict` порядок ключей не должен влиять на результат: `{"a": 1, "b": 2}` и `{"b": 2, "a": 1}` равны — значит, и замороженные версии должны быть равны. Поэтому `frozenset`, а не `tuple(d.items())`.

## Вопросы с собеседования по уроку:
::: quiz open q21-7 собес
Чем изменяемые типы отличаются от неизменяемых? Приведи примеры и объясни, почему это важно на практике.
--- answer
Неизменяемый объект нельзя изменить после создания: любая «модификация» создаёт новый объект (`int`, `float`, `str`, `bytes`, `tuple`, `frozenset`, `None`). Изменяемый меняется на месте, и все имена, ссылающиеся на него, видят изменения (`list`, `dict`, `set`, объекты своих классов). Почему это важно: только неизменяемые (точнее, хешируемые) объекты могут быть ключами словаря и элементами множества; изменяемый аргумент по умолчанию создаётся один раз и копит состояние между вызовами; функция может неожиданно изменить переданный список; `[[0]*3]*3` создаёт три ссылки на один список; неизменяемые объекты безопасно разделять между потоками и кэшировать. При этом кортеж неизменяем только поверхностно — список внутри него можно менять.
--- points
- определение и примеры обоих видов
- «изменение» неизменяемого создаёт новый объект
- ключи dict / элементы set должны быть хешируемыми
- ловушка с изменяемым аргументом по умолчанию
- побочные эффекты при передаче в функцию, поверхностная неизменяемость tuple
:::

::: quiz open q21-8 собес
Как передаются аргументы в функцию в Python — по значению или по ссылке?
--- answer
Ни так, ни так в классическом смысле: по соиспользованию (call by sharing, иногда говорят «по ссылке на объект»). Параметр функции — новое локальное имя, привязанное к тому же объекту, что передал вызывающий. Поэтому изменение изменяемого объекта (`lst.append`) видно снаружи, а перепривязка параметра (`lst = [...]`, `n += 1` для int) — нет: она меняет только локальное имя. Для неизменяемых объектов поведение выглядит как передача по значению, потому что изменить их нельзя.
--- points
- call by sharing: параметр ссылается на тот же объект
- изменение объекта видно снаружи
- перепривязка имени не видна снаружи
- для неизменяемых типов похоже на передачу по значению
:::
