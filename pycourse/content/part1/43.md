# 4.3 SOLID, паттерны и внедрение зависимостей

## SOLID на Python (вопрос в 41% интервью):
| Принцип | Суть | Нарушение → исправление |
|---|---|---|
| **S** — единственная ответственность | у модуля одна причина меняться | `OrderService` считает цены, пишет в БД и шлёт письма → разнести на калькулятор, репозиторий, уведомителя |
| **O** — открытость/закрытость | расширяем, не меняя существующий код | цепочка `if kind == …` на каждый новый тип → словарь стратегий или реестр |
| **L** — подстановка Лисков | наследник работает везде, где работает родитель | `Square(Rectangle)` ломает `set_width`; `ReadOnlyList(list)` бросает в `append` |
| **I** — разделение интерфейсов | не заставляй зависеть от ненужных методов | один огромный `Storage` → маленькие `Protocol`: `Reader`, `Writer` |
| **D** — инверсия зависимостей | бизнес-логика зависит от абстракций | `OrderService` создаёт `PostgresRepo()` внутри → получает `repo: OrderRepo` в конструкторе |

Плюс принципы, о которых спрашивают в Т-Банке: **KISS** (не усложняй), **DRY** (не повторяйся — но и не склеивай похожее, но разное), **YAGNI** (не делай впрок).

## Паттерны, которые в Python выглядят иначе:
| Паттерн | Классически | По-питоновски |
|---|---|---|
| Strategy | иерархия классов-стратегий | словарь функций, функция как параметр |
| Singleton | класс с `getInstance` | объект на уровне модуля |
| Factory | класс-фабрика | `classmethod`-конструктор, реестр через `__init_subclass__` |
| Iterator | класс с `hasNext` | генератор |
| Decorator | обёртка-класс с тем же интерфейсом | декоратор функции или `__getattr__`-прокси |
| Command | класс с `execute` | `functools.partial`, замыкание |
| Observer | интерфейс подписчика | список колбэков, `weakref` для подписчиков-объектов |
| Template method | абстрактный базовый класс | тот же ABC или функция, принимающая шаги |

::: solve Strategy вместо if/elif (частая задача лайвкода)
Было — каждая новая скидка требует правки функции (нарушение O):
```python
def total(items, discount):
    s = sum(i.price for i in items)
    if discount == "black_friday":
        return s * 0.7
    elif discount == "loyal":
        return s - 500 if s > 5000 else s
    return s
```
Стало — функция закрыта для изменений, новые скидки регистрируются снаружи:
```python
DISCOUNTS = {}

def discount(name):
    def register(fn):
        DISCOUNTS[name] = fn
        return fn
    return register

@discount("black_friday")
def _bf(s): return s * 0.7

def total(items, kind=None):
    s = sum(i.price for i in items)
    if kind is None:
        return s
    try:
        return DISCOUNTS[kind](s)
    except KeyError:
        raise ValueError(f"неизвестная скидка {kind!r}") from None
```
Частые ошибки на собесе: оставить `if/elif`, забыть про неизвестный тип, нагородить иерархию классов там, где хватает функций.
:::

## Внедрение зависимостей (DI):
Объект **получает** зависимости, а не создаёт их сам. В Python для этого не нужен фреймворк: передавай зависимости в конструктор, тип описывай `Protocol`. В тестах подставляешь фейки, в проде — настоящие реализации; связывание происходит в одном месте («composition root»: `main`, фабрика приложения, `Depends` в FastAPI).
```python
class OrderRepo(Protocol):
    def save(self, order: Order) -> int: ...

class OrderService:
    def __init__(self, repo: OrderRepo, notifier: Notifier, clock=datetime.now):
        self.repo, self.notifier, self.clock = repo, notifier, clock
```

::: quiz review q43-3 собес
Сделай код-ревью: какие проблемы видишь и как бы переделал?
```python
import smtplib, psycopg

class UserService:
    def register(self, email, password):
        if "@" not in email:
            return False
        conn = psycopg.connect("dbname=prod user=admin password=123")
        conn.execute(f"INSERT INTO users VALUES ('{email}', '{password}')")
        conn.commit()
        smtplib.SMTP("smtp.gmail.com").sendmail("noreply@x.ru", email, "Привет!")
        return True
```
--- answer
- **SQL-инъекция**: f-строка в SQL. Нужны параметры: `execute("INSERT … VALUES (%s, %s)", (email, pwd_hash))`
- **пароль хранится открытым текстом** → хешировать (argon2, bcrypt)
- **секреты в коде** (строка подключения) → конфиг или переменные окружения
- **нарушение S и D**: сервис сам создаёт подключение и SMTP-клиент → внедрять `UserRepo` и `Mailer` через конструктор, тогда код тестируется без БД и почты
- **новое соединение на каждый вызов и не закрывается** → пул соединений и `with`
- **ошибки сигнализируются `False`** без причины → исключения (`InvalidEmail`, `UserExists`), проверка уникальности (UNIQUE и обработка `IntegrityError`)
- **письмо внутри запроса**: если SMTP упадёт после commit, пользователь создан, а запрос вернёт ошибку → отправлять асинхронно (очередь, outbox)
- валидация email примитивная → pydantic `EmailStr` или библиотека
- `INSERT` без списка колонок ломается при изменении схемы
--- points
- SQL-инъекция и параметризованный запрос
- пароль в открытом виде, секреты в коде
- зависимости создаются внутри: DI, тестируемость
- соединения: пул, закрытие
- ошибки через исключения, уникальность email
- отправка письма вне транзакции запроса (очередь)
:::

* `EventBus ★` — подписка на события; подписчики-методы хранятся через слабые ссылки и не мешают сборке мусора (задача Positive Technologies) {test_event_bus}
+ Словарь «событие → список ссылок». Для связанного метода (`inspect.ismethod(cb)`) храни `weakref.WeakMethod(cb)`, для обычной функции — сильную ссылку (обёртку, которая при вызове возвращает её). ! `weakref.ref(obj.method)` умирает сразу: связанный метод создаётся заново при каждом обращении. Поэтому `WeakMethod`. Исключение одного подписчика не должно мешать остальным: собери ошибки и после рассылки брось `ExceptionGroup`.

## Вопросы с собеседования по уроку:
::: quiz open q43-1 собес
Расскажи про SOLID. Приведи пример нарушения каждого принципа из своей практики или на Python.
--- answer
- **S** — модуль меняется по одной причине. Нарушение: view в Django, которая валидирует, считает, пишет в базу и шлёт письма. Исправление: сервисный слой, репозиторий, отдельный уведомитель.
- **O** — расширение без изменения. Нарушение: `if payment_type == "card" … elif …` в десяти местах. Исправление: стратегии в реестре, полиморфизм.
- **L** — подтип заменяет базовый тип. Нарушение: наследник переопределяет метод и бросает `NotImplementedError` или ужесточает входные условия; `Square(Rectangle)`. Исправление: композиция или другая иерархия.
- **I** — маленькие интерфейсы. Нарушение: репозиторий с 30 методами, и тестовый фейк должен реализовать их все. Исправление: несколько `Protocol` под конкретных потребителей.
- **D** — зависимость от абстракций. Нарушение: сервис импортирует и создаёт `boto3.client` внутри. Исправление: передать клиент (или его Protocol-обёртку) в конструктор, связывать в composition root (`Depends` в FastAPI).

Важно не догматизировать: принципы — инструменты против конкретных проблем (сложно тестировать, страшно менять), а не самоцель.
--- points
- все пять букв с правильной сутью
- пример нарушения и исправления для каждой
- связь с тестируемостью и DI
- питоничные средства: Protocol, словарь стратегий
- принципы как инструмент, без догматизма
:::

::: quiz open q43-2 собес
Какие паттерны проектирования ты используешь? Как они выглядят в Python?
--- answer
Называю те, что реально применяю, и показываю питоновский вариант. Strategy — словарь функций или функция-параметр (сортировка с `key`, расчёт скидок). Factory — `classmethod`-конструкторы (`from_dict`, `from_env`) и реестры. Adapter — обёртка над внешним API или библиотекой с интерфейсом, нужным моему коду (S3-клиент за `Storage`-протоколом). Repository — доступ к данным за интерфейсом, чтобы бизнес-логика не знала про ORM. Decorator — декораторы функций: ретраи, кэш, логирование, авторизация. Observer — сигналы Django, колбэки, шина событий. Unit of Work — сессия SQLAlchemy, `transaction.atomic`. Dependency Injection — передача зависимостей через конструктор, `Depends` в FastAPI. Singleton — объект на уровне модуля (настройки, пул соединений). Многие классические паттерны в Python не нужны в «полной» форме: функции первого класса, модули и генераторы закрывают их проще.
--- points
- 4–6 паттернов, которые реально применял
- питоничная форма каждого: функции, classmethod, модуль
- Repository, Unit of Work, DI в бэкенде
- примеры из фреймворков: Depends, сигналы, atomic
- понимание, что часть паттернов в Python упрощается
:::
