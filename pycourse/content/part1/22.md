# 2.2 Коллекции изнутри: list, dict, set, collections

## `list` — динамический массив:
Внутри — массив **указателей** на объекты (поэтому в списке могут лежать объекты разных типов). Когда место кончается, CPython выделяет новый массив с запасом (~12.5% сверху плюс константа) и переносит указатели. Поэтому:
- `append` — O(1) **амортизированно**: редкие дорогие расширения размазываются по многим дешёвым вставкам
- `lst[i]` — O(1): адрес вычисляется по индексу
- `insert(0, x)` и `pop(0)` — O(n): сдвигаются все указатели
- `x in lst` — O(n), линейный поиск

`tuple` — тоже массив указателей, но фиксированного размера: меньше памяти, хешируется, CPython кэширует маленькие кортежи.

## `dict` — хеш-таблица:
1. От ключа считается `hash(key)`, по нему выбирается ячейка таблицы
2. Если ячейка занята другим ключом (**коллизия**), CPython пробует следующие ячейки по псевдослучайной последовательности — это **открытая адресация**, а не цепочки списков
3. Ключ сравнивается сначала по хешу, затем по `is`, затем по `==`
4. Когда таблица заполнена на 2/3, она увеличивается и все ключи перераскладываются

С Python 3.6 словарь **компактный**: отдельный разреженный массив индексов и плотный массив записей `(hash, key, value)` в порядке вставки. Отсюда экономия памяти и гарантированный (с 3.7) **порядок вставки** при обходе. `set` устроен так же, но без значений и без компактности — порядок у множеств не гарантирован.

::: py Как спрашивают
«Как устроен словарь?» → «Какая сложность поиска? А в худшем случае?» (O(n), если все ключи с одним хешем) → «Почему ключ должен быть хешируемым?» → «Что будет, если изменить объект-ключ после вставки?» (хеш изменится, ключ «потеряется» в таблице) → «Почему порядок сохраняется?»
:::

::: quiz output q22-1 собес
Что выведет программа?
```python
d = {1: "a", True: "b", 1.0: "c"}
print(d)
print(len({0, False, 0.0, "", None}))
```
--- answer
{1: 'c'}
3
--- why
`1 == True == 1.0` и `hash(1) == hash(True) == hash(1.0)`, поэтому для словаря это **один ключ**. Ключ остаётся первым вставленным (`1`), а значение перезаписывается последним (`"c"`). Во множестве `0`, `False` и `0.0` — один элемент, `""` и `None` — ещё два.
:::

## Сложность — шпаргалка:
| Операция | list | dict | set |
|---|---|---|---|
| поиск `x in c` | O(n) | O(1)* | O(1)* |
| вставка | `append` O(1)**, `insert` O(n) | O(1)* | O(1)* |
| удаление | `pop()` O(1), `remove(x)` O(n) | `del d[k]` O(1)* | `discard` O(1)* |
| перебор | O(n) | O(n) | O(n) |

\* в среднем; в худшем O(n) при массовых коллизиях. ** амортизированно.

## Модуль `collections` и его друзья:
| Тип | Зачем | Пример |
|---|---|---|
| `deque` | очередь с O(1) с обоих концов; `maxlen` для «последних N» | BFS, скользящее окно |
| `Counter` | подсчёт; `most_common(k)`, сложение и вычитание счётчиков | частоты слов |
| `defaultdict` | значение по умолчанию для нового ключа | `defaultdict(list)` для группировки |
| `OrderedDict` | `move_to_end`, `popitem(last=False)`; сравнение учитывает порядок | LRU-кэш |
| `namedtuple` | кортеж с именами полей | лёгкие записи |
| `heapq` | двоичная куча поверх списка (минимальная) | top-k, слияние |
| `bisect` | бинарный поиск в отсортированном списке | вставка с сохранением порядка |

Что выведет программа?
```python
from collections import Counter, defaultdict
c = Counter("abracadabra")
print(c.most_common(2))
g = defaultdict(list)
for w in ["ant", "bee", "ape"]:
    g[w[0]].append(w)
```

--- why
`most_common` сортирует по убыванию частоты, а при равенстве оставляет порядок первого появления (`b` встретилась раньше `r`). Обращение `g["z"]` к `defaultdict` **создаёт** ключ — поэтому длина стала 3. Это частая неочевидная утечка: проверку наличия делай через `in`, а не через `g[key]`.

## Вопросы с собеседования по уроку:
::: quiz open q22-5 собес
Как устроен `dict` в Python? Какая сложность операций и почему ключи должны быть хешируемыми?
--- answer
`dict` — хеш-таблица с открытой адресацией. По `hash(key)` выбирается ячейка; при коллизии CPython пробует другие ячейки по псевдослучайной последовательности. Ключ в ячейке сравнивается сначала по хешу, затем по идентичности, затем по `==`. При заполнении на 2/3 таблица увеличивается и всё перераскладывается, поэтому вставка — O(1) амортизированно. Поиск, вставка, удаление — O(1) в среднем, O(n) в худшем случае, если у многих ключей совпадает хеш. С 3.6 словарь компактный: массив индексов плюс плотный массив записей в порядке вставки, отсюда экономия памяти и гарантированный с 3.7 порядок. Ключ должен быть хешируемым, потому что ячейка вычисляется по хешу: если хеш объекта изменится после вставки, ключ уже не найдётся. Поэтому изменяемые `list`, `dict`, `set` ключами быть не могут, а для своих классов `__hash__` должен быть согласован с `__eq__`.
--- points
- хеш-таблица, ячейка по hash(key)
- коллизии и открытая адресация
- сравнение по хешу, потом по ==
- расширение при заполнении, амортизированное O(1); худший случай O(n)
- компактный dict и порядок вставки
- почему ключ должен быть хешируемым и неизменным
:::

::: quiz open q22-6 собес
Чем `list` отличается от `tuple`? Когда что использовать?
--- answer
`list` изменяемый, `tuple` неизменяемый. Технически оба — массивы указателей, но кортеж фиксированного размера: занимает меньше памяти, быстрее создаётся (CPython кэширует маленькие кортежи, а константные кортежи создаются ещё при компиляции), его можно использовать как ключ словаря и элемент множества (если хешируемо содержимое). Список нужен для однородной коллекции, которая растёт и меняется. Кортеж — для записи фиксированной структуры, где позиция имеет смысл (координаты, строка из БД, несколько возвращаемых значений), для ключей и для данных, которые не должны меняться. Нюанс: неизменяемость кортежа поверхностная — список внутри кортежа менять можно.
--- points
- изменяемость
- память и скорость создания
- хешируемость, ключи словаря
- семантика: коллекция против записи
- поверхностная неизменяемость tuple
:::
