# 3.1 Области видимости, замыкания и декораторы

## LEGB — где Python ищет имя:
**L**ocal (внутри функции) → **E**nclosing (объемлющие функции) → **G**lobal (модуль) → **B**uilt-in (`len`, `print`).

Главное правило: **имя локальное, если внутри функции ему что-то присваивается** — где угодно в теле, даже ниже по коду. Это решается при компиляции функции, а не при выполнении строки.
- `global x` — присваивать в имя модуля
- `nonlocal x` — присваивать в имя объемлющей функции

::: quiz output q31-1 собес verify=exception
Что выведет программа?
```python
x = 10

def f():
    print(x)
    x = 20

f()
```
--- answer
UnboundLocalError
--- why
Из-за `x = 20` компилятор считает `x` локальным во всей функции. `print(x)` обращается к локальной переменной, которой ещё ничего не присвоено: `UnboundLocalError` (это подкласс `NameError`). То же самое случается с `x += 1` — это тоже присваивание. Лечится `global x` или передачей значения параметром.
:::

## Замыкание:
**Замыкание** — функция, которая запоминает переменные объемлющей области даже после того, как та завершилась. Переменные хранятся в ячейках (`f.__closure__`), и замыкание держит **саму переменную, а не её значение на момент создания**.
```python
def make_multiplier(k):
    def mul(x):
        return x * k      # k — свободная переменная из make_multiplier
    return mul

double = make_multiplier(2)
print(double(21), double.__closure__[0].cell_contents)   # 42 2
```

## Декоратор:
Функции в Python — **объекты первого класса**: их можно передавать, возвращать, хранить в переменных. **Декоратор** — вызываемый объект, который принимает функцию и возвращает замену. `@deco` над `def f` — то же самое, что `f = deco(f)` сразу после определения.
```python
import functools, time

def time_it(func):
    @functools.wraps(func)                 # переносит __name__, __doc__, __wrapped__…
    def wrapper(*args, **kwargs):          # любые аргументы
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)   # не забыть вернуть результат
        finally:
            print(f"{func.__name__}: {time.perf_counter() - start:.3f} c")
    return wrapper
```

## Декоратор с параметрами — три уровня:
```python
def repeat(times):              # 1. фабрика: принимает параметры
    def decorator(func):        # 2. декоратор: принимает функцию
        @functools.wraps(func)
        def wrapper(*args, **kwargs):   # 3. обёртка: принимает аргументы вызова
            for _ in range(times - 1):
                func(*args, **kwargs)
            return func(*args, **kwargs)
        return wrapper
    return decorator

@repeat(3)
def hi(): print("hi")
# без синтаксического сахара: hi = repeat(3)(hi)
```

::: py Как спрашивают на платформенной секции Авито
Цепочка от простого к сложному: что такое декоратор → напиши декоратор → сделай, чтобы он работал с любыми аргументами → как применить без `@` и когда это полезно (декорировать чужую функцию, применить условно) → что такое объект первого класса → декоратор с параметрами, и тоже без `@` → что покажет `func.__doc__` → что напечатается при *импорте* модуля с декорированной функцией → декоратор для async-функции → один декоратор и для sync, и для async.
:::

def deco(name):

--- why
Выражения декораторов вычисляются сверху вниз (обе фабрики), а применяются снизу вверх: ближайший к функции — первым. Всё это происходит **при определении функции**, то есть при импорте модуля, — вызов тут ни при чём. При вызове обёртки работают снаружи внутрь. Без `functools.wraps` внешний декоратор видит имя `inner` — метаданные потеряны.

## Декоратор для async-функций и универсальный:
```python
import asyncio, functools, inspect

def log_calls(func):
    if inspect.iscoroutinefunction(func):
        @functools.wraps(func)
        async def awrapper(*args, **kwargs):
            print("call", func.__name__)
            return await func(*args, **kwargs)
        return awrapper

    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print("call", func.__name__)
        return func(*args, **kwargs)
    return wrapper
```
Обычная обёртка для корутинной функции вернёт объект корутины, не дожидаясь его. Это «работает», но код до и после `func()` выполнится не тогда, когда ожидаешь: таймер намерит ноль, а `try/except` не поймает ошибку из корутины.

## Полезное из `functools`:
| Что | Зачем |
|---|---|
| `wraps` | сохранить метаданные обёрнутой функции |
| `lru_cache(maxsize=128)`, `cache` | мемоизация; аргументы должны быть хешируемыми; `cache_info()`, `cache_clear()` |
| `partial(f, x=1)` | зафиксировать часть аргументов |
| `singledispatch` | перегрузка функции по типу первого аргумента |
| `reduce` | свёртка последовательности |
| `cached_property` | вычислить атрибут один раз и сохранить в экземпляре |

* `make_counter` — фабрика счётчиков: каждый вызов возвращаемой функции даёт 1, 2, 3… {test_make_counter}
+ Внутри фабрики — переменная `n = 0` и вложенная функция с `nonlocal n`, которая делает `n += 1` и возвращает `n`.
! Без `nonlocal` получишь `UnboundLocalError`: `+=` делает имя локальным. Два счётчика должны быть независимыми.
* `call_count` — декоратор, который считает вызовы в атрибуте `wrapper.calls` и сохраняет имя и docstring функции {test_call_count}
+ `@functools.wraps(func)` над обёрткой, `wrapper.calls = 0` после определения, внутри — `wrapper.calls += 1` и `return func(*args, **kwargs)`.
! Вызов, который бросил исключение, — тоже вызов. Не забудь вернуть результат функции.
* `memoize` — кэш результатов без `lru_cache`; учитывает позиционные и именованные аргументы {test_memoize}
+ Словарь `cache` в замыкании. Ключ — `(args, tuple(sorted(kwargs.items())))`. Есть в кэше — вернуть, нет — вычислить и сохранить. Сделай кэш доступным как `wrapper.cache`.
! `f(1, b=2)` и `f(1, b=2)` с kwargs в другом порядке — один ключ, поэтому `sorted`. А вот `f(1, 2)` и `f(1, b=2)` могут быть разными ключами — это допустимо, так делает и `lru_cache`.
* `retry` — декоратор с параметрами: повторить вызов при указанных исключениях {test_retry}
+ Три уровня: `retry(times, exceptions=(Exception,), delay=0, sleep=time.sleep)` → декоратор → обёртка. В обёртке цикл `for attempt in range(times)`: `try: return func(...)`, `except exceptions as e:` запомнить ошибку и, если попытка не последняя, вызвать `sleep(delay)`. После цикла — `raise` последней ошибки.
! Исключения, которых нет в `exceptions`, пробрасываются сразу, без повторов. После последней попытки спать не нужно. `sleep` передаётся параметром, чтобы тест не ждал по-настоящему.
* `rate_limit ★` — не больше `max_calls` вызовов за любые `period` секунд, иначе `RateLimitExceeded` (задача Kaspersky) {test_rate_limit}
+ Скользящее окно: `deque` с временем успешных вызовов. Перед вызовом выкинь слева всё, что старше `now - period`. Если в очереди `max_calls` элементов — исключение, иначе добавь `now` и вызови функцию. Время бери из параметра `clock` (по умолчанию `time.monotonic`).
! Фиксированное окно («сбрасываем счётчик каждые period секунд») пропускает удвоенный лимит на стыке окон — тест проверяет именно это. Отклонённый вызов не занимает место в окне. Используй `monotonic`, а не `time.time`: системные часы могут прыгнуть назад.

## Вопросы с собеседования по уроку:
::: quiz open q31-5 собес
Что такое декоратор? Напиши декоратор, который измеряет время выполнения функции, и объясни каждую строку.
--- answer
Декоратор — вызываемый объект, который принимает функцию и возвращает новую (обычно обёртку), добавляя поведение без изменения исходного кода. `@deco` над определением — синтаксический сахар для `f = deco(f)`, выполняется один раз при определении функции. Работает потому, что функции — объекты первого класса, а обёртка — замыкание над исходной функцией.

```python
def time_it(func):
    @functools.wraps(func)                # сохранить __name__, __doc__, __wrapped__
    def wrapper(*args, **kwargs):         # принять любые аргументы
        start = time.perf_counter()       # монотонные часы высокого разрешения
        try:
            return func(*args, **kwargs)  # вызвать и вернуть результат
        finally:                          # замер даже при исключении
            print(func.__name__, time.perf_counter() - start)
    return wrapper
```
Для декоратора с параметрами нужен ещё один уровень: фабрика, возвращающая декоратор. Для async-функций обёртка должна быть `async def` и делать `await func(...)`.
--- points
- определение: принимает функцию, возвращает замену
- `@deco` — это `f = deco(f)` при определении
- `*args, **kwargs` и возврат результата
- `functools.wraps` и зачем он
- замыкание как механизм; параметризованный декоратор — три уровня
:::

::: quiz open q31-6 собес
Что такое замыкание? Что такое позднее связывание и как оно проявляется?
--- answer
Замыкание — вложенная функция, которая использует переменные объемлющей функции и сохраняет к ним доступ после её завершения. Переменные хранятся в ячейках (`__closure__`), и замыкание держит ссылку на переменную, а не копию значения. Отсюда позднее связывание: значение берётся в момент вызова, а не создания. Классический пример — лямбды в цикле `[lambda: i for i in range(3)]`: все вернут последнее значение `i`. Исправления: аргумент по умолчанию `lambda i=i: i`, `functools.partial`, фабрика функций. Чтобы изменять переменную объемлющей области (а не только читать), нужен `nonlocal`, иначе присваивание создаст локальную переменную. На замыканиях построены декораторы, фабрики функций, колбэки с состоянием.
--- points
- функция + захваченные переменные объемлющей области
- хранится переменная (ячейка), а не значение
- позднее связывание и пример с лямбдами в цикле
- способы исправить: аргумент по умолчанию, partial
- nonlocal для изменения
:::
