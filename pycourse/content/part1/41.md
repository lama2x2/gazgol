# 4.1 Классы и магические методы

## Класс и экземпляр:
Класс — тоже объект (типа `type`). У класса и у каждого экземпляра свой словарь атрибутов: `C.__dict__` и `obj.__dict__`. При чтении `obj.attr` Python смотрит сначала в экземпляр, потом в класс и его родителей (упрощённо; полная картина с дескрипторами — в 4.2). При **присваивании** `obj.attr = …` атрибут всегда создаётся в экземпляре.

::: quiz output q41-1 собес
Что выведет программа?
```python
class Dog:
    tricks = []

    def __init__(self, name):
        self.name = name

    def add(self, trick):
        self.tricks.append(trick)

a, b = Dog("a"), Dog("b")
a.add("sit")
b.add("roll")
print(a.tricks)
a.tricks = ["own"]
print(a.tricks, b.tricks, Dog.tricks)
```
--- answer
['sit', 'roll']
['own'] ['sit', 'roll'] ['sit', 'roll']
--- why
`tricks` — атрибут **класса**, один список на всех. `self.tricks.append` не присваивает, а изменяет найденный в классе список. А вот `a.tricks = [...]` создаёт атрибут в экземпляре `a`, который **затеняет** классовый. Изменяемые значения по умолчанию — в `__init__`.
:::

## Три вида методов:
| | Первый аргумент | Зачем |
|---|---|---|
| обычный метод | `self` — экземпляр | работа с состоянием объекта |
| `@classmethod` | `cls` — класс (и подкласс, если вызван на нём) | альтернативные конструкторы: `Date.from_string("2026-01-01")`, фабрики |
| `@staticmethod` | ничего | функция, логически относящаяся к классу, но не использующая ни класс, ни экземпляр |

## `__new__` и `__init__`:
`C(args)` вызывает `C.__new__(C, args)` — он **создаёт** объект и возвращает его, затем `obj.__init__(args)` — **инициализирует**. `__new__` переопределяют редко: для неизменяемых типов (наследник `int` или `tuple` должен задать значение в момент создания), синглтонов и кэширования экземпляров. Если `__new__` вернул объект не своего класса, `__init__` не вызывается.

## Магические (dunder) методы — главные:
| Группа | Методы | Для чего |
|---|---|---|
| представление | `__repr__`, `__str__`, `__format__` | `repr()` — однозначно, для разработчика (в идеале `eval`-абельно), `str()` — для пользователя. Если нет `__str__`, используется `__repr__` |
| сравнение | `__eq__`, `__lt__`, `__le__`, … | `functools.total_ordering` достроит остальные по `__eq__` и одному из `__lt__`… |
| хеш | `__hash__` | **определил `__eq__` — `__hash__` становится `None`**, объект перестаёт быть хешируемым |
| контейнер | `__len__`, `__getitem__`, `__setitem__`, `__contains__`, `__iter__` | `len`, `[]`, `in`, `for` |
| арифметика | `__add__`, `__radd__`, `__iadd__`, `__mul__`… | `+`, отражённые (правый операнд), на месте (`+=`) |
| прочее | `__bool__`, `__call__`, `__enter__`/`__exit__` | истинность, вызов как функции, `with` |

::: quiz output q41-2 собес verify=exception
Что выведет программа?
```python
class P:
    def __init__(self, x):
        self.x = x
    def __eq__(self, other):
        return isinstance(other, P) and self.x == other.x

print(P(1) == P(1), P(1) is P(1))
print({P(1)})
```
--- answer
True False
TypeError
--- why
Как только класс определяет `__eq__` без `__hash__`, Python ставит `__hash__ = None`: иначе равные объекты имели бы разные хеши (по умолчанию хеш — от `id`), и словари сломались бы. Если объект неизменяемый, определи `__hash__` по тем же полям, что и `__eq__`: `return hash(self.x)`.
:::

## Как Python вычисляет `a + b`:
1. `a.__add__(b)`. Если вернул что угодно, кроме `NotImplemented`, — это результат
2. Иначе `b.__radd__(a)` — «отражённый» метод правого операнда
3. Оба вернули `NotImplemented` — `TypeError`

Исключение из правила: если тип `b` — **подкласс** типа `a` и переопределяет `__radd__`, сначала пробуют его.

::: quiz output q41-3 собес
Что выведет программа?
```python
class A:
    def __add__(self, other):
        print("A.__add__")
        return NotImplemented

class B:
    def __radd__(self, other):
        print("B.__radd__", type(other).__name__)
        return "B"

print(A() + B())
print(0 + B())
```
--- answer
A.__add__
B.__radd__ A
B
B.__radd__ int
B
--- why
`A.__add__` отказался (`NotImplemented` — не исключение, а специальное значение), и Python спросил `B.__radd__`. С `0 + B()` то же: `int.__add__` не умеет складываться с `B`. Именно поэтому, чтобы твои объекты работали с `sum()` (который начинает с 0), нужен `__radd__`, обрабатывающий 0.
:::

## Инкапсуляция по соглашению:
- `_x` — «внутреннее, не трогай» (соглашение, ничего не запрещает)
- `__x` — **искажение имени (name mangling)**: внутри класса `A` превращается в `_A__x`. Нужно, чтобы подкласс случайно не затёр атрибут родителя, — а не для секретности
- `@property` — геттер и сеттер с синтаксисом атрибута: можно начать с простого атрибута и позже добавить логику, не меняя интерфейс

::: quiz output q41-4
Что выведет программа?
```python
class A:
    def __init__(self):
        self.__x = 1
        self._y = 2

a = A()
print(a._y, a._A__x)
print(hasattr(a, "__x"), sorted(vars(a)))
```
--- answer
2 1
False ['_A__x', '_y']
--- why
Компилятор переписал `self.__x` в `self._A__x` внутри класса `A`. Снаружи имя `__x` не существует, но «приватный» атрибут доступен под искажённым именем.
:::

## `dataclass` — классы данных без шаблонного кода:
```python
from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True, order=True)
class Item:
    price: int
    name: str
    tags: list[str] = field(default_factory=list, compare=False)   # не tags=[]!

    def __post_init__(self):
        if self.price < 0:
            raise ValueError("цена < 0")
```
Генерирует `__init__`, `__repr__`, `__eq__`; `order=True` — сравнения по полям по порядку; `frozen=True` — запрет присваивания и `__hash__`; `slots=True` (3.10) — `__slots__`. Для валидации входящих данных из сети чаще берут pydantic, а dataclass — для внутренних структур.

::: quiz choice q41-5 собес
Когда используют `@classmethod`, а когда `@staticmethod`?
- [ ] разницы нет, это синонимы
- [x] `classmethod` получает класс и подходит для альтернативных конструкторов (наследник получит экземпляр своего класса); `staticmethod` — обычная функция в пространстве имён класса
- [ ] `staticmethod` быстрее, поэтому его используют всегда, когда не нужен self
- [ ] `classmethod` нельзя вызвать на экземпляре
--- why
`Date.from_string()` через `classmethod` вызывает `cls(...)`, поэтому `MyDate.from_string()` создаст `MyDate`, а не `Date`. `staticmethod` подходит для вспомогательной функции, которая логически относится к классу. Оба можно вызывать и на классе, и на экземпляре.
:::

::: hw 41
* `Version` — версия вида `"1.10.2"` со сравнением, хешем и альтернативным конструктором {test_version}
+ В `__init__(self, *parts)` храни кортеж чисел. `from_string(cls, s)` — `@classmethod`: `cls(*map(int, s.split(".")))`. `__eq__` и `__lt__` сравнивают кортежи (недостающие части считай нулями: `1.2 == 1.2.0`), `@functools.total_ordering` достроит остальное. `__hash__` — согласованный с `__eq__`: от кортежа без хвостовых нулей. `__repr__` → `Version('1.10.2')`, `__str__` → `1.10.2`.
! Строки сравнивать нельзя: `"1.10" < "1.9"` как строки. Сравнение с чужим типом — `return NotImplemented`, а не `False` и не исключение.
* `Money` — деньги в копейках с валютой: сложение, `sum()`, сравнение, хеш {test_money}
+ Храни `cents: int` и `currency: str`. `__add__`: другая валюта — `ValueError`, не `Money` — `NotImplemented`. `__radd__`: если `other == 0`, вернуть `self` (это для `sum`), иначе — `self + other`. `__str__` → `"10.50 RUB"` (`f"{cents // 100}.{cents % 100:02d}"`). `__bool__` — ненулевая сумма.
! Отрицательные суммы: `-150` копеек — это `"-1.50 RUB"`, а не `"-2.50"` (целочисленное деление округляет вниз). Деньги — не `float`: 0.1 + 0.2 ≠ 0.3.
* `Vector` — n-мерный вектор: `len`, индексы и срезы, `abs`, умножение на число с обеих сторон, скалярное произведение через `@` {test_vector}
+ Храни кортеж `tuple(components)`. `__getitem__`: если ключ — `slice`, верни `Vector(self._c[key])`, иначе число. `__mul__` для числа (`isinstance(k, (int, float))`), иначе `NotImplemented`; `__rmul__ = __mul__`. `__matmul__` — `sum(a * b for a, b in zip(...))`, при разной длине `ValueError`. `__eq__` только с `Vector`.
! `3 * v` вызывает `int.__mul__` → `NotImplemented` → `v.__rmul__(3)`. Без `__rmul__` упадёт. `__iter__` можно не писать: `__getitem__` с индексами от 0 уже даёт итерацию, но явный `__iter__` быстрее.
* `HashMap ★` — своя хеш-таблица без `dict` и `set`: `m[k] = v`, `m[k]`, `del m[k]`, `in`, `len`, `get`, итерация по ключам {test_hashmap}
+ Метод цепочек: список корзин `self._buckets = [[] for _ in range(8)]`, корзина — список пар `[key, value]`. Индекс корзины — `hash(key) % len(buckets)`. Вставка: найди ключ в корзине и замени значение, иначе добавь пару. Когда `size / len(buckets) > 0.75`, создай в 2 раза больше корзин и переложи все пары.
! Ключи сравнивай через `==` (как dict). Тест подсовывает ключи с одинаковым хешем — все попадут в одну корзину, и это должно работать. Не забудь уменьшать `size` при удалении; отсутствующий ключ — `KeyError`.

## Вопросы с собеседования по уроку:
::: quiz open q41-6 собес
Чем `__str__` отличается от `__repr__`? Что будет, если определить `__eq__`, но не `__hash__`?
--- answer
`__repr__` — однозначное представление для разработчика (логи, отладка, REPL, элементы внутри контейнеров: `print([obj])` вызывает `repr`). В идеале по нему можно воссоздать объект: `Money(1050, 'RUB')`. `__str__` — читаемое представление для пользователя, используется `print` и `str()`, f-строками. Если `__str__` не определён, берётся `__repr__`, поэтому определять стоит в первую очередь `__repr__`. Если определить `__eq__` без `__hash__`, Python установит `__hash__ = None`, и объект станет нехешируемым: его нельзя положить в `set` или использовать ключом `dict`. Это защита контракта «равные объекты — равные хеши». Решение — определить `__hash__` от тех же полей, что участвуют в `__eq__`, и только для неизменяемых объектов (или `@dataclass(frozen=True)`).
--- points
- repr для разработчика, однозначный; str для пользователя
- print и str используют `__str__`, контейнеры — `__repr__`; без `__str__` берётся `__repr__`
- `__eq__` без `__hash__` → `__hash__ = None`
- контракт: равные объекты — равные хеши
- хеш только для неизменяемых, frozen dataclass
:::
