# 3.2 Итераторы и генераторы

## Протокол итерации:
- **итерируемый объект (iterable)** — у него есть `__iter__()`, который возвращает итератор. Список, строка, словарь, файл, `range`
- **итератор (iterator)** — у него есть `__next__()`, который отдаёт следующий элемент или бросает `StopIteration`, и `__iter__()`, который возвращает `self`

Цикл `for x in obj` разворачивается так:
```python
it = iter(obj)            # obj.__iter__()
while True:
    try:
        x = next(it)      # it.__next__()
    except StopIteration:
        break
    ...                   # тело цикла
```
Итератор **одноразовый**: прошёл до конца — дальше пусто. Итерируемый контейнер можно обходить много раз, потому что каждый `iter()` создаёт новый итератор.

::: quiz output q32-1 собес
Что выведет программа?
```python
g = (x * x for x in range(3))
print(sum(g))
print(sum(g))
it = iter([1, 2, 3])
print(next(it), list(it), list(it))
```
--- answer
5
0
1 [2, 3] []
--- why
Генераторное выражение — итератор: первый `sum` его исчерпал, второй получил пустую последовательность. С `iter(список)` то же: `next` забрал 1, первый `list` — остальное, второй — ничего. Частый баг: передать генератор в две функции подряд.
:::

## Генератор:
Функция с `yield` при вызове **не выполняется**, а возвращает объект-генератор (это итератор). Каждый `next()` выполняет тело до следующего `yield` и **замораживает** кадр функции вместе с локальными переменными. `return` внутри генератора означает конец: значение уходит в `StopIteration.value`.

::: quiz output q32-2 собес
Что выведет программа?
```python
def gen():
    print("старт")
    yield 1
    print("между")
    yield 2
    print("конец")

g = gen()
print("создан")
for x in g:
    print(x)
```
--- answer
создан
старт
1
между
2
конец
--- why
При `gen()` тело не выполняется — поэтому «создан» первым. Дальше код идёт порциями до каждого `yield`. «конец» печатается при третьем `next`, после чего генератор бросает `StopIteration`, и цикл завершается.
:::

## Зачем это нужно — ленивость:
| | список `[f(x) for x in data]` | генератор `(f(x) for x in data)` |
|---|---|---|
| память | O(n): все элементы сразу | O(1): по одному |
| когда считается | сразу | по запросу |
| обходить повторно | можно | нельзя, одноразовый |
| `len`, индекс | есть | нет |

Ленивые конвейеры обрабатывают данные, которые не помещаются в память:
```python
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:                 # файл — тоже ленивый итератор по строкам
            yield line.rstrip("\n")

errors = (l for l in read_lines("app.log") if " ERROR " in l)
first_10 = list(itertools.islice(errors, 10))   # прочитаем ровно столько, сколько нужно
```
::: warn Провал на собесе Ozon
«Найти топ-10 URL в логе на 10 ГБ»: `f.readlines()` или `f.read().split()` — сразу провал, это вся десятигигабайтная выгрузка в памяти. Правильно — построчный обход и `Counter`. Следующий вопрос интервьюера: «А если уникальных URL сотни миллионов и Counter не влезает?» Ответ: разбить на части по хешу URL (каждая часть влезает в память), посчитать каждую и слить топы; или приближённые алгоритмы вроде Count-Min Sketch и Space-Saving.
:::

## `yield from` и двусторонние генераторы:
- `yield from sub` — делегировать: отдать всё из `sub` и получить его `return`-значение как результат выражения
- `g.send(v)` — передать значение внутрь: оно становится результатом `yield`
- `g.throw(exc)` — бросить исключение в точке `yield`, `g.close()` — бросить `GeneratorExit`, чтобы генератор завершился и выполнил свои `finally`

::: quiz output q32-3
Что выведет программа?
```python
def inner():
    yield 1
    yield 2
    return "готово"

def outer():
    result = yield from inner()
    print("inner вернул", result)
    yield 3

print(list(outer()))
```
--- answer
inner вернул готово
[1, 2, 3]
--- why
`yield from` прокидывает наружу всё, что отдаёт `inner`, а его `return` становится значением выражения. Печать происходит во время работы `list()`, то есть до того, как список готов и напечатан. На `yield from` и `send` были построены корутины до появления `async/await`.
:::

::: quiz output q32-4
Что выведет программа?
```python
g = (i for i in range(10))
print(5 in g)
print(next(g))
print(sum(1 for _ in g))
```
--- answer
True
6
3
--- why
`in` для итератора — это перебор, который **потребляет** элементы до найденного. После `5 in g` следующий — 6, а после `next` остаются 7, 8, 9.

## `itertools` — что знать:
| Функция | Что делает |
|---|---|
| `islice(it, n)` | первые n элементов любого итератора |
| `chain(a, b)`, `chain.from_iterable` | склеить итераторы |
| `groupby(it, key)` | группы **подряд идущих** одинаковых ключей (сначала сортируй!) |
| `count`, `cycle`, `repeat` | бесконечные последовательности |
| `accumulate` | нарастающий итог |
| `pairwise` (3.10), `batched` (3.12) | соседние пары, пачки по n |
| `product`, `permutations`, `combinations` | перебор |
| `tee(it, n)` | n независимых копий итератора (буферизует!) |

::: quiz choice q32-5 собес
Как сделать свой класс, который можно обходить в `for` **много раз**, как `range`?
- [ ] реализовать `__next__` и в `__iter__` вернуть `self`
- [x] в `__iter__` каждый раз возвращать **новый** итератор: например, сделать `__iter__` генератором
- [ ] унаследоваться от `list`
- [ ] реализовать только `__len__`
--- why
Если `__iter__` возвращает `self`, объект и есть итератор: после первого прохода он исчерпан, и второй `for` ничего не выведет. Разделяй контейнер и итератор. Проще всего написать `__iter__` с `yield` внутри: каждый вызов создаёт свежий генератор со своим состоянием. Это задача из реальных лайвкодов («напиши свой range»).
:::

::: hw 32
* `MyRange` — свой `range(start, stop, step=1)`: многоразовый, с `len` и `in` {test_my_range}
+ В `__init__` сохрани параметры. `__iter__` — генератор: `i = start`, пока `i < stop` (или `i > stop` при отрицательном шаге) — `yield i` и `i += step`. `__len__` — по формуле `max(0, (stop - start + step - 1) // step)` для положительного шага (подумай, как для отрицательного). `__contains__` — за O(1): попадает ли в диапазон и делится ли `x - start` на шаг.
! `__iter__`, возвращающий `self`, ломает второй проход. `step == 0` — `ValueError`, как у встроенного `range`. `__contains__` перебором — O(n), тест проверяет `10**12 in MyRange(0, 10**15, 2)`.
* `chunked` — разбить любой итерируемый объект на списки по n элементов, лениво {test_chunked}
+ Возьми итератор `it = iter(iterable)` и в цикле `chunk = list(islice(it, n))`; если пусто — выйти, иначе `yield chunk`.
! Должно работать с бесконечным итератором (тест берёт первые 3 пачки из `itertools.count()`), значит, никаких `list(iterable)` целиком. Последняя пачка может быть короче.
* `flatten` — разложить вложенные списки и кортежи любой глубины в плоскую последовательность {test_flatten}
+ Рекурсивный генератор: для каждого элемента — если это `list` или `tuple`, то `yield from flatten(x)`, иначе `yield x`.
! Строки не раскладывай на символы, даже если они вложены. Результат — генератор, а не список.
* `top_urls` — топ-k URL по числу запросов в потоке строк лога, не загружая лог в память (Ozon) {test_top_urls}
+ Формат строки: `"2026-01-01T10:00:00 GET /api/users 200 12ms"`. URL — третье поле: `line.split()[2]`. Один проход с `Counter`, затем сортировка пар по `(-count, url)` и первые k.
! Тест подаёт 200 000 строк генератором и следит за памятью через `tracemalloc`: `list(lines)` или `readlines`-подобное решение не пройдёт. Пустые и битые строки (меньше трёх полей) пропускай.
* `merge_sorted ★` — лениво слить несколько отсортированных итераторов в один отсортированный {test_merge_sorted}
+ Куча `heapq` из кортежей `(значение, номер_источника)`, в начале — по первому элементу каждого источника. Достал минимум → `yield` → положил следующий элемент из того же источника. Номер источника в кортеже нужен, чтобы не сравнивать итераторы при равных значениях.
! Источники могут быть бесконечными или пустыми. Нельзя использовать `heapq.merge` и `sorted`. При равных значениях порядок — сначала из источника с меньшим номером.

## Вопросы с собеседования по уроку:
::: quiz open q32-6 собес
Чем отличаются итерируемый объект, итератор и генератор?
--- answer
Итерируемый объект — всё, по чему можно пройти `for`: у него есть `__iter__`, который возвращает итератор (или, по старому протоколу, `__getitem__` с индексами от 0). Итератор — объект с `__next__`, который возвращает следующий элемент или бросает `StopIteration`, и `__iter__`, возвращающим `self`. Итератор хранит позицию и одноразовый; контейнер можно обходить много раз, потому что каждый раз создаётся новый итератор. Генератор — удобный способ написать итератор: функция с `yield` возвращает объект-генератор, который выполняет тело по частям и замораживает кадр между `next`. Генераторное выражение `(x for x in …)` — то же в одну строку. Генераторы ленивые: экономят память и позволяют работать с бесконечными и огромными потоками. Ещё у генераторов есть `send`, `throw`, `close` и `yield from` для делегирования.
--- points
- iterable: есть `__iter__`, возвращающий итератор
- iterator: `__next__` + `StopIteration`, одноразовый
- генератор — функция с yield, ленивое выполнение, замороженный кадр
- генераторное выражение против списка: память
- send / yield from
:::

::: quiz open q32-7 собес
Как обработать файл, который не помещается в память? А если он приходит по сети или сжат?
--- answer
Читать потоково и не держать всё сразу: `for line in f` читает файл буферами и отдаёт по строке; для бинарных данных — `f.read(chunk_size)` в цикле. Обработку строить ленивым конвейером генераторов (фильтр → преобразование → агрегация), а в памяти держать только агрегаты (`Counter`, суммы). Если агрегат сам не влезает — разбить данные по хешу ключа на части во временные файлы и обработать каждую (внешняя сортировка, map-reduce). Сжатый файл: `gzip.open(path, "rt")` тоже читается потоково. Поток из сети: `requests` с `stream=True` и `iter_lines()` или асинхронный клиент с чтением кусками. Масштабирование: распараллелить по частям файла (`multiprocessing`), поскольку парсинг — CPU-работа, а для очень больших объёмов — Spark или ClickHouse.
--- points
- построчное или кусочное чтение, без read()/readlines()
- генераторный конвейер, в памяти только агрегаты
- если агрегат не влезает — разбить по хешу или внешняя сортировка
- gzip.open и потоковое чтение из сети
- параллельная обработка частей
:::
