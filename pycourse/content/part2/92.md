# 9.2 Дейкстра, система непересекающихся множеств, остовное дерево

## Алгоритм Дейкстры:
Кратчайшие пути от одной вершины во взвешенном графе с **неотрицательными** весами. Жадно берём ближайшую ещё не обработанную вершину (из кучи) и **релаксируем** её рёбра: если через неё до соседа короче — обновляем.
```python
import heapq

def dijkstra(graph, src):                  # graph[u] = [(v, w), ...]
    dist = {src: 0}
    h = [(0, src)]
    while h:
        d, u = heapq.heappop(h)
        if d > dist[u]:
            continue                       # устаревшая запись — пропускаем
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(h, (nd, v))
    return dist
```
O((V + E) log V). Вместо операции «уменьшить ключ» мы просто кладём в кучу новую запись, а старые отбрасываем проверкой `d > dist[u]`.

| Задача | Алгоритм |
|---|---|
| без весов | BFS, O(V + E) |
| веса 0 и 1 | 0-1 BFS с `deque`: вес 0 — в начало, 1 — в конец |
| неотрицательные веса | Дейкстра |
| отрицательные веса | Беллман — Форд, O(V·E), находит отрицательные циклы |
| все пары, маленький V | Флойд — Уоршелл, O(V³) |

::: quiz choice q92-1 собес
Почему Дейкстра неверна с отрицательными весами?
- [ ] куча не умеет хранить отрицательные числа
- [x] алгоритм считает вершину окончательно обработанной, когда достаёт её из кучи; с отрицательным ребром позже может найтись путь короче, но вершина уже «закрыта»
- [ ] из-за переполнения
- [ ] она верна, просто медленнее
--- why
Жадный выбор опирается на то, что продолжение пути не может его укоротить. Отрицательное ребро ломает это предположение. Пример: A→B вес 2, A→C вес 3, C→B вес −2. Дейкстра закроет B с расстоянием 2, хотя через C — 1.

## Система непересекающихся множеств (DSU, Union-Find):
Хранит разбиение элементов на группы и умеет быстро: `find(x)` — представитель группы x, `union(a, b)` — объединить группы.
```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # сжатие пути (половинное)
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                                  # уже вместе: ребро замыкает цикл
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra                              # меньшее дерево под большее
        self.size[ra] += self.size[rb]
        return True
```
Со сжатием путей и объединением по размеру операции почти O(1) (обратная функция Аккермана). **Сигналы:** «связаны ли», «сколько компонент», «добавляем рёбра по одному», «образует ли ребро цикл», «является ли граф деревом» — классический пример Яндекса.

## Минимальное остовное дерево — Краскал:
Отсортировать рёбра по весу и добавлять по порядку, если `union` вернул True (ребро не создаёт цикл). Получится дерево из V − 1 рёбер минимального суммарного веса. O(E log E). Применение — дешёвая сеть: соединить офисы кабелем минимальной длины.

::: quiz output q92-2
Что выведет программа?
```python
parent = list(range(6))

def find(x):
    while parent[x] != x:
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False
    parent[rb] = ra
    return True

print([union(a, b) for a, b in [(0, 1), (2, 3), (1, 3), (0, 2), (4, 5)]])
print(len({find(x) for x in range(6)}))
```
--- answer
[True, True, True, False, True]
2
--- why
После трёх объединений 0, 1, 2, 3 в одной группе, поэтому ребро (0, 2) уже ничего не объединяет: в графе оно замкнуло бы цикл. Остаются группы {0, 1, 2, 3} и {4, 5}. Эта версия без сжатия путей и без учёта размеров: на цепочке объединений `find` будет O(n).
:::

## Вопросы с собеседования по уроку:
::: quiz open q92-3
Как найти кратчайший путь в графе? Какой алгоритм выбрать в зависимости от условий?
--- answer
Зависит от весов. Без весов (или все веса равны) — BFS, O(V + E): первый раз, когда дошли до вершины, путь кратчайший. Веса только 0 и 1 — 0-1 BFS с двусторонней очередью. Неотрицательные веса — Дейкстра с кучей, O((V + E) log V): жадно извлекаем ближайшую необработанную вершину и релаксируем рёбра; для одной цели можно остановиться, когда её извлекли. Если есть хорошая эвристика расстояния до цели (карта, евклидово расстояние) — A*, это Дейкстра с приоритетом `g + h`. Отрицательные веса — Беллман — Форд, O(V·E), он же находит отрицательные циклы. Все пары на небольшом графе — Флойд — Уоршелл, O(V³). Чтобы восстановить сам путь, храним предка каждой вершины при релаксации. На практике (карты, маршрутизация) добавляют предподсчёт: contraction hierarchies, двусторонний поиск.
--- points
- BFS без весов
- 0-1 BFS
- Дейкстра для неотрицательных, сложность
- A* с эвристикой
- Беллман — Форд для отрицательных, Флойд для всех пар
- восстановление пути через предков
:::
