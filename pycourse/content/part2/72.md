# 7.2 Два указателя

## Когда узнавать паттерн:
**Сигналы:** массив **отсортирован** (или его можно отсортировать), «пара или тройка с суммой», «палиндром», «слить два отсортированных», «удалить на месте», «за O(1) дополнительной памяти». Два индекса двигаются так, что каждый проходит массив не больше одного раза — итого O(n).

## Три разновидности:
| Вид | Как двигаются | Примеры |
|---|---|---|
| навстречу | `l = 0`, `r = n - 1`, сдвигаем один из них по условию | пара с суммой в отсортированном, палиндром, контейнер с водой |
| в одну сторону (быстрый и медленный) | `write` отстаёт от `read` | удалить дубликаты, сдвинуть нули на месте |
| по двум массивам | `i` по `a`, `j` по `b` | слияние, пересечение отсортированных |

::: solve Пара с суммой в отсортированном массиве (LeetCode 167)
*«Массив отсортирован, поэтому если `a[l] + a[r]` меньше цели, увеличить сумму можно только сдвинув `l` вправо, а если больше — `r` влево. Мы никогда не пропускаем ответ: пары, которые отбрасываем, заведомо не подходят. O(n) времени, O(1) памяти — лучше, чем словарь».*
```python
def pair_sum_sorted(a, target):
    l, r = 0, len(a) - 1
    while l < r:
        s = a[l] + a[r]
        if s == target:
            return l, r
        if s < target:
            l += 1
        else:
            r -= 1
    return None
```
:::

::: quiz choice q72-1 собес
Почему в `pair_sum_sorted` при `s < target` можно сдвинуть `l`, не проверяя пары `(l, r')` для всех `r' < r`?
- [ ] это эвристика, иногда ответ теряется
- [x] для любого `r' < r` сумма `a[l] + a[r']` ≤ `a[l] + a[r]` < target, значит, ни одна пара с этим `l` не подходит — `l` можно выбросить
- [ ] потому что массив без повторов
- [ ] потому что target положительный
--- why
Это и есть доказательство корректности двух указателей: на каждом шаге мы отбрасываем строку или столбец «матрицы сумм», в котором ответа гарантированно нет. На собесе такое рассуждение вслух — сильный сигнал.
:::

## Слияние двух отсортированных (задача Т-Банка):
«Объединить два отсортированных массива в отсортированный **без повторов** за линейное время и O(1) дополнительной памяти (кроме результата)».
```python
def merge_unique(a, b):
    i = j = 0
    out = []
    while i < len(a) or j < len(b):
        if j == len(b) or (i < len(a) and a[i] <= b[j]):
            x = a[i]; i += 1
        else:
            x = b[j]; j += 1
        if not out or out[-1] != x:
            out.append(x)
    return out
```
`sorted(set(a + b))` даёт тот же результат, но за O((n + m) log(n + m)) и с лишней памятью — на собесе это решение «на троечку», которое стоит назвать как первое и сразу улучшить.

::: quiz output q72-2
Что выведет программа?
```python
def move_zeros(a):
    write = 0
    for read in range(len(a)):
        if a[read] != 0:
            a[write], a[read] = a[read], a[write]
            write += 1
    return a

print(move_zeros([0, 1, 0, 3, 12]))
print(move_zeros([0, 0, 1]))
```
--- answer
[1, 3, 12, 0, 0]
[1, 0, 0]
--- why
`write` указывает на место для следующего ненулевого. Обмен (а не просто присваивание) гарантирует, что нули «выдавливаются» в конец, а порядок ненулевых сохраняется. O(n), O(1) памяти.
:::

::: quiz bug q72-3
В чём ошибка проверки палиндрома?
```python
def is_pal(s):
    l, r = 0, len(s)
    while l < r:
        if s[l] != s[r]:
            return False
        l += 1
        r -= 1
    return True
```
- [x] `r = len(s)` — индекс за пределами строки, нужно `len(s) - 1`
- [ ] условие должно быть `l <= r`
- [ ] нельзя сравнивать символы через `!=`
- [ ] всё правильно
--- why
`s[len(s)]` бросит `IndexError` для непустой строки. Классическая ошибка на единицу. `l < r` правильно: средний символ в строке нечётной длины сравнивать не нужно.
:::

::: hw 72
* `merge_unique` — объединение двух отсортированных списков без повторов за O(n + m), без `set` и `sorted` (Т-Банк) {test_merge_unique}
+ Два указателя, на каждом шаге бери меньший элемент; в результат добавляй, только если он не равен последнему добавленному.
! Повторы бывают внутри каждого списка, а не только между ними. Когда один список кончился, дочитай второй — проще всего в том же цикле, как в разборе.
* `is_palindrome` — строка палиндром, если учитывать только буквы и цифры и не различать регистр (LeetCode 125) {test_is_palindrome}
+ Указатели навстречу. Пропускай символы, для которых `not ch.isalnum()`, сравнивай `lower()`.
! Не создавай отфильтрованную копию: задача на O(1) памяти. Строка только из знаков препинания — палиндром.
* `remove_duplicates` — удалить повторы из отсортированного списка **на месте**, вернуть количество уникальных `k`; первые `k` элементов — уникальные по порядку (LeetCode 26) {test_remove_duplicates}
+ `write = 1`; для каждого `read` от 1: если `a[read] != a[write - 1]`, то `a[write] = a[read]` и `write += 1`.
! Пустой список → 0. Тест проверяет, что это тот же объект списка, а не новый.
* `three_sum` — все уникальные тройки с суммой 0, каждая отсортирована, список троек отсортирован (LeetCode 15) {test_three_sum}
+ Отсортируй. Для каждого `i` — два указателя на отрезке справа от него ищут пару с суммой `-a[i]`. Пропускай одинаковые `a[i]` и, найдя тройку, сдвигай указатели через одинаковые значения.
! O(n²) — это ожидаемая сложность. Перебор троек O(n³) не уложится на 1500 элементах. Дубликаты троек — главная ловушка.
* `trap_water ★` — сколько воды задержится между столбиками высот (LeetCode 42) {test_trap_water}
+ Указатели навстречу и максимумы `left_max`, `right_max`. Двигай ту сторону, где максимум меньше: над ней вода ограничена именно этим максимумом, `water += max - h`.
! Решение с двумя массивами префиксных максимумов — O(n) памяти, тоже засчитывается, но на собесе спросят O(1). Перебор «для каждого столбика ищем максимумы» — O(n²), тест на 200 000 столбиков его не пропустит.
:::

## Вопросы с собеседования по уроку:
::: quiz open q72-4
Когда два указателя подходят лучше хеш-таблицы, и наоборот?
--- answer
Два указателя хороши, когда данные отсортированы (или сортировка допустима по условию) и нужна O(1) дополнительной памяти: пары и тройки с суммой в отсортированном массиве, слияние, удаление на месте, палиндромы. Их корректность опирается на монотонность: сдвиг указателя отбрасывает варианты, в которых ответа гарантированно нет. Хеш-таблица лучше, когда порядок произвольный и сортировать нельзя (нужны исходные индексы), когда нужен один проход по потоку данных, или когда данные не сравнимы, а только хешируемы. Цена — O(n) памяти. Если массив не отсортирован, у двух указателей появляется O(n log n) на сортировку — для «пары с суммой» это хуже словаря за O(n), а для 3Sum — не важно, там всё равно O(n²).
--- points
- два указателя требуют сортированности и монотонности
- O(1) памяти против O(n) у хеша
- хеш — если нужны исходные индексы или поток
- учитывать цену сортировки O(n log n)
:::
