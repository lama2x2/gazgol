# 8.2 Связные списки

## Зачем они на собесе:
В Python связные списки почти не нужны в работе, но «развернуть связный список» спрашивают в каждом четвёртом интервью: задача проверяет аккуратность с указателями и граничными случаями. Узел:
```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next
```

## Приёмы:
| Приём | Для чего |
|---|---|
| **фиктивная голова** (`dummy = ListNode(0, head)`) | вставка и удаление в начале без особого случая; в конце возвращаешь `dummy.next` |
| **быстрый и медленный указатель** | середина списка, поиск цикла (Флойд), k-й с конца |
| **разворот на месте** | `prev, cur = None, head` и перецепка `cur.next = prev` |
| **рисуй** | на собесе нарисуй 3–4 узла и стрелки, прогоняй по шагам |

::: solve Разворот списка (LeetCode 206)
```python
def reverse(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next       # 1. запомнить хвост
        cur.next = prev      # 2. развернуть стрелку
        prev, cur = cur, nxt # 3. шагнуть
    return prev              # новая голова
```
*«Проверяю на 1→2→3: после первого шага 1→None, prev=1; после второго 2→1, prev=2; после третьего 3→2, prev=3, cur=None. Возвращаю 3. Пустой список — сразу None, один узел — он же. O(n) времени, O(1) памяти. Рекурсивная версия короче, но тратит O(n) стека и на длинном списке упрётся в лимит рекурсии Python».*
:::

## Цикл в списке — алгоритм Флойда:
Медленный указатель идёт на 1 шаг, быстрый — на 2. Если цикла нет, быстрый дойдёт до конца. Если цикл есть, внутри цикла быстрый догоняет медленного на 1 узел за шаг и неизбежно встретит его. O(n) времени, O(1) памяти (вместо множества посещённых узлов).

::: quiz choice q82-1 собес
Как найти середину связного списка за один проход?
- [ ] посчитать длину, затем пройти до середины — это два прохода
- [x] быстрый указатель делает два шага, медленный — один; когда быстрый дошёл до конца, медленный в середине
- [ ] скопировать в массив и взять `arr[len // 2]`
- [ ] это невозможно без длины
--- why
Копирование в массив — O(n) памяти: для разминки сойдёт, но спросят O(1). Нюанс для чётной длины: условие `while fast and fast.next` даёт вторую из двух средних, а `while fast.next and fast.next.next` — первую. Уточни у интервьюера, какую нужно.
:::

::: quiz bug q82-2
Что не так с удалением всех узлов со значением `x`?
```python
def remove_all(head, x):
    cur = head
    while cur and cur.next:
        if cur.next.val == x:
            cur.next = cur.next.next
        else:
            cur = cur.next
    return head
```
- [ ] нельзя присваивать `cur.next`
- [x] голова сама может иметь значение `x`: первые узлы никогда не проверяются; нужен фиктивный узел перед головой
- [ ] подряд идущие `x` не удалятся
- [ ] цикл бесконечный
--- why
Подряд идущие `x` как раз удалятся: при удалении `cur` не сдвигается. А вот `remove_all(1→1→2, 1)` вернёт `1→2`. С `dummy = ListNode(0, head)` и стартом с `cur = dummy` особый случай исчезает, ответ — `dummy.next`.

## Вопросы с собеседования по уроку:
::: quiz open q82-3
Чем связный список отличается от массива? Когда что выгоднее?
--- answer
Массив (`list` в Python) хранит элементы (указатели) подряд в памяти: доступ по индексу O(1), хорошая локальность кэша процессора, вставка и удаление в середине — O(n) из-за сдвига, расширение — амортизированное O(1). Связный список — узлы в произвольных местах памяти, связанные ссылками: доступ по индексу O(n), но вставка и удаление в известном месте (есть ссылка на узел) — O(1), нет переаллокаций, легко склеивать списки. Цена — память на ссылки и промахи кэша. На практике массивы почти всегда быстрее. Связные списки уместны, когда нужны частые вставки и удаления в середине по известным узлам: LRU-кэш (двусвязный список + словарь), очереди с удалением из середины, аллокаторы. В Python `collections.deque` — двусвязный список блоков, а `OrderedDict` использует двусвязный список для порядка.
--- points
- память подряд против узлов со ссылками
- доступ по индексу O(1) против O(n)
- вставка и удаление в середине O(n) против O(1) по известному узлу
- кэш-локальность: массив быстрее на практике
- применения: LRU, deque, OrderedDict
:::
