# 10.2 Динамическое программирование

## Когда это DP:
**Сигналы:** «сколько способов», «минимальная / максимальная стоимость», «можно ли», «самая длинная подпоследовательность» — и при этом задача распадается на **перекрывающиеся подзадачи** с **оптимальной подструктурой** (оптимум большой задачи собирается из оптимумов меньших). Перебор решает одни и те же подзадачи экспоненциально много раз; DP решает каждую один раз.

## Рецепт из пяти шагов (проговаривай их вслух):
1. **Состояние**: что значит `dp[i]` (или `dp[i][j]`) — одним предложением
2. **Переход**: как `dp[i]` выражается через меньшие состояния
3. **База**: начальные значения
4. **Порядок вычисления**: чтобы нужные состояния были готовы раньше
5. **Ответ**: какое состояние (или максимум по каким) и есть ответ

## Два способа:
```python
from functools import cache

@cache                                  # сверху вниз: рекурсия + мемоизация
def ways(n):
    if n <= 1:
        return 1
    return ways(n - 1) + ways(n - 2)

def ways_bottom_up(n):                  # снизу вверх: таблица, без рекурсии
    a, b = 1, 1                         # dp[i-2], dp[i-1] — хватает O(1) памяти
    for _ in range(n - 1):
        a, b = b, a + b
    return b
```
Сверху вниз проще придумать, но в Python упирается в лимит рекурсии и медленнее из-за вызовов. Снизу вверх быстрее и часто позволяет хранить только последние строки таблицы.

::: solve Размен монет (LeetCode 322)
*«Состояние: `dp[s]` — минимальное число монет, чтобы набрать сумму s. Переход: `dp[s] = 1 + min(dp[s - c])` по монетам `c <= s`. База: `dp[0] = 0`, остальное — бесконечность. Порядок: s по возрастанию. Ответ: `dp[amount]` или −1. Сложность O(amount · k). Жадный алгоритм "бери самую крупную" здесь не работает: монеты [1, 3, 4], сумма 6 — жадно 4+1+1, а оптимально 3+3».*
```python
def coin_change(coins, amount):
    INF = float("inf")
    dp = [0] + [INF] * amount
    for s in range(1, amount + 1):
        for c in coins:
            if c <= s and dp[s - c] + 1 < dp[s]:
                dp[s] = dp[s - c] + 1
    return dp[amount] if dp[amount] != INF else -1
```
:::

## Классические шаблоны:
| Задача | Состояние | Переход |
|---|---|---|
| ступеньки, Фибоначчи | `dp[i]` — способов дойти до i | `dp[i-1] + dp[i-2]` |
| грабитель (LeetCode 198) | `dp[i]` — максимум с первых i домов | `max(dp[i-1], dp[i-2] + a[i])` |
| пути в сетке | `dp[r][c]` — путей до клетки | `dp[r-1][c] + dp[r][c-1]` |
| рюкзак 0/1 | `dp[w]` — максимум ценности при весе ≤ w | по весу **убывая**: `max(dp[w], dp[w - wi] + vi)` |
| наибольшая общая подпоследовательность | `dp[i][j]` для префиксов | равны: `dp[i-1][j-1] + 1`, иначе `max(dp[i-1][j], dp[i][j-1])` |
| расстояние Левенштейна | `dp[i][j]` — правок между префиксами | `min(удалить, вставить, заменить)` |
| наибольшая возрастающая подпоследовательность | `tails[k]` — минимальный хвост для длины k+1 | бинарный поиск, O(n log n) |

::: quiz choice q102-1 собес
В рюкзаке 0/1 с одномерным массивом `dp[w]` цикл по весам идёт **от большего к меньшему**. Почему?
- [ ] так быстрее работает кэш процессора
- [x] при обходе по возрастанию `dp[w - wi]` уже может включать текущий предмет, и он будет взят несколько раз — получится рюкзак с повторами
- [ ] иначе выйдем за границу массива
- [ ] разницы нет
--- why
По убыванию `dp[w - wi]` ещё хранит значение «без текущего предмета» — с предыдущей строки двумерной таблицы. По возрастанию получается неограниченный рюкзак (каждый предмет сколько угодно раз) — как в размене монет. Отличный вопрос, чтобы проверить понимание, а не заучивание.
:::

::: quiz output q102-2
Что выведет программа?
```python
def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

print(lcs("abcde", "ace"), lcs("abc", "def"), lcs("AGGTAB", "GXTXAYB"))
```
--- answer
3 0 4
--- why
Общие подпоследовательности: «ace», ничего, «GTAB». Таблица `(n+1) × (m+1)` с нулевой строкой и столбцом избавляет от проверок границ. Память O(n·m), но для длины ответа хватает двух строк.

## Вопросы с собеседования по уроку:
::: quiz open q102-3
Что такое динамическое программирование? Чем мемоизация отличается от табуляции?
--- answer
DP — метод решения задач с оптимальной подструктурой и перекрывающимися подзадачами: ответ собирается из ответов меньших подзадач, и каждая подзадача решается один раз, а результат сохраняется. Это превращает экспоненциальный перебор в полиномиальный. Чтобы применить, формулируют состояние (что хранит `dp[i]`), переход, базу, порядок вычисления и где ответ. Мемоизация (сверху вниз) — рекурсивное решение, которое кэширует результаты (`functools.cache`): легко написать из переборного, вычисляются только нужные состояния. Минусы: накладные расходы на вызовы, лимит рекурсии в Python. Табуляция (снизу вверх) — явная таблица, заполняемая циклами в правильном порядке: быстрее, без рекурсии, позволяет экономить память, храня только последние строки, но нужно продумать порядок и иногда считаются лишние состояния. Отличие DP от жадного алгоритма: жадный делает локально лучший выбор и не пересматривает его, а это верно не всегда (размен монет [1, 3, 4]).
--- points
- оптимальная подструктура и перекрывающиеся подзадачи
- состояние, переход, база, порядок, ответ
- мемоизация: сверху вниз, cache, рекурсия
- табуляция: снизу вверх, экономия памяти
- отличие от жадного, пример размена
:::
