# 7.4 Бинарный поиск: по массиву и по ответу

## Когда узнавать паттерн:
**Сигналы:** отсортированный массив, «найти первый / последний элемент, который…», O(log n) в требованиях, огромный диапазон ответа (до 10⁹ и больше), формулировки «минимальная скорость / ёмкость / время, при которой получится». Главное условие — **монотонный предикат**: есть граница, левее которой ответ «нет», а правее — «да» (или наоборот).

## Шаблон, в котором не ошибаешься:
Ищем **первую** позицию, где `ok(i)` истинно, на полуинтервале `[lo, hi)`:
```python
def first_true(lo, hi, ok):
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid          # mid подходит — ответ в [lo, mid]
        else:
            lo = mid + 1      # не подходит — ответ в [mid + 1, hi)
    return lo                 # hi, если подходящих нет
```
- `lower_bound(a, x)` — первая позиция, где `a[i] >= x`: `first_true(0, len(a), lambda i: a[i] >= x)`
- `upper_bound(a, x)` — первая позиция, где `a[i] > x`
- в стандартной библиотеке это `bisect.bisect_left` и `bisect.bisect_right`. На собесе можно сослаться, но часто просят написать самому

Инвариант: ответ всегда лежит в `[lo, hi]`, отрезок строго уменьшается на каждом шаге. В Python переполнения в `(lo + hi) // 2` нет, но в других языках пишут `lo + (hi - lo) // 2` — об этом могут спросить.

::: quiz bug q74-1 собес
Почему этот бинарный поиск иногда зависает?
```python
def first_ge(a, x):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid
        else:
            hi = mid
    return lo
```
- [ ] `//` надо заменить на `/`
- [x] `lo = mid` не сдвигает границу, когда `hi = lo + 1`: `mid` равен `lo`, и цикл крутится вечно; нужно `lo = mid + 1`
- [ ] нужно `while lo <= hi`
- [ ] массив должен быть без повторов
--- why
Каждая ветка обязана уменьшать отрезок. При `lo = 0, hi = 1`: `mid = 0`, и если `a[0] < x`, то `lo = 0` снова. Кроме того, с `hi = len(a) - 1` нельзя вернуть «x больше всех» (позицию `len(a)`): полуинтервал `[0, len(a))` из шаблона решает и это.
:::

## Бинарный поиск по ответу:
Если можно быстро проверить «получится ли при значении v», а «получится» монотонно по v, — ищем минимальное подходящее v бинарным поиском по **диапазону значений**, а не по массиву.

::: solve Минимальная скорость поедания бананов (LeetCode 875)
*«Есть кучки бананов и h часов, за час можно съесть до v бананов из одной кучки. Найти минимальную v. Если успеваем при скорости v, то успеем и при большей — предикат монотонный. Проверка для одной v — O(n): сумма ⌈pile/v⌉. Диапазон v — от 1 до max(piles). Итого O(n log max)».*
```python
def min_eating_speed(piles, h):
    def ok(v):
        return sum((p + v - 1) // v for p in piles) <= h   # ⌈p / v⌉ без float
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```
:::

::: quiz choice q74-2
Массив `[4, 5, 6, 7, 0, 1, 2]` — отсортированный и «повёрнутый». Как найти в нём элемент за O(log n)?
- [ ] нельзя, массив не отсортирован
- [x] на каждом шаге одна из половин `[lo, mid]` или `[mid, hi]` отсортирована — проверь, лежит ли x в её диапазоне, и выбери половину
- [ ] сначала отсортировать, потом искать
- [ ] линейный поиск, но с двух концов
--- why
Сравнение `a[lo] <= a[mid]` говорит, что левая половина отсортирована. Если `a[lo] <= x < a[mid]`, ищем слева, иначе справа. Симметрично для правой половины. Это LeetCode 33 и частая задача второго уровня.
:::

::: hw 74
* `lower_bound` — первая позиция `i`, где `a[i] >= x` (или `len(a)`), без `bisect` {test_lower_bound}
+ Шаблон `first_true` на `[0, len(a))`.
! Пустой массив → 0; `x` больше всех → `len(a)`; повторы → самый левый.
* `search_range` — первая и последняя позиции `x` в отсортированном массиве или `(-1, -1)`, за O(log n) (LeetCode 34) {test_search_range}
+ Два бинарных поиска: `lower_bound(x)` и `lower_bound(x + 1) - 1` (для целых) или `upper_bound(x) - 1`.
! Найти один `x` и расширяться в стороны — O(n) на массиве из одинаковых чисел. Тест это проверит.
* `search_rotated` — индекс `x` в повёрнутом отсортированном массиве без повторов или −1 (LeetCode 33) {test_search_rotated}
+ Отрезок `[lo, hi]` включительно. Если `a[mid] == x` — ответ. Если `a[lo] <= a[mid]`, левая половина отсортирована: при `a[lo] <= x < a[mid]` иди влево, иначе вправо. Иначе отсортирована правая: при `a[mid] < x <= a[hi]` вправо, иначе влево.
! Массив может быть не повёрнут вовсе или из одного элемента. Нестрогое `<=` в `a[lo] <= a[mid]` важно, когда `lo == mid`.
* `min_ship_capacity` — минимальная грузоподъёмность, чтобы перевезти грузы по порядку за `days` дней (LeetCode 1011) {test_min_ship_capacity}
+ Бинарный поиск по ответу на `[max(weights), sum(weights)]`. Проверка: жадно набирай груз в текущий день, пока влезает, иначе начинай новый день; уложились в `days`?
! Нижняя граница — `max(weights)`, а не 1: самый тяжёлый груз должен поместиться целиком. Порядок грузов менять нельзя.
* `find_valley ★` — индекс любого локального минимума за O(log n): `a[i]` меньше соседей (за границами массива — +∞), соседние элементы различны (задача «Найти впадину» из собесов Ozon, LeetCode 162 наоборот) {test_find_valley}
+ Если `a[mid] > a[mid + 1]`, то справа точно есть впадина (иди вниз по склону — где-то он закончится), `lo = mid + 1`; иначе `hi = mid`. Шаблон `first_true` на `[0, n - 1)`.
! Тест проверяет число обращений к элементам: на массиве из миллиона элементов линейный проход не подойдёт. Не вычисляй `min(a)` — это тоже O(n).

## Вопросы с собеседования по уроку:
::: quiz open q74-3 собес
Когда применим бинарный поиск? Как не ошибиться в границах?
--- answer
Бинарный поиск применим, когда есть монотонный предикат: элементы или значения ответа делятся на две части — «нет» и «да», — и мы ищем границу. Это отсортированный массив (найти элемент, первое вхождение, место для вставки), повёрнутый массив (одна половина всегда отсортирована), поиск по ответу (минимальная ёмкость, скорость, время — когда проверку «хватит ли v» можно сделать быстро и она монотонна по v), а также функции на отрезке. Сложность O(log n) шагов, умноженных на стоимость проверки. Чтобы не ошибиться: выбрать один шаблон и всегда его использовать — например, полуинтервал `[lo, hi)` и поиск первого `true`; явно сформулировать инвариант (ответ всегда в `[lo, hi]`); убедиться, что каждая ветка сокращает отрезок (`lo = mid + 1`, `hi = mid`); проверить случаи «подходящих нет» (вернётся `hi`), пустой массив, один элемент, повторы. В Python есть `bisect_left`/`bisect_right` и `key=` (3.10).
--- points
- монотонный предикат как условие
- три класса задач: массив, повёрнутый массив, поиск по ответу
- O(log n) × стоимость проверки
- один шаблон и инвариант
- каждая ветка сокращает отрезок; граничные случаи
:::
