# 10.1 Рекурсия и перебор с возвратом

## Рекурсия — как не утонуть:
1. **База**: самый простой случай, на котором рекурсия останавливается
2. **Шаг**: как свести задачу к меньшей того же вида
3. **Доверие**: считаем, что вызов для меньшей задачи работает правильно, и собираем из него ответ

В Python у рекурсии есть цена: каждый вызов — кадр стека, лимит по умолчанию — 1000 (`sys.getrecursionlimit()`), хвостовая рекурсия не оптимизируется. Для перебора с глубиной до десятков уровней это не проблема, для обхода списка из миллиона элементов — проблема.

## Перебор с возвратом (backtracking):
Строим решение по шагам. На каждом шаге пробуем варианты, уходим вглубь, а вернувшись — **отменяем** выбор и пробуем следующий. **Сигналы:** «все подмножества / перестановки / комбинации», «все способы», «расставить так, чтобы…» (ферзи, судоку), маленькие ограничения (n ≤ 15–20).
```python
def backtrack(path, choices):
    if is_solution(path):
        result.append(path[:])          # копия! path дальше изменится
        return
    for c in choices:
        if not valid(path, c):
            continue                    # отсечение: не идём в заведомо плохие ветки
        path.append(c)                  # выбрать
        backtrack(path, next_choices)   # исследовать
        path.pop()                      # отменить
```

::: solve Все подмножества (LeetCode 78)
*«Для каждого элемента два варианта — взять или не взять, итого 2ⁿ подмножеств, и вывод сам по себе занимает O(n · 2ⁿ). Рекурсия по индексу: на каждом уровне добавляю текущий путь в ответ и пробую продолжить каждым следующим элементом».*
```python
def subsets(nums):
    res, path = [], []
    def go(start):
        res.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            go(i + 1)
            path.pop()
    go(0)
    return res
```
Итеративная альтернатива — битовые маски: число `mask` от 0 до 2ⁿ − 1, бит i означает «элемент i взят».
:::

::: quiz bug q101-1 собес
Почему функция возвращает список пустых списков?
```python
def permutations(nums):
    res, path, used = [], [], [False] * len(nums)
    def go():
        if len(path) == len(nums):
            res.append(path)
            return
        for i, x in enumerate(nums):
            if not used[i]:
                used[i] = True
                path.append(x)
                go()
                path.pop()
                used[i] = False
    go()
    return res
```
- [ ] `used` надо сбрасывать до вызова
- [x] в `res` кладётся **один и тот же** список `path`, который потом опустошается откатами; нужна копия `path[:]`
- [ ] рекурсия не завершается
- [ ] `enumerate` нельзя использовать в рекурсии
--- why
Ловушка из урока 2.1 о ссылках: все элементы `res` — одна ссылка на `path`, а к концу перебора он пуст. Это самая частая ошибка в backtracking на собесе.

::: quiz output q101-2
Что выведет программа?
```python
def gen_parens(n):
    res = []
    def go(s, opened, closed):
        if len(s) == 2 * n:
            res.append(s)
            return
        if opened < n:
            go(s + "(", opened + 1, closed)
        if closed < opened:
            go(s + ")", opened, closed + 1)
    go("", 0, 0)
    return res

print(gen_parens(3))
print(len(gen_parens(4)))
```
--- answer
['((()))', '(()())', '(())()', '()(())', '()()()']
14
--- why
Отсечение «закрывать можно, только если открытых больше» сразу отбрасывает неправильные строки, и перебор идёт только по правильным последовательностям. Их количество — числа Каталана: 1, 2, 5, 14, 42… Строки неизменяемы, поэтому здесь не нужен явный откат: `s + "("` создаёт новую строку.

+ Рекурсия с счётчиками открытых и закрытых, как в тренажёре. Сначала пробуй `(`, потом `)`, тогда порядок получится лексикографическим сам.
! Генерировать все 2²ⁿ строк и фильтровать — слишком медленно для n = 12 (тест).
* `combination_sum` — все уникальные комбинации из чисел-кандидатов (каждое можно брать сколько угодно раз) с суммой target; каждая комбинация по неубыванию, список — в лексикографическом порядке (LeetCode 39) {test_combination_sum}
+ Отсортируй кандидатов. Рекурсия `go(start, remaining)`: для `i >= start` берёшь `c[i]` и вызываешь `go(i, remaining - c[i])` — тот же `i`, потому что число можно повторить. Если `c[i] > remaining` — `break`: дальше только больше.
! Перестановки одной комбинации (`[2, 3]` и `[3, 2]`) — дубликаты; старт с `i`, а не с 0, их исключает. Кандидаты различны и положительны.

## Вопросы с собеседования по уроку:
::: quiz open q101-3
Чем перебор с возвратом отличается от полного перебора? Как его ускорить?
--- answer
Полный перебор генерирует все кандидаты и проверяет каждый целиком. Backtracking строит решение по шагам и бросает ветку, как только частичное решение нарушает условия (отсечение), не достраивая её до конца, — так он обходит лишь часть дерева вариантов. Ускорение: раннее отсечение (проверка ограничений на каждом шаге, а не в конце), правильный порядок выбора (сначала самые ограниченные переменные — как в судоку клетка с минимумом вариантов; сортировка кандидатов, чтобы делать `break`), структуры для быстрой проверки (множества столбцов и диагоналей в ферзях вместо перебора), оценки сверху для отсечения в оптимизационных задачах (ветви и границы), мемоизация повторяющихся подзадач — и тогда это уже динамическое программирование. В Python ещё помогает избегать копирования на каждом шаге: менять общий путь и откатывать, а копировать только готовые решения.
--- points
- отсечение частичных решений против проверки полных
- порядок выбора и сортировка кандидатов
- быстрые структуры для проверки ограничений
- ветви и границы
- мемоизация → переход к DP
:::
