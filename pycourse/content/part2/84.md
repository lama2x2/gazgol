# 8.4 Кучи и интервалы

## Куча — `heapq`:
Двоичная куча в обычном списке: `h[0]` — **минимум**, у элемента `i` дети `2i + 1` и `2i + 2`. `heappush` и `heappop` — O(log n), `heapify` — O(n), посмотреть минимум — O(1).
```python
import heapq
h = []
heapq.heappush(h, (priority, counter, task))   # кортежи сравниваются поэлементно
prio, _, task = heapq.heappop(h)
heapq.nlargest(k, data), heapq.nsmallest(k, data)
```
- **максимальной кучи нет** — кладут `-x` (в 3.14 появились `heapq.heappush_max` и компания, но на собесе почти везде используют минус)
- счётчик в кортеже нужен, чтобы при равных приоритетах не сравнивать сами задачи (они могут быть несравнимы)

**Сигналы:** «k наибольших / наименьших», «k-й по величине», «слить k отсортированных», «медиана потока», «ближайшие события / задачи по времени», Дейкстра.

## Top-k за O(n log k):
Держим **минимальную** кучу размера k. Новый элемент больше минимума кучи — заменяем минимум. В конце в куче k наибольших, а `h[0]` — k-й наибольший. Сортировка всего массива — O(n log n), и для потока данных она невозможна.

::: quiz choice q84-1 собес
Нужно найти 10 самых больших чисел в потоке из миллиарда чисел. Какой подход?
- [ ] загрузить всё в список и отсортировать
- [x] минимальная куча размера 10: O(n log 10) ≈ O(n) времени и O(10) памяти
- [ ] максимальная куча из всех элементов
- [ ] хеш-таблица
--- why
Поток не помещается в память, поэтому сортировка не годится. Куча на k элементов обрабатывает каждый элемент за O(log k) и хранит только k элементов. Если данные лежат в массиве и можно его портить, есть quickselect за O(n) в среднем.
:::

## Интервалы:
**Сигналы:** встречи, бронирования, отрезки времени, «объединить пересекающиеся», «сколько комнат нужно», «вставить интервал». Почти всегда первый шаг — **сортировка по началу** (или по концу — в жадных задачах).

::: solve Слияние интервалов (LeetCode 56)
```python
def merge(intervals):
    res = []
    for start, end in sorted(intervals):
        if res and start <= res[-1][1]:          # пересекается с последним
            res[-1][1] = max(res[-1][1], end)    # max: последний может «поглощать»
        else:
            res.append([start, end])
    return res
```
*«Сортирую по началу — O(n log n). Дальше один проход: если начало текущего не больше конца последнего — сливаю. `max` нужен для случая `[1, 10], [2, 3]`. Касание `[1, 2], [2, 3]` считаю пересечением — уточню у интервьюера».*
:::

## Сколько переговорок нужно (LeetCode 253):
Сортируем встречи по началу и держим **минимальную кучу концов** занятых комнат. Если самая рано освобождающаяся комната свободна к началу встречи — занимаем её (`heapreplace`), иначе нужна новая. Ответ — максимальный размер кучи. Альтернатива — «метод заметающей прямой»: события `(время, +1)` и `(время, −1)`, отсортировать, найти максимум нарастающей суммы.

::: quiz output q84-2
Что выведет программа?
```python
import heapq

h = []
for x in [5, 1, 8, 3, 9, 2]:
    heapq.heappush(h, x)
    if len(h) > 3:
        heapq.heappop(h)
print(sorted(h), h[0])

events = sorted([(1, 1), (4, -1), (2, 1), (3, -1), (3, 1), (5, -1)])
cur = best = 0
for _, d in events:
    cur += d
    best = max(best, cur)
print(best)
```
--- answer
[5, 8, 9] 5
2
--- why
Куча размера 3 оставляет три наибольших, а на вершине — третий по величине. Во второй части события отсортированы так, что при одинаковом времени `-1` идёт раньше `+1` (кортеж `(3, -1)` меньше `(3, 1)`): встреча, закончившаяся в 3, освобождает комнату для встречи, начинающейся в 3. Если нужно наоборот (касание — конфликт), порядок событий меняют.

## Вопросы с собеседования по уроку:
::: quiz open q84-3
Что такое куча и где она используется на практике?
--- answer
Куча — двоичное дерево с «кучевым» свойством: родитель не больше детей (min-heap), поэтому минимум всегда в корне. Хранится в массиве без указателей: дети элемента i — 2i+1 и 2i+2. Вставка и извлечение минимума — O(log n) («просеивание» вверх и вниз), построение из массива — O(n), минимум — O(1). В Python — модуль `heapq` поверх списка (только min-heap; для max — отрицательные ключи), потокобезопасная `queue.PriorityQueue`. Применения: очереди с приоритетом (планировщики задач, Celery с приоритетами), таймеры и отложенные задачи (event loop asyncio держит запланированные колбэки в куче по времени срабатывания), алгоритм Дейкстры, слияние k отсортированных потоков (внешняя сортировка, слияние сегментов в LSM-деревьях баз данных), top-k и медиана потока в аналитике.
--- points
- свойство кучи, минимум в корне
- хранение в массиве, индексы детей
- сложности: push/pop O(log n), heapify O(n)
- heapq: только min-heap, приём с минусом
- применения: приоритеты, таймеры asyncio, Дейкстра, k-way merge, top-k
:::
