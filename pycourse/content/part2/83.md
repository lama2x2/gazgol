# 8.3 Деревья: обходы, BST, LCA

## Узел и обходы:
```python
class TreeNode:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right
```
| Обход | Порядок | Где нужен |
|---|---|---|
| прямой (pre-order) | узел → левое → правое | копирование, сериализация |
| центрированный (in-order) | левое → узел → правое | в BST даёт **отсортированный** порядок |
| обратный (post-order) | левое → правое → узел | высота, удаление, «посчитать снизу вверх» |
| в ширину (BFS) | по уровням, очередь | уровни, кратчайший путь, «ширина дерева» |

**Рекурсивный шаблон** «посчитать что-то по дереву»: ответ для узла = функция(ответ для левого, ответ для правого, сам узел). База — `None`.
```python
def height(node):
    if node is None:
        return 0
    return 1 + max(height(node.left), height(node.right))
```
Глубина рекурсии = высота дерева. Для вырожденного дерева («палки») из 10 000 узлов рекурсия упадёт (лимит 1000) — тогда нужен итеративный обход со стеком. Об этом стоит сказать вслух.

## Обход в ширину по уровням:
```python
from collections import deque

def level_order(root):
    if not root:
        return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):          # ровно текущий уровень
            node = q.popleft()
            level.append(node.val)
            if node.left: q.append(node.left)
            if node.right: q.append(node.right)
        res.append(level)
    return res
```

## Двоичное дерево поиска (BST):
Для каждого узла: все значения в левом поддереве **меньше**, в правом — **больше**. Поиск, вставка, удаление — O(h), где h — высота: O(log n) для сбалансированного дерева (AVL, красно-чёрное) и O(n) для вырожденного. In-order обход BST — отсортированная последовательность.

::: quiz bug q83-1 собес
Почему эта проверка «является ли дерево BST» неверна?
```python
def is_bst(node):
    if node is None:
        return True
    if node.left and node.left.val >= node.val:
        return False
    if node.right and node.right.val <= node.val:
        return False
    return is_bst(node.left) and is_bst(node.right)
```
- [ ] нельзя сравнивать через `>=`
- [x] проверяются только прямые дети, а условие BST — для **всего** поддерева: дерево `5 → (левый 3 → правый 7)` пройдёт проверку, хотя 7 в левом поддереве пятёрки
- [ ] рекурсия здесь не нужна
- [ ] пустое дерево — не BST
--- why
Правильно — передавать вниз допустимый диапазон `(lo, hi)`: для левого поддерева верхняя граница становится `node.val`, для правого — нижняя. Или проверить, что in-order обход строго возрастает. Это одна из самых частых ошибок на собесе.

::: quiz output q83-2
Что выведет программа?
```python
class T:
    def __init__(self, v, l=None, r=None):
        self.v, self.l, self.r = v, l, r

def walk(n, order):
    if not n:
        return []
    if order == "pre":
        return [n.v] + walk(n.l, order) + walk(n.r, order)
    if order == "in":
        return walk(n.l, order) + [n.v] + walk(n.r, order)
    return walk(n.l, order) + walk(n.r, order) + [n.v]

root = T(4, T(2, T(1), T(3)), T(6, None, T(7)))
for o in ("pre", "in", "post"):
    print(o, walk(root, o))
```
--- answer
pre [4, 2, 1, 3, 6, 7]
in [1, 2, 3, 4, 6, 7]
post [1, 3, 2, 7, 6, 4]
--- why
Дерево — BST, поэтому in-order отсортирован. Pre-order начинается с корня, post-order заканчивается им. Склеивание списков в каждом вызове — O(n²) в худшем случае; на собесе лучше передавать общий список-аккумулятор или писать генератор с `yield from`.

## Наименьший общий предок (LCA):
Для двоичного дерева общего вида: рекурсивно ищем `p` и `q` в левом и правом поддеревьях. Если нашли по одному с каждой стороны — текущий узел и есть LCA. Если оба с одной стороны — LCA там.
```python
def lca(node, p, q):
    if node is None or node is p or node is q:
        return node
    left, right = lca(node.left, p, q), lca(node.right, p, q)
    if left and right:
        return node
    return left or right
```
Для BST проще: спускаемся от корня, пока `p` и `q` по одну сторону от узла.

* `level_order` — значения по уровням слева направо (LeetCode 102) {test_level_order}
+ Очередь `deque` и внутренний цикл `for _ in range(len(q))` на один уровень.
! `list.pop(0)` вместо `deque` — O(n²) на широком дереве.
* `is_valid_bst` — проверить, что дерево — BST со строгими неравенствами (LeetCode 98) {test_is_valid_bst}
+ Обход со стеком троек `(узел, lo, hi)`: значение должно быть строго между `lo` и `hi`; левому ребёнку передай `(lo, node.val)`, правому — `(node.val, hi)`. Или in-order обход итеративно и проверка возрастания.
! Проверка только детей — ошибка из тренажёра выше. Равные значения запрещены. Работай без рекурсии: тест подаёт глубокое дерево.
* `lowest_common_ancestor` — LCA двух узлов в двоичном дереве (не BST) (LeetCode 236) {test_lca}
+ Рекурсия из разбора или итеративно: обходом запомни родителя каждого узла, собери предков `p` в множество, поднимайся от `q`, пока не встретишь предка `p`.
! Узел может быть предком самого себя: если `p` — предок `q`, ответ `p`. Сравнивай узлы по идентичности: значения в тесте повторяются.
* `serialize` / `deserialize ★` — превратить дерево в строку и обратно (LeetCode 297) {test_serialize}
+ Прямой обход с маркером пустого узла: `"1,2,#,#,3,4,#,#,5,#,#"`. Разбор — итератор по токенам и рекурсивная функция «прочитать узел»: `#` → `None`, иначе узел, затем левое и правое поддерево. Или BFS по уровням.
! Значения бывают отрицательными и многозначными — разделитель обязателен. Для глубоких деревьев (тест — 3000 уровней) рекурсивный разбор упрётся в лимит: либо BFS, либо итеративная версия.

## Вопросы с собеседования по уроку:
::: quiz open q83-3
Что такое сбалансированное дерево поиска и зачем оно нужно? Где деревья встречаются в бэкенде?
--- answer
BST даёт поиск, вставку и удаление за O(h). Если вставлять отсортированные ключи в обычное BST, оно вырождается в список, и h = n. Сбалансированные деревья (AVL, красно-чёрные) после вставки и удаления выполняют повороты и поддерживают h = O(log n), поэтому операции гарантированно логарифмические. В отличие от хеш-таблицы, дерево хранит порядок: даёт минимум и максимум, «следующий после x», диапазонные запросы — за O(log n + k). В бэкенде: индексы баз данных — B-деревья и B+-деревья (широкие узлы под размер страницы диска, мало уровней, листья связаны для диапазонных сканов); отсортированные множества Redis (skip list, близкий родственник); деревья в файловых системах; trie — для автодополнения и маршрутизации URL; кучи — для очередей с приоритетом и таймеров. В стандартной библиотеке Python сбалансированного дерева нет: обычно хватает `dict` + `sorted`, `bisect` или пакета `sortedcontainers`.
--- points
- вырождение BST и O(h)
- балансировка: AVL, красно-чёрные, h = O(log n)
- порядок и диапазонные запросы — преимущество над хешем
- B-деревья в индексах БД
- в Python: bisect, sortedcontainers
:::
