# 10.3 Жадные алгоритмы и битовые трюки

## Жадный алгоритм:
На каждом шаге делает **локально лучший выбор** и никогда его не пересматривает. Работает быстро (обычно сортировка + один проход), но верен не всегда. На собесе мало придумать жадность — нужно **обосновать**, почему она верна, или привести контрпример.

**Как обосновывать — аргумент обмена:** возьми любое оптимальное решение, которое на первом шаге поступило не жадно, и покажи, что его можно поменять на жадный выбор, не ухудшив результат. Значит, существует оптимальное решение, начинающееся с жадного шага.

| Задача | Жадный выбор | Почему верно |
|---|---|---|
| максимум непересекающихся встреч | сортировать по **концу**, брать, если не пересекается | раньше закончившаяся встреча оставляет больше места |
| минимум интервалов удалить, чтобы не пересекались (LeetCode 435) | то же, ответ — `n − взятые` | то же |
| прыжки (LeetCode 55) | поддерживать самую дальнюю достижимую позицию | достижимость — отрезок `[0, far]` |
| акции, одна сделка (LeetCode 121) | минимум цены слева, лучший `price − min` | перебираем день продажи |
| размен монет | **неверно** в общем случае | [1, 3, 4], сумма 6 |

::: quiz choice q103-1 собес
Нужно выбрать максимум непересекающихся встреч. Какой жадный критерий верен?
- [ ] брать самые короткие встречи
- [ ] брать встречи, которые начинаются раньше
- [x] брать встречи, которые **заканчиваются** раньше, пропуская пересекающиеся с уже взятыми
- [ ] брать встречи с наименьшим числом пересечений
--- why
Контрпример к «начинается раньше»: одна длинная встреча на весь день против десяти коротких. К «самые короткие»: короткая встреча на стыке двух длинных непересекающихся. «Заканчивается раньше» доказывается обменом: первую встречу оптимального решения можно заменить на ту, что закончилась раньше всех, — она ни с чем больше не конфликтует.
:::

## Битовые операции:
| Операция | Смысл |
|---|---|
| `x & 1` | нечётность |
| `x & (x - 1)` | убрать младший единичный бит; `== 0` → x — степень двойки (при x > 0) |
| `x & -x` | оставить только младший единичный бит |
| `a ^ a == 0`, `a ^ 0 == a` | XOR «сокращает» пары |
| `1 << k`, `x >> k` | 2ᵏ, деление на 2ᵏ |
| `mask >> i & 1` | взят ли элемент i в подмножестве-маске |
| `x.bit_count()` (3.10) | число единичных битов |

В Python целые **неограниченной длины**, а отрицательные ведут себя как бесконечное дополнение до двух: `-1` — это «бесконечно много единиц». Поэтому трюки, которые в C++ упираются в 32 бита, в Python иногда работают иначе: `-8 & (-8 - 1)` не равно 0 — уточняй про отрицательные числа.

::: quiz output q103-2 собес
Что выведет программа?
```python
def is_pow2(x):
    return x > 0 and x & (x - 1) == 0

print([x for x in range(-4, 17) if is_pow2(x)])

nums = [4, 1, 2, 1, 2]
acc = 0
for x in nums:
    acc ^= x
print(acc, (12).bit_count(), 12 & -12)
```
--- answer
[1, 2, 4, 8, 16]
4 2 4
--- why
Проверка `x > 0` обязательна: `0 & -1 == 0`, и без неё ноль считался бы степенью двойки. Задача из «пулемёта» Ozon: интервьюер ждёт `x & (x-1)` и вопроса про ноль и отрицательные. XOR всех элементов оставляет единственное число без пары. 12 = 0b1100: две единицы, младшая — 4.
:::

## Вопросы с собеседования по уроку:
::: quiz open q103-3
Как понять, что жадный алгоритм даёт правильный ответ?
--- answer
Нужно доказательство, обычно одно из двух. Аргумент обмена: берём произвольное оптимальное решение, которое на некотором шаге отличается от жадного, и показываем, что жадный выбор можно подставить вместо его выбора без ухудшения; повторяя, превращаем оптимальное решение в жадное — значит, жадное тоже оптимально. «Жадный не отстаёт»: по индукции показываем, что после каждого шага жадное решение не хуже любого другого по какой-то мере (например, раньше заканчивается). Если доказать не получается, ищу контрпример на маленьких данных — помогает перебор на случайных входах. Типичные ловушки: размен монет произвольного номинала (верен только для «канонических» систем вроде 1, 2, 5, 10), рюкзак 0/1 (жадность по удельной ценности верна только для дробного рюкзака), выбор встреч по началу или длине. Если жадность неверна, задачу обычно решает динамика.
--- points
- аргумент обмена
- жадный «не отстаёт» по индукции
- проверка контрпримерами и перебором
- классические ловушки: монеты, рюкзак 0/1, встречи
- при неудаче — динамика
:::
