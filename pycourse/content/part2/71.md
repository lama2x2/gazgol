## Паттерн «запомни, что видел»:
**Сигналы в условии:** «найти пару с суммой», «есть ли дубликат», «сколько раз встречается», «первый неповторяющийся», «сгруппировать». Перебор пар — O(n²). Словарь «значение → индекс или счётчик» превращает поиск в O(1), а весь проход — в O(n) по времени и O(n) по памяти.

::: solve Two Sum (LeetCode 1) — самая частая задача первого этапа
*«Перебор пар — O(n²). Иду слева направо и для каждого x спрашиваю: видел ли я `target - x`? Храню в словаре "значение → индекс". O(n) времени, O(n) памяти».*
```python
def two_sum(nums, target):
    seen = {}                        # значение → индекс
    for j, x in enumerate(nums):
        i = seen.get(target - x)
        if i is not None:
            return i, j
        seen.setdefault(x, j)        # первое вхождение
    return None
```
*«Проверяю: [3, 3], target 6 — на j=1 нахожу 3 с индексом 0. Важно сначала искать, потом добавлять: иначе x найдёт сам себя при target = 2x».*
:::

## Префиксные суммы:
`pref[i]` — сумма первых i элементов (`pref[0] = 0`). Сумма отрезка `nums[l..r]` = `pref[r + 1] - pref[l]` за O(1) после O(n) подготовки.

**Префиксная сумма + словарь** решают «сколько подотрезков с суммой k»: отрезок `(i, j]` имеет сумму k, если `pref[j] - pref[i] = k`, то есть мы ищем, сколько раз раньше встречалась префиксная сумма `pref[j] - k`. Работает и с отрицательными числами — в отличие от скользящего окна.
```python
from collections import defaultdict

def subarray_sum(nums, k):
    count, s = 0, 0
    seen = defaultdict(int)
    seen[0] = 1                      # пустой префикс
    for x in nums:
        s += x
        count += seen[s - k]
        seen[s] += 1
    return count
```

::: quiz choice q71-1 собес
Почему в `subarray_sum` нужно `seen[0] = 1` до цикла?
- [ ] чтобы словарь не был пустым
- [x] чтобы посчитать отрезки, которые начинаются с самого первого элемента: для них «предыдущая» префиксная сумма — пустой префикс, равный 0
- [ ] чтобы обработать отрицательные числа
- [ ] это не нужно, просто оптимизация
--- why
Для `nums = [3], k = 3`: после первого шага `s = 3`, ищем `seen[3 - 3] = seen[0]`. Без начальной единицы ответ будет 0 вместо 1. Такие «служебные» начальные значения — частый источник ошибки на единицу.
:::

def has_pair(nums, target):

::: hw 71
* `two_sum` — индексы `(i, j)`, `i < j`, двух чисел с суммой target; среди пар — с наименьшим `j`, а при нём — с наименьшим `i`; нет пары — `None` (LeetCode 1) {test_two_sum}
+ Словарь «значение → первый индекс». Для каждого `j` сначала ищи `target - x`, потом добавляй `x`, если его ещё нет.
! `setdefault`, а не `seen[x] = j`: нужен наименьший `i`. И не находи сам себя.
* `subarray_sum_k` — количество непрерывных подотрезков с суммой k, числа бывают отрицательными (LeetCode 560) {test_subarray_sum_k}
+ Префиксная сумма и словарь счётчиков префиксов, `seen[0] = 1` до цикла.
! Скользящее окно здесь не работает: с отрицательными числами сумма окна не монотонна. Тест сравнивает с перебором на случайных массивах.
* `longest_consecutive` — длина самой длинной последовательности подряд идущих целых, порядок в массиве не важен, за O(n) (LeetCode 128) {test_longest_consecutive}
+ `s = set(nums)`. Начинай счёт только с чисел, у которых нет `x - 1` в множестве, — это начала цепочек. От начала иди вверх, пока `x + 1` в множестве.
! Сортировка даёт O(n log n). Без проверки «это начало цепочки» внутренний цикл запустится от каждого числа — O(n²) на `range(100000)`, тест это заметит.
* `RangeSum` — сумма отрезка `[l, r]` включительно за O(1) после O(n) подготовки {test_range_sum}
+ В `__init__` построй `pref` длины n + 1. `query(l, r)` — `pref[r + 1] - pref[l]`.
! Тест делает 200 000 запросов к массиву из 100 000 чисел: `sum(nums[l:r+1])` на каждый запрос не уложится.
* `longest_balanced ★` — длина самого длинного подотрезка, в котором нулей и единиц поровну (LeetCode 525) {test_longest_balanced}
+ Замени 0 на −1, тогда «поровну» — это «сумма 0». Префиксный баланс и словарь «баланс → **первый** индекс, где он встретился». Если баланс уже был на индексе i, то отрезок `(i, j]` сбалансирован.
! Начальное значение: баланс 0 на индексе −1. Сохраняй только первое вхождение баланса — нужен самый длинный отрезок.
:::

## Вопросы с собеседования по уроку:
::: quiz open q71-3 собес
Как хеш-таблица помогает ускорять алгоритмы? Какие у неё ограничения?
--- answer
Хеш-таблица даёт поиск, вставку и удаление за O(1) в среднем. Поэтому вложенный перебор «для каждого элемента найти подходящий» (O(n²)) превращается в один проход с запоминанием (O(n)): Two Sum, поиск дубликатов, подсчёт частот, группировка, префиксные суммы со словарём. Цена — O(n) дополнительной памяти. Ограничения: ключи должны быть хешируемыми; порядок значений таблица не хранит, поэтому для «ближайшего большего» или диапазонных запросов нужны отсортированные структуры (сортировка, `bisect`, деревья); худший случай O(n) при коллизиях (в CPython строковые хеши рандомизированы, чтобы защититься от атак подбором коллизий); константа выше, чем у массива, — для ключей из небольшого диапазона чисел массив счётчиков быстрее.
--- points
- O(1) в среднем: поиск, вставка
- превращает O(n²) в O(n) за счёт O(n) памяти
- примеры: two sum, частоты, префиксы
- ограничения: хешируемость, нет порядка, худший случай
- альтернативы: массив счётчиков, сортировка, bisect
:::
