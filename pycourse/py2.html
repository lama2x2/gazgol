Паттерн «запомни, что видел»:

Сигналы в условии: «найти пару с суммой», «есть ли дубликат», «сколько раз встречается», «первый неповторяющийся», «сгруппировать». Перебор пар — O(n²). Словарь «значение → индекс или счётчик» превращает поиск в O(1), а весь проход — в O(n) по времени и O(n) по памяти.

Two Sum (LeetCode 1) — самая частая задача первого этапа

*«Перебор пар — O(n²). Иду слева направо и для каждого x спрашиваю: видел ли я target - x? Храню в словаре "значение → индекс". O(n) времени, O(n) памяти».*

def two_sum(nums, target):
    seen = {}                        # значение → индекс
    for j, x in enumerate(nums):
        i = seen.get(target - x)
        if i is not None:
            return i, j
        seen.setdefault(x, j)        # первое вхождение
    return None

«Проверяю: [3, 3], target 6 — на j=1 нахожу 3 с индексом 0. Важно сначала искать, потом добавлять: иначе x найдёт сам себя при target = 2x».

7.1 Хеш-таблицы и префиксные суммы

Префиксные суммы:

pref[i] — сумма первых i элементов (pref[0] = 0). Сумма отрезка nums[l..r] = pref[r + 1] - pref[l] за O(1) после O(n) подготовки.

Префиксная сумма + словарь решают «сколько подотрезков с суммой k»: отрезок (i, j] имеет сумму k, если pref[j] - pref[i] = k, то есть мы ищем, сколько раз раньше встречалась префиксная сумма pref[j] - k. Работает и с отрицательными числами — в отличие от скользящего окна.

from collections import defaultdict

def subarray_sum(nums, k):
    count, s = 0, 0
    seen = defaultdict(int)
    seen[0] = 1                      # пустой префикс
    for x in nums:
        s += x
        count += seen[s - k]
        seen[s] += 1
    return count

ВыбериПочему в subarray_sum нужно seen[0] = 1 до цикла?· частый вопрос на собесе

Почему

Для nums = [3], k = 3: после первого шага s = 3, ищем seen[3 - 3] = seen[0]. Без начальной единицы ответ будет 0 вместо 1. Такие «служебные» начальные значения — частый источник ошибки на единицу.

Как решать. Словарь «значение → первый индекс». Для каждого j сначала ищи target - x, потом добавляй x, если его ещё нет.

Как решать. В __init__ построй pref длины n + 1. query(l, r) — pref[r + 1] - pref[l].

Подвох. Начальное значение: баланс 0 на индексе −1. Сохраняй только первое вхождение баланса — нужен самый длинный отрезок.

Вопрос с собесаКак хеш-таблица помогает ускорять алгоритмы? Какие у неё ограничения?

Эталонный ответ

Хеш-таблица даёт поиск, вставку и удаление за O(1) в среднем. Поэтому вложенный перебор «для каждого элемента найти подходящий» (O(n²)) превращается в один проход с запоминанием (O(n)): Two Sum, поиск дубликатов, подсчёт частот, группировка, префиксные суммы со словарём. Пара с суммой в отсортированном массиве (LeetCode 167)

*«Массив отсортирован, поэтому если a[l] + a[r] меньше цели, увеличить сумму можно только сдвинув l вправо, а если больше — r влево. Мы никогда не пропускаем ответ: пары, которые отбрасываем, заведомо не подходят. O(n) времени, O(1) памяти — лучше, чем словарь».*

def pair_sum_sorted(a, target):
    l, r = 0, len(a) - 1
    while l < r:
        s = a[l] + a[r]
        if s == target:
            return l, r
        if s < target:
            l += 1
        else:
            r -= 1
    return None

Почему

Это и есть доказательство корректности двух указателей: на каждом шаге мы отбрасываем строку или столбец «матрицы сумм», в котором ответа гарантированно нет. На собесе такое рассуждение вслух — сильный сигнал.

7.2 Два указателя

Слияние двух отсортированных (задача Т-Банка):

«Объединить два отсортированных массива в отсортированный без повторов за линейное время и O(1) дополнительной памяти (кроме результата)».

def merge_unique(a, b):
    i = j = 0
    out = []
    while i < len(a) or j < len(b):
        if j == len(b) or (i < len(a) and a[i] <= b[j]):
            x = a[i]; i += 1
        else:
            x = b[j]; j += 1
        if not out or out[-1] != x:
            out.append(x)
    return out

sorted(set(a + b)) даёт тот же результат, но за O((n + m) log(n + m)) и с лишней памятью — на собесе это решение «на троечку», которое стоит назвать как первое и сразу улучшить.

def move_zeros(a):
    write = 0
    for read in range(len(a)):
        if a[read] != 0:
            a[write], a[read] = a[read], a[write]
            write += 1
    return a

print(move_zeros([0, 0, 1]))

7.2 Два указателя

Домашка 7.2

Как решать

Как решать. Два указателя, на каждом шаге бери меньший элемент; в результат добавляй, только если он не равен последнему добавленному.

Подвох. Повторы бывают внутри каждого списка, а не только между ними. Когда один список кончился, дочитай второй — проще всего в том же цикле, как в разборе.

Как решать

Как решать. Указатели навстречу. Пропускай символы, для которых not ch.isalnum(), сравнивай lower().

Подвох. Не создавай отфильтрованную копию: задача на O(1) памяти. Строка только из знаков препинания — палиндром.

Как решать

Как решать. write = 1; для каждого read от 1: если a[read] != a[write - 1], то a[write] = a[read] и write += 1.

Подвох. Пустой список → 0. Тест проверяет, что это тот же объект списка, а не новый.

Как решать

Как решать. Отсортируй. Для каждого i — два указателя на отрезке справа от него ищут пару с суммой -a[i]. Пропускай одинаковые a[i] и, найдя тройку, сдвигай указатели через одинаковые значения.

Подвох. O(n²) — это ожидаемая сложность. Перебор троек O(n³) не уложится на 1500 элементах. Дубликаты троек — главная ловушка.

Как решать

Как решать. Указатели навстречу и максимумы left_max, right_max. Двигай ту сторону, где максимум меньше: над ней вода ограничена именно этим максимумом, water += max - h.

Подвох. Решение с двумя массивами префиксных максимумов — O(n) памяти, тоже засчитывается, но на собесе спросят O(1). Перебор «для каждого столбика ищем максимумы» — O(n²), тест на 200 000 столбиков его не пропустит.

7.3 Скользящее окно

Когда узнавать паттерн:

Сигналы: «непрерывный подотрезок / подстрока», «самый длинный / короткий / сколько подотрезков, где выполняется условие», «не больше k различных», «без повторов», «сумма окна длины k». Окно [left, right] двигается вправо: правая граница добавляет элемент, левая убирает. Каждый элемент входит и выходит из окна по одному разу — O(n).

Условие применимости: если окно «хорошее», то и любое вложенное в него — тоже хорошее (или наоборот). Тогда при нарушении достаточно сдвигать левую границу. С отрицательными числами для сумм это свойство ломается — там нужны префиксные суммы (урок 7.1).

Шаблон окна переменной длины:

def longest_good(a):
    counts = {}              # состояние окна
    left = best = 0
    for right, x in enumerate(a):
        counts[x] = counts.get(x, 0) + 1          # 1. добавить правый
        while not good(counts):                   # 2. пока окно плохое —
            y = a[left]                           #    убрать левый
            counts[y] -= 1
            if counts[y] == 0:
                del counts[y]
            left += 1
        best = max(best, right - left + 1)        # 3. окно хорошее — обновить ответ
    return best

Внутренний while не делает решение O(n²): left за всё время сдвигается не больше n раз.

Самая длинная подстрока без повторов (LeetCode 3)

Окно хорошее, если в нём нет повторов. Вместо счётчиков удобно хранить последний индекс каждого символа и прыгать левой границей сразу за предыдущее вхождение:

def longest_unique(s):
    last = {}
    left = best = 0
    for right, ch in enumerate(s):
        if last.get(ch, -1) >= left:     # повтор внутри окна
            left = last[ch] + 1
        last[ch] = right
        best = max(best, right - left + 1)
    return best

Проверка >= left важна: символ мог встречаться раньше, но уже вне окна — тогда левую границу трогать нельзя («abba»: на второй a прошлое вхождение левее окна).

7.3 Скользящее окно

ВыбериЗадача: «Найти количество подотрезков, в которых все значения различны» (вторая задача Яндекса из официального разбора). Как посчитать за O(n)?· частый вопрос на собесе

Почему

Если окно [left, right] без повторов, то и все его суффиксы [left', right] при left' ≥ left — тоже. Значит, при фиксированном right хорошие отрезки — это ровно right - left + 1 штук. Это частый приём: «самый длинный» превращается в «сколько всего», если суммировать длины окон.

Что выведет?Что выведет программа?

def max_window_sum(a, k):
    s = sum(a[:k])
    best = s
    for i in range(k, len(a)):
        s += a[i] - a[i - k]
        best = max(best, s)
    return best

print(max_window_sum([1, 4, 2, 10, 2, 3, 1, 0, 20], 4))
print(max_window_sum([-1, -2, -3], 2))
Вывод
24
-3

Окно фиксированной длины: на каждом шаге прибавляем вошедший элемент и вычитаем вышедший, без пересчёта суммы — O(n). Лучшее окно — [3, 1, 0, 20] = 24. Начальное значение best — сумма первого окна, а не 0: иначе для отрицательных чисел вернётся неверный 0.

7.3 Скользящее окно

Домашка 7.3

Как решать

Как решать. Сумма первого окна, затем сдвиг: s += a[i] - a[i - k].

Подвох. Начальный best — сумма первого окна, не 0: тест подаёт отрицательные числа.

Как решать

Как решать. Последние индексы символов и прыжок левой границы, как в разборе.

Подвох. Строка "abba": ответ 2. Если не проверять, что прошлое вхождение внутри окна, левая граница прыгнет назад.

Как решать

Как решать. Окно со счётчиками значений и текущей суммой. Добавил правый — если различных стало больше двух, сдвигай левый, вычитая из суммы и уменьшая счётчики. После — обнови ответ суммой окна.

Подвох. Удаляй ключ из словаря, когда его счётчик упал до 0, иначе len(counts) будет врать. Неотрицательность важна: расширение окна не уменьшает сумму, поэтому самое широкое допустимое окно — лучшее.

Как решать

Как решать. Окно без повторов (как в задаче выше), для каждого right прибавляй right - left + 1.

Подвох. Ответ для 100 000 различных чисел — около 5·10⁹: в Python переполнения нет, но решение должно быть O(n) — перебор подотрезков не уложится.

Как решать

Как решать. need = Counter(t) и счётчик missing = len(t). Двигай правую границу: если символ нужен (need[ch] > 0), уменьши missing; уменьши need[ch] всегда. Когда missing == 0, сдвигай левую границу, пока окно остаётся полным, запоминая лучшее, затем выйди из «полного» состояния.

Подвох. Сравнивать Counter окна с Counter(t) на каждом шаге — O(n · |алфавит|): терпимо, но на собесе спросят O(n). Кратность важна: для t = "aa" окно должно содержать две a.

Когда узнавать паттерн:

Сигналы: отсортированный массив, «найти первый / последний элемент, который…», O(log n) в требованиях, огромный диапазон ответа (до 10⁹ и больше), формулировки «минимальная скорость / ёмкость / время, при которой получится». Шаблон, в котором не ошибаешься:

Ищем первую позицию, где ok(i) истинно, на полуинтервале [lo, hi):

def first_true(lo, hi, ok):
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid          # mid подходит — ответ в [lo, mid]
        else:
            lo = mid + 1      # не подходит — ответ в [mid + 1, hi)
    return lo                 # hi, если подходящих нет
  • lower_bound(a, x) — первая позиция, где a[i] >= x: first_true(0, len(a), lambda i: a[i] >= x)
  • upper_bound(a, x) — первая позиция, где a[i] > x
  • в стандартной библиотеке это bisect.bisect_left и bisect.bisect_right. На собесе можно сослаться, но часто просят написать самому

Инвариант: ответ всегда лежит в [lo, hi], отрезок строго уменьшается на каждом шаге. В Python переполнения в (lo + hi) // 2 нет, но в других языках пишут lo + (hi - lo) // 2 — об этом могут спросить.

Бинарный поиск по ответу:

Минимальная скорость поедания бананов (LeetCode 875)

«Есть кучки бананов и h часов, за час можно съесть до v бананов из одной кучки. Найти минимальную v. Если успеваем при скорости v, то успеем и при большей — предикат монотонный. Проверка для одной v — O(n): сумма ⌈pile/v⌉. Диапазон v — от 1 до max(piles). Итого O(n log max)».

def min_eating_speed(piles, h):
    def ok(v):
        return sum((p + v - 1) // v for p in piles) <= h   # ⌈p / v⌉ без float
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

8.1 Стек, очередь и монотонный стек

Монотонный стек:

Стек, в котором элементы всегда идут по возрастанию (или убыванию). Когда приходит новый элемент, мы выталкиваем всё, что он «побеждает», — и для вытолкнутых он и есть ответ «ближайший справа больший». Каждый элемент кладётся и вынимается один раз — O(n) вместо O(n²).

def next_greater(a):
    res = [-1] * len(a)
    stack = []                        # индексы, значения по убыванию
    for i, x in enumerate(a):
        while stack and a[stack[-1]] < x:
            res[stack.pop()] = x      # x — ближайший справа больший для вершины
        stack.append(i)
    return res

Обход в ширину по уровням:

from collections import deque

def level_order(root):
    if not root:
        return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):          # ровно текущий уровень
            node = q.popleft()
            level.append(node.val)
            if node.left: q.append(node.left)
            if node.right: q.append(node.right)
        res.append(level)
    return res

Двоичное дерево поиска (BST):

Для каждого узла: все значения в левом поддереве меньше, в правом — больше. Поиск, вставка, удаление — O(h), где h — высота: O(log n) для сбалансированного дерева (AVL, красно-чёрное) и O(n) для вырожденного. In-order обход BST — отсортированная последовательность.

    if left and right:

    return left or right

BFS — обход в ширину:

Очередь; посещаем вершины слоями по расстоянию от старта. Даёт кратчайший путь по числу рёбер в невзвешенном графе. O(V + E).

from collections import deque

def bfs(graph, start):
    dist = {start: 0}
    q = deque([start])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:          # отмечаем при добавлении, а не при извлечении
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

DFS — обход в глубину:

Стек (или рекурсия); идём вглубь до упора, затем откатываемся. Для компонент связности, поиска циклов, топологической сортировки, «есть ли путь». O(V + E). Рекурсивный DFS в Python упирается в лимит рекурсии (1000) на длинных цепочках — на собесе пиши итеративный или скажи о sys.setrecursionlimit.

9.1 BFS, DFS и топологическая сортировка

Топологическая сортировка:

Порядок вершин ориентированного графа без циклов (DAG), в котором каждое ребро u → v идёт слева направо: сначала зависимость, потом зависящий. Алгоритм Кана:

  1. посчитай входящие степени
  2. положи в очередь все вершины со степенью 0
  3. достаёшь вершину → в ответ; у её соседей уменьшаешь степень; ставшие нулевыми — в очередь
  4. если в ответе меньше V вершин — в графе цикл

Применения: порядок миграций, сборка зависимостей пакетов, планирование задач с зависимостями (DAG в Airflow), порядок вычисления ячеек в таблице.

def num_islands(grid):
    R, C = len(grid), len(grid[0]) if grid else 0
    seen, count = set(), 0
    for r in range(R):
        for c in range(C):
            if grid[r][c] == "1" and (r, c) not in seen:
                count += 1
                seen.add((r, c))
                q = deque([(r, c)])
                while q:
                    y, x = q.popleft()
                    for ny, nx in ((y + 1, x), (y - 1, x), (y, x + 1), (y, x - 1)):
                        if 0 <= ny < R and 0 <= nx < C and grid[ny][nx] == "1" and (ny, nx) not in seen:
                            seen.add((ny, nx))
                            q.append((ny, nx))
    return count

from collections import deque

def kahn(n, edges):
    g = {i: [] for i in range(n)}
    indeg = [0] * n
    for u, v in edges:
        g[u].append(v)
        indeg[v] += 1
    q = deque(i for i in range(n) if indeg[i] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == n else None

9.2 Дейкстра, система непересекающихся множеств, остовное дерево

Алгоритм Дейкстры:

Кратчайшие пути от одной вершины во взвешенном графе с неотрицательными весами. Жадно берём ближайшую ещё не обработанную вершину (из кучи) и релаксируем её рёбра: если через неё до соседа короче — обновляем.

import heapq

def dijkstra(graph, src):                  # graph[u] = [(v, w), ...]
    dist = {src: 0}
    h = [(0, src)]
    while h:
        d, u = heapq.heappop(h)
        if d > dist[u]:
            continue                       # устаревшая запись — пропускаем
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(h, (nd, v))
    return dist

O((V + E) log V). Вместо операции «уменьшить ключ» мы просто кладём в кучу новую запись, а старые отбрасываем проверкой d > dist[u].

Почему

9.2 Дейкстра, система непересекающихся множеств, остовное дерево

Система непересекающихся множеств (DSU, Union-Find):

Хранит разбиение элементов на группы и умеет быстро: find(x) — представитель группы x, union(a, b) — объединить группы.

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # сжатие пути (половинное)
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                                  # уже вместе: ребро замыкает цикл
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra                              # меньшее дерево под большее
        self.size[ra] += self.size[rb]
        return True

Со сжатием путей и объединением по размеру операции почти O(1) (обратная функция Аккермана). Сигналы: «связаны ли», «сколько компонент», «добавляем рёбра по одному», «образует ли ребро цикл», «является ли граф деревом» — классический пример Яндекса.

Минимальное остовное дерево — Краскал:

Отсортировать рёбра по весу и добавлять по порядку, если union вернул True (ребро не создаёт цикл). Получится дерево из V − 1 рёбер минимального суммарного веса. O(E log E). Применение — дешёвая сеть: соединить офисы кабелем минимальной длины.

10.1 Рекурсия и перебор с возвратом

Рекурсия — как не утонуть:

  1. База: самый простой случай, на котором рекурсия останавливается
  2. Шаг: как свести задачу к меньшей того же вида
  3. Доверие: считаем, что вызов для меньшей задачи работает правильно, и собираем из него ответ

В Python у рекурсии есть цена: каждый вызов — кадр стека, лимит по умолчанию — 1000 (sys.getrecursionlimit()), хвостовая рекурсия не оптимизируется. Для перебора с глубиной до десятков уровней это не проблема, для обхода списка из миллиона элементов — проблема.

Перебор с возвратом (backtracking):

Строим решение по шагам. На каждом шаге пробуем варианты, уходим вглубь, а вернувшись — отменяем выбор и пробуем следующий. Сигналы: «все подмножества / перестановки / комбинации», «все способы», «расставить так, чтобы…» (ферзи, судоку), маленькие ограничения (n ≤ 15–20).

def backtrack(path, choices):
    if is_solution(path):
        result.append(path[:])          # копия! path дальше изменится
        return
    for c in choices:
        if not valid(path, c):
            continue                    # отсечение: не идём в заведомо плохие ветки
        path.append(c)                  # выбрать
        backtrack(path, next_choices)   # исследовать
        path.pop()                      # отменить

Все подмножества (LeetCode 78)

«Для каждого элемента два варианта — взять или не взять, итого 2ⁿ подмножеств, и вывод сам по себе занимает O(n · 2ⁿ). Рекурсия по индексу: на каждом уровне добавляю текущий путь в ответ и пробую продолжить каждым следующим элементом».

def subsets(nums):
    res, path = [], []
    def go(start):
        res.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            go(i + 1)
            path.pop()
    go(0)
    return res

Когда это DP:

Сигналы: «сколько способов», «минимальная / максимальная стоимость», «можно ли», «самая длинная подпоследовательность» — и при этом задача распадается на перекрывающиеся подзадачи с оптимальной подструктурой (оптимум большой задачи собирается из оптимумов меньших). Перебор решает одни и те же подзадачи экспоненциально много раз; DP решает каждую один раз.

Рецепт из пяти шагов (проговаривай их вслух):

  1. Состояние: что значит dp[i] (или dp[i][j]) — одним предложением
  2. Переход: как dp[i] выражается через меньшие состояния
  3. База: начальные значения
  4. Порядок вычисления: чтобы нужные состояния были готовы раньше
  5. Ответ: какое состояние (или максимум по каким) и есть ответ

Два способа:

from functools import cache

@cache                                  # сверху вниз: рекурсия + мемоизация
def ways(n):
    if n <= 1:
        return 1
    return ways(n - 1) + ways(n - 2)

def ways_bottom_up(n):                  # снизу вверх: таблица, без рекурсии
    a, b = 1, 1                         # dp[i-2], dp[i-1] — хватает O(1) памяти
    for _ in range(n - 1):
        a, b = b, a + b
    return b

Сверху вниз проще придумать, но в Python упирается в лимит рекурсии и медленнее из-за вызовов. Снизу вверх быстрее и часто позволяет хранить только последние строки таблицы.

Размен монет (LeetCode 322)

*«Состояние: dp[s] — минимальное число монет, чтобы набрать сумму s. Переход: dp[s] = 1 + min(dp[s - c]) по монетам c <= s. База: dp[0] = 0, остальное — бесконечность. Порядок: s по возрастанию. Ответ: dp[amount] или −1. Сложность O(amount · k). Жадный алгоритм "бери самую крупную" здесь не работает: монеты [1, 3, 4], сумма 6 — жадно 4+1+1, а оптимально 3+3».*

def coin_change(coins, amount):
    INF = float("inf")
    dp = [0] + [INF] * amount
    for s in range(1, amount + 1):
        for c in coins:
            if c <= s and dp[s - c] + 1 < dp[s]:
                dp[s] = dp[s - c] + 1
    return dp[amount] if dp[amount] != INF else -1

def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

print(lcs("abcde", "ace"), lcs("abc", "def"), lcs("AGGTAB", "GXTXAYB"))

Общие подпоследовательности: «ace», ничего, «GTAB». Таблица (n+1) × (m+1) с нулевой строкой и столбцом избавляет от проверок границ. Память O(n·m), но для длины ответа хватает двух строк.

ПодумайЧто такое динамическое программирование? Чем мемоизация отличается от табуляции?

Эталонный ответ

DP — метод решения задач с оптимальной подструктурой и перекрывающимися подзадачами: ответ собирается из ответов меньших подзадач, и каждая подзадача решается один раз, а результат сохраняется. Минусы: накладные расходы на вызовы, лимит рекурсии в Python. Табуляция (снизу вверх) — явная таблица, заполняемая циклами в правильном порядке: быстрее, без рекурсии, позволяет экономить память, храня только последние строки, но нужно продумать порядок и иногда считаются лишние состояния. ПодумайКак понять, что жадный алгоритм даёт правильный ответ?

Эталонный ответ

Нужно доказательство, обычно одно из двух. Аргумент обмена: берём произвольное оптимальное решение, которое на некотором шаге отличается от жадного, и показываем, что жадный выбор можно подставить вместо его выбора без ухудшения; повторяя, превращаем оптимальное решение в жадное — значит, жадное тоже оптимально. «Жадный не отстаёт»: по индукции показываем, что после каждого шага жадное решение не хуже любого другого по какой-то мере (например, раньше заканчивается). Если доказать не получается, ищу контрпример на маленьких данных — помогает перебор на случайных входах. Типичные ловушки: размен монет произвольного номинала (верен только для «канонических» систем вроде 1, 2, 5, 10), рюкзак 0/1 (жадность по удельной ценности верна только для дробного рюкзака), выбор встреч по началу или длине.
