%% 7 | Go изнутри: как это устроено
# 7.1 Массивы, слайсы и строки изнутри

## Зачем знать, как это устроено:
В первой части ты пользовался срезами как списками из Python. На собеседовании спрашивают другое: *почему* код ведёт себя так, а не иначе. Вопросы «как устроен слайс», «как растёт capacity» и «что будет, если передать слайс в функцию» входят в топ-10 вопросов на Go-собесах. Ещё важнее, что на этих местах ошибаются в рабочем коде.

## Массив — значение фиксированной длины:
```go
var a [3]int          // [0 0 0]
b := [...]int{1, 2, 3} // длину посчитает компилятор
c := b                // КОПИЯ всех трёх элементов
c[0] = 100            // b не изменился
```
- длина — часть типа: `[3]int` и `[4]int` — разные типы, их нельзя присвоить друг другу
- массив передаётся и присваивается **целиком**, как число
- массивы можно сравнивать через `==`

В коде массивы встречаются редко. Зато под каждым слайсом лежит массив.

## Слайс — окно в массив:
Слайс — это маленькая структура из трёх полей, её называют *заголовком* (slice header):
```go
type slice struct {
    array unsafe.Pointer // указатель на первый элемент окна
    len   int            // сколько элементов видно
    cap   int            // сколько помещается до конца массива
}
```
Копируя слайс, ты копируешь эти три поля, а массив под ними остаётся общим. Поэтому две переменные-слайса могут менять одни и те же данные.

::: quiz output q71-1
Массив или слайс?
```go
package main

import "fmt"

func main() {
	a := [3]int{1, 2, 3}
	b := a
	b[0] = 100

	s := []int{1, 2, 3}
	t := s
	t[0] = 100

	fmt.Println(a[0], s[0])
}
```
--- answer
1 100
--- why
`b := a` копирует массив целиком, поэтому `a` не меняется. `t := s` копирует только заголовок: `t` и `s` смотрят в один массив, и запись через `t` видна через `s`.
:::

## Срез среза: len и cap
```go
s := []int{0, 1, 2, 3, 4, 5}   // len 6, cap 6
t := s[2:4]                    // [2 3], len 2, cap 4 — до конца массива
u := s[2:4:4]                  // [2 3], len 2, cap 2 — полное выражение s[low:high:max]
```
`cap` нового среза считается от его начала до конца исходного массива. Третье число в `s[low:high:max]` ограничивает capacity. Тогда `append` к такому срезу не сможет залезть в чужие элементы.

## append: в тот же массив или в новый
- если `len < cap`, элемент пишется **в тот же массив** и становится виден всем, кто на этот массив смотрит
- если места нет, Go выделяет **новый массив**, копирует туда элементы и возвращает слайс на него. Старые слайсы продолжают смотреть в старый массив

Поэтому результат `append` всегда присваивают: `s = append(s, x)`.

::: quiz output q71-2 собес
Что станет с исходным слайсом?
```go
package main

import "fmt"

func main() {
	s := []int{0, 1, 2, 3, 4, 5}
	t := s[2:4]
	fmt.Println(t, len(t), cap(t))

	t = append(t, 99)
	fmt.Println(s)
}
```
--- answer
[2 3] 2 4
[0 1 2 3 99 5]
--- why
У `t` capacity 4 (от индекса 2 до конца массива), поэтому `append` не выделяет новый массив, а пишет 99 на место `s[4]`. Это частая причина багов: функция «только добавила элемент к своему кусочку», а данные испортились у вызывающего. Защита — `s[2:4:4]` или копия.
:::

## Как растёт capacity:
Когда место кончается, `append` выделяет массив с запасом, чтобы следующие добавления были дешёвыми:
- пока слайс маленький (до 256 элементов), capacity растёт **вдвое**
- дальше рост плавно замедляется примерно до ×1.25, чтобы не тратить лишнюю память
- итог округляется вверх до класса размера аллокатора, поэтому точные числа бывают «странными»: 1, 2, 4, 8 … 512, 848, 1280

В среднем добавление элемента стоит O(1) (амортизированно). Если размер известен заранее, выделяй сразу: `make([]T, 0, n)`. Тогда перевыделений не будет совсем.

::: quiz output q71-3 собес
Слайс передали в функцию:
```go
package main

import "fmt"

func add(s []int) {
	s[0] = 100
	s = append(s, 4)
	s[1] = 200
}

func main() {
	s := []int{1, 2, 3}
	add(s)
	fmt.Println(s)
}
```
--- answer
[100 2 3]
--- why
Функция получила копию заголовка. `s[0] = 100` пишет в общий массив, и это видно снаружи. У слайса len 3 и cap 3, поэтому `append` создаёт новый массив, и локальная `s` теперь смотрит в него. `s[1] = 200` меняет уже новый массив, вызывающий этого не видит. А сам элемент 4 снаружи не виден никогда: у внешнего `s` len остался 3.
:::

::: quiz output q71-4
Два append от одного слайса:
```go
package main

import "fmt"

func main() {
	a := make([]int, 3, 10)
	b := append(a, 1)
	c := append(a, 2)
	fmt.Println(b[3], c[3])
}
```
--- answer
2 2
--- why
Места в массиве хватает (cap 10), поэтому оба `append` пишут в один и тот же элемент общего массива — с индексом 3. Второй перезаписывает первый, и `b` с `c` видят одно значение. Отсюда правило: не делай несколько `append` от одного слайса, если результаты должны жить независимо.
:::

## nil-слайс и пустой слайс:
```go
var a []int     // nil: заголовок {nil, 0, 0}
b := []int{}    // не nil: указатель на пустой массив, len 0
```
- оба можно читать, обходить через `range` и передавать в `append`: `append(nil, 1)` работает
- `len`, `cap` и `range` у nil-слайса ведут себя как у пустого
- разница видна в JSON: nil кодируется как `null`, пустой как `[]`. Для API это важно, фронтенд часто ждёт `[]`

::: quiz output q71-5
nil или не nil:
```go
package main

import "fmt"

func main() {
	var a []int
	b := []int{}
	fmt.Println(a == nil, b == nil, len(a), len(b))

	a = append(a, 1)
	fmt.Println(a)
}
```
--- answer
true false 0 0
[1]
--- why
`var a []int` — нулевое значение слайса, то есть nil. `[]int{}` — пустой, но не nil. `append` к nil-слайсу работает: он просто выделяет массив.
:::

## copy и пакет slices:
```go
dst := make([]int, len(src))
n := copy(dst, src)              // копирует min(len(dst), len(src)) элементов

slices.Contains(s, 3)            // есть ли элемент
slices.Index(s, 3)               // индекс или -1
slices.Sort(s)                   // сортировка на месте
c := slices.Clone(s)             // независимая копия
slices.Equal(a, b)               // сравнение — через == слайсы сравнивать нельзя
```

::: quiz choice q71-6 собес verify=compile-error
Можно ли сравнить два слайса через ==?
```go
package main

import "fmt"

func main() {
	a := []int{1, 2}
	b := []int{1, 2}
	fmt.Println(a == b)
}
```
- [ ] напечатает `true`
- [ ] напечатает `false`: это разные массивы

- [ ] упадёт с panic
--- why
Слайсы сравнимы только с `nil`. Сравнивать содержимое — работа `slices.Equal`, адрес массива — `&a[0] == &b[0]`. По той же причине слайс не может быть ключом map. А вот массивы `[2]int` сравниваются через `==`.

## Строки изнутри:
Строка — это неизменяемая последовательность **байтов**. Её заголовок похож на слайс, но без cap: указатель и длина.
- `len(s)` — количество байтов. Кириллица в UTF-8 занимает 2 байта, эмодзи — 4
- `s[i]` — байт (`byte`, то есть `uint8`), а не символ
- `for i, r := range s` идёт по **рунам**: `r` — символ (`rune`, то есть `int32`), `i` — номер байта, с которого он начинается
- `utf8.RuneCountInString(s)` — количество символов
- `[]byte(s)` и `string(b)` копируют данные, потому что строка неизменяема

::: quiz output q71-8 собес
Байты, руны, индексы:
```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "Go, привет"
	fmt.Println(len(s), utf8.RuneCountInString(s))

	for i, r := range "ёж" {
		fmt.Println(i, string(r))
	}

	fmt.Println(s[4])
}
```
--- answer
16 10
0 ё
2 ж
208
--- why
«Go, » — 4 байта, «привет» — 6 букв по 2 байта, итого 16 байтов и 10 символов. `range` отдаёт индекс *байта*, где начинается руна, поэтому `ж` на позиции 2. `s[4]` — первый байт буквы «п» в UTF-8 (0xD0 = 208), а не буква.
:::

## Склейка строк:
Каждая `s += x` создаёт новую строку и копирует в неё всё старое содержимое. В цикле получается O(n²). Правильно так:
```go
var b strings.Builder
b.Grow(64)                 // если примерный размер известен — одна аллокация
for _, w := range words {
    b.WriteString(w)
}
result := b.String()       // без лишнего копирования
```
Для пары строк `a + b` и `fmt.Sprintf` нормальны. Builder нужен в циклах.

::: quiz choice q71-9
Нужно собрать CSV из 100 000 строк. Какой вариант быстрее всего?
- [ ] `res += line + "\n"` в цикле
- [ ] `res = fmt.Sprintf("%s%s\n", res, line)` в цикле
- [x] `strings.Builder` с `Grow` и `WriteString` в цикле
- [ ] все одинаковы: компилятор оптимизирует
--- why
Первые два варианта на каждом шаге копируют всю накопленную строку: 100 000 раз всё длиннее и длиннее. Builder дописывает в растущий буфер, как `append`, а `Grow` убирает и перевыделения.
:::

! С `s[i:j]` у куска есть запас capacity, и `append` к первому куску перезапишет начало второго. Тест делает именно такой `append`.
* `Join` — склеить слова через разделитель за одну аллокацию {TestJoin}

## Вопросы с собеседования по уроку:
Ответь своими словами, как на собеседовании, и только потом открой эталон. Пункты для самопроверки — то, что интервьюер ждёт услышать.

::: quiz open q71-10 собес
Чем слайс отличается от массива?
--- answer
Массив — значение фиксированной длины. Длина входит в тип (`[3]int` ≠ `[4]int`), при присваивании и передаче в функцию массив копируется целиком, массивы можно сравнивать через `==`.

Слайс — заголовок из трёх полей: указатель на элемент массива, длина и вместимость. Он ссылается на массив и может расти через `append`, при нехватке места выделяется новый массив. Копирование слайса копирует только заголовок, данные остаются общими. Нулевое значение — `nil`. Сравнивать слайсы можно только с `nil`.
--- points
- длина массива — часть типа, массив копируется целиком
- слайс — структура из указателя, len и cap
- копия слайса разделяет массив с оригиналом
- append может выделить новый массив
- слайсы нельзя сравнивать через == (только с nil)
:::

::: quiz open q71-11 собес
Как работает append и как растёт capacity?
--- answer
Если `len < cap`, `append` записывает элемент в существующий массив и возвращает слайс с увеличенной длиной. Если места нет, выделяется новый массив большего размера, старые элементы копируются, и возвращается слайс на новый массив. Поэтому результат `append` нужно присваивать.

Рост: для небольших слайсов (до 256 элементов) capacity удваивается, дальше коэффициент плавно уменьшается примерно до 1.25. Итоговый размер округляется до класса размера аллокатора. Амортизированная сложность добавления — O(1). Если размер известен, лучше сразу `make([]T, 0, n)`.
--- points
- при len < cap — запись в тот же массив
- иначе — новый массив и копирование
- результат append нужно присваивать
- до ~256 элементов рост ×2, дальше медленнее (~×1.25)
- заранее известный размер — make с capacity
:::

::: quiz open q71-12 собес
Что произойдёт, если передать слайс в функцию и изменить его внутри?
--- answer
В функцию передаётся копия заголовка, а массив общий. Поэтому изменение существующих элементов (`s[i] = x`) видно у вызывающего. А `append` внутри функции меняет только локальный заголовок: вызывающий не увидит новую длину, а если произошло перевыделение, не увидит и дальнейших изменений. Чтобы изменения длины дошли, функция возвращает новый слайс (`s = f(s)`) или принимает указатель на слайс.
--- points
- копируется заголовок, массив общий
- изменение элементов видно снаружи
- append не меняет len у вызывающего
- после перевыделения изменения идут в другой массив
- решение — вернуть слайс из функции
:::

::: quiz open q71-13 собес
Что такое строка в Go? Как узнать её длину в символах и в байтах?
--- answer
Строка — неизменяемая последовательность байтов, обычно в UTF-8. Внутри она устроена как указатель и длина. `len(s)` возвращает количество байтов. Количество символов (рун) — `utf8.RuneCountInString(s)` или `len([]rune(s))`. Индексация `s[i]` возвращает байт, а `range` по строке идёт по рунам и отдаёт индекс байта, с которого начинается руна. `rune` — это алиас `int32`, кодовая точка Unicode.
--- points
- строка неизменяема и состоит из байтов
- len — байты, RuneCountInString — символы
- s[i] — байт, range — руны
- rune = int32
:::

::: quiz open q71-14 собес
Как эффективно конкатенировать строки?
--- answer
Строки неизменяемы, поэтому `+=` в цикле каждый раз создаёт новую строку и копирует старую: O(n²) по времени и много мусора. Для склейки в цикле используют `strings.Builder` (`WriteString`, затем `String()`), заранее вызвав `Grow`, если размер известен. Для слайса строк есть `strings.Join`. Для двух-трёх строк `+` нормален.
--- points
- строки неизменяемы, += копирует
- в цикле это O(n²)
- strings.Builder (+ Grow)
- strings.Join для готового слайса
:::
