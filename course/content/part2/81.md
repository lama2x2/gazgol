# 8.1 Ошибки как следует

## Три вида ошибок в Go:
В первой части ты возвращал `errors.New` и проверял `err != nil`. В настоящем сервисе ошибки путешествуют через несколько слоёв: БД → хранилище → бизнес-логика → HTTP-хендлер. На каждом шаге нужно решать, что с ошибкой делать. Для этого их делят на три вида.

| Вид | Пример | Как проверять |
|---|---|---|
| **sentinel** — заранее объявленное значение | `io.EOF`, `sql.ErrNoRows`, `ErrNotFound` | `errors.Is(err, ErrNotFound)` |
| **типизированная** — свой тип с полями | `*ValidationError{Field: "price"}` | `errors.As(err, &target)` |
| **непрозрачная** — просто текст с контекстом | `fmt.Errorf("connect: %v", err)` | только `err != nil` |

## Обёртка: %w строит цепочку
```go
var ErrNotFound = errors.New("not found")

func (s *Store) Get(id int) (Ad, error) {
    ad, ok := s.ads[id]
    if !ok {
        return Ad{}, fmt.Errorf("ad %d: %w", id, ErrNotFound) // добавили контекст
    }
    return ad, nil
}
```
`%w` кладёт исходную ошибку внутрь новой. Получается цепочка: `handler: get ad 42: not found`. `errors.Is` и `errors.As` проходят по всей цепочке через `Unwrap()`. С `%v` вместо `%w` текст тот же, но цепочка рвётся, и `errors.Is` уже ничего не найдёт.

**Сравнивать текст ошибок нельзя никогда:** `err.Error() == "not found"` сломается от первой правки сообщения.

::: quiz output q81-1 собес
%w против %v:
```go
package main

import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("not found")

func find() error {
	return fmt.Errorf("find ad 42: %w", ErrNotFound)
}

func main() {
	err := fmt.Errorf("handler: %w", find())
	fmt.Println(err)
	fmt.Println(errors.Is(err, ErrNotFound), err == ErrNotFound)

	err2 := fmt.Errorf("handler: %v", find())
	fmt.Println(errors.Is(err2, ErrNotFound))
}
```
--- answer
handler: find ad 42: not found
true false
false
--- why
`errors.Is` разворачивает цепочку и находит `ErrNotFound` на дне. `==` сравнивает только внешнюю ошибку, поэтому `false`. В `err2` использован `%v`: текст тот же, но исходная ошибка превратилась в строку, и цепочки больше нет.
:::

## errors.As — достать ошибку нужного типа:
```go
type ValidationError struct {
    Field string
    Msg   string
}

func (e *ValidationError) Error() string { return e.Field + ": " + e.Msg }

var ve *ValidationError
if errors.As(err, &ve) {          // ищет в цепочке *ValidationError
    fmt.Println("плохое поле:", ve.Field)
}
```
Вторым аргументом передаётся **указатель на переменную** нужного типа. Если такая ошибка нашлась в цепочке, `As` положит её в переменную.

::: quiz output q81-2
Достаём поле из ошибки:
```go
package main

import (
	"errors"
	"fmt"
)

type ValidationError struct{ Field string }

func (e *ValidationError) Error() string { return "invalid " + e.Field }

func main() {
	err := fmt.Errorf("create ad: %w", &ValidationError{Field: "price"})

	var ve *ValidationError
	if errors.As(err, &ve) {
		fmt.Println("поле:", ve.Field)
	}
	fmt.Println(err)
}
```
--- answer
поле: price
create ad: invalid price
--- why
`errors.As` нашёл `*ValidationError` внутри обёртки и записал его в `ve`. Текст внешней ошибки складывается из префикса и `Error()` внутренней.
:::

## errors.Join — несколько ошибок сразу:
Валидация формы находит сразу три проблемы. Возвращать только первую неудобно для пользователя.
```go
var errs []error
if title == "" {
    errs = append(errs, &ValidationError{Field: "title", Msg: "обязательное поле"})
}
if price < 0 {
    errs = append(errs, &ValidationError{Field: "price", Msg: "не может быть отрицательной"})
}
return errors.Join(errs...) // nil, если ошибок нет
```
`errors.Join` возвращает nil для пустого списка, а `Is`/`As` ищут внутри всех объединённых ошибок.

## Где обрабатывать ошибку:
**Ошибку обрабатывают один раз.** Либо ты её обработал (залогировал, вернул пользователю статус, повторил запрос), либо вернул наверх с контекстом. «Залогировал и вернул» — антипаттерн: одна проблема попадает в лог пять раз, по разу на каждом слое.

```go
// плохо
if err != nil {
    log.Printf("ошибка: %v", err)
    return err
}

// хорошо: нижние слои добавляют контекст...
if err != nil {
    return fmt.Errorf("load ad %d: %w", id, err)
}
// ...а решение принимает верхний слой — HTTP-хендлер
```

## panic — только для багов:
- `error` — ожидаемые ситуации: нет записи, неверный ввод, сеть отвалилась
- `panic` — «так не может быть»: нарушен инвариант, программист ошибся, приложение не может стартовать без конфига (`regexp.MustCompile`, `template.Must`)
- `recover` ставят на границах: middleware HTTP-сервера, обработчик задачи в воркере. Тогда один сломанный запрос не роняет весь сервис
- `log.Fatal` и `os.Exit` — только в `main`: они не выполняют `defer`

::: quiz output q81-3 собес
defer и panic — порядок:
```go
package main

import "fmt"

func double() (n int) {
	defer func() { n *= 2 }()
	return 3
}

func main() {
	x := 1
	defer fmt.Println("defer x =", x)
	x = 2

	defer func() {
		if r := recover(); r != nil {
			fmt.Println("поймали:", r, double())
		}
	}()
	panic("ой")
}
```
--- answer
поймали: ой 6
defer x = 1
--- why
Отложенные вызовы выполняются в обратном порядке, поэтому сначала recover, потом печать x. **Аргументы defer вычисляются в момент объявления**, а не выполнения: `x` был 1. В `double` defer меняет именованный результат уже после `return 3`, поэтому получится 6.
:::

::: quiz review q81-4
Найди все проблемы в этом коде. Их не меньше четырёх.
```go
func (h *Handler) GetAd(w http.ResponseWriter, r *http.Request) {
    id, _ := strconv.Atoi(r.PathValue("id"))
    ad, err := h.store.Get(id)
    if err != nil {
        log.Println("store error:", err)
        if err.Error() == "not found" {
            w.WriteHeader(404)
        }
        panic(err)
    }
    json.NewEncoder(w).Encode(ad)
}
```
--- answer
1. Ошибка `Atoi` проигнорирована: для `/ads/abc` получится id = 0, и мы честно поищем объявление с id 0. Нужно вернуть 400.
2. Сравнение текста ошибки: сломается, как только `Get` обернёт ошибку контекстом. Нужен `errors.Is(err, ErrNotFound)`.
3. `panic` на ожидаемой ошибке: любая проблема с БД роняет обработку запроса (или весь сервис без recover-middleware). Нужно вернуть 500.

5. Ошибка логируется, а потом ещё и «возвращается» через panic: двойная обработка.
6. Ошибка `Encode` не проверяется, и `Content-Type: application/json` не выставлен.
--- points
- проигнорирована ошибка Atoi (нужен 400)
- сравнение строк вместо errors.Is
- panic вместо ответа 500
- нет return после ответа 404
- лог + повторная обработка одной ошибки

## Вопросы с собеседования по уроку:
::: quiz open q81-5 собес
Как устроена обработка ошибок в Go? Чем отличаются errors.Is и errors.As?
--- answer
Ошибка в Go — обычное значение типа `error` (интерфейс с методом `Error() string`), которое функция возвращает последним результатом. Исключений нет, ошибки проверяются явно через `if err != nil`. При передаче наверх ошибку оборачивают с контекстом через `fmt.Errorf("...: %w", err)`, и получается цепочка. `errors.Is(err, target)` проверяет, есть ли в цепочке конкретное значение (sentinel-ошибка вроде `sql.ErrNoRows`). `errors.As(err, &target)` ищет в цепочке ошибку определённого *типа* и записывает её в target, чтобы достать поля. Для нескольких ошибок есть `errors.Join`. Сравнивать текст ошибок нельзя.
--- points
- ошибка — значение, интерфейс error
- оборачивание %w и цепочка
- Is — сравнение со значением по цепочке
- As — поиск по типу и доступ к полям
- не сравнивать строки ошибок
:::

::: quiz open q81-6 собес
Как работает defer и в каком порядке выполняются отложенные вызовы? Когда уместен panic?
--- answer
`defer` откладывает вызов до выхода из функции: при обычном return, при panic, при любом пути. Отложенные вызовы выполняются в обратном порядке (LIFO). Аргументы вычисляются в момент объявления defer, а не выполнения. Отложенная функция может изменить именованные результаты, и на этом построен перехват паники через `recover`. `recover` работает только внутри отложенной функции.

Panic уместен для программных ошибок и невозможных состояний (нарушен инвариант, не удалось инициализировать обязательный ресурс при старте, `Must`-функции). Для ожидаемых ошибок — `error`. `recover` ставят на границах (HTTP-middleware, воркер), чтобы один сбой не ронял весь процесс.
--- points
- выполняется при выходе из функции, в том числе при panic
- порядок LIFO
- аргументы вычисляются сразу
- может менять именованные результаты, recover только в defer
- panic — для багов и невозможных состояний, error — для ожидаемых
:::
