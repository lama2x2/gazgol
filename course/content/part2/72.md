# 7.2 Map, интерфейсы и дженерики изнутри

## Map — хеш-таблица:
`map[K]V` хранит пары в хеш-таблице. Чтобы найти ключ, Go считает от него хеш и по хешу сразу определяет, в какой ячейке искать. Поэтому поиск, вставка и удаление в среднем работают за O(1).

**Классическое устройство (до Go 1.24)** до сих пор спрашивают на собесах:
- таблица — массив **бакетов**, в каждом до 8 пар ключ-значение
- младшие биты хеша выбирают бакет, старшие (`tophash`) хранятся в бакете для быстрой проверки
- если бакет полон, к нему цепляется **overflow-бакет**. Так решаются коллизии
- когда в среднем больше 6.5 элементов на бакет, таблица растёт вдвое. Элементы переезжают **постепенно** (эвакуация), понемногу при каждой записи, чтобы не было длинной паузы

**С Go 1.24 — Swiss Tables:** элементы лежат в группах по 8 слотов с управляющим словом, по которому можно проверить сразу 8 кандидатов. Большая map состоит из нескольких независимых таблиц, и растёт каждая по отдельности. Снаружи поведение то же, только быстрее и экономнее по памяти.

## Правила, которые из этого следуют:
- **ключ должен быть сравнимым** (`==`): числа, строки, указатели, каналы, массивы и структуры из сравнимых полей. Слайсы, map и функции ключом быть не могут
- **порядок обхода случайный**, и Go специально перемешивает его на каждом `range`. Нужен порядок — отсортируй ключи
- **nil-map** можно читать (вернётся нулевое значение), но запись в неё вызывает panic
- **взять адрес значения нельзя**: `&m[k]` не скомпилируется, ведь при росте таблицы значения переезжают. По той же причине нельзя `m[k].Price = 10` для структур — храни указатели или перезаписывай целиком
- **map не потокобезопасна**: одновременная запись из двух горутин даёт `fatal error: concurrent map writes`. Это не panic, `recover` её не поймает. Защищай мьютексом
- map передаётся «по ссылке»: внутри лежит указатель на таблицу, поэтому добавленный в функции ключ виден снаружи
- множество (set) делают через `map[T]struct{}`: пустая структура занимает 0 байт

## Интерфейсы изнутри:
Значение интерфейсного типа — пара из двух слов:
```go
type iface struct {
    tab  *itab          // какой конкретный тип внутри + таблица его методов
    data unsafe.Pointer // указатель на само значение
}
```
У пустого интерфейса `any` вместо `itab` просто указатель на тип. При вызове метода через интерфейс Go берёт адрес функции из таблицы. Это *динамическая диспетчеризация*: такой вызов чуть дороже прямого, и компилятор не может его встроить.

**Интерфейс равен nil, только если оба слова — nil.** Если положить в интерфейс nil-указатель, тип уже известен, и интерфейс не nil. Это самая известная ловушка Go.

::: quiz output q72-4 собес
Ловушка с nil:
```go
package main

import "fmt"

type MyErr struct{}

func (*MyErr) Error() string { return "boom" }

func check(fail bool) error {
	var e *MyErr
	if fail {
		e = &MyErr{}
	}
	return e
}

func main() {
	err := check(false)
	fmt.Println(err == nil)
	fmt.Printf("%T\n", err)
}
```
--- answer
false
*main.MyErr
--- why
`check` возвращает интерфейс `error`, внутри которого лежит тип `*MyErr` и значение nil. Тип не пуст, поэтому `err != nil`, и вызывающий решит, что произошла ошибка. Правило: если ошибки нет, пиши явно `return nil`, а не переменную конкретного типа.
:::

## Как правильно работать с интерфейсами:
- **объявляй интерфейс там, где он нужен** (у потребителя), а не рядом с реализацией. Хендлеру нужен `AdStore` с двумя методами — вот он и объявляет `AdStore`
- **маленькие интерфейсы**: `io.Reader` — один метод. Чем меньше интерфейс, тем больше типов его реализуют
- **принимай интерфейсы, возвращай структуры**: `func NewService(s AdStore) *Service`
- проверка на этапе компиляции, что тип реализует интерфейс: `var _ AdStore = (*PostgresStore)(nil)`
- интерфейсы встраиваются: `type ReadWriter interface { Reader; Writer }`

::: quiz choice q72-5 собес
Пакет `postgres` реализует хранилище объявлений, пакет `api` его использует. Где лучше объявить интерфейс `AdStore`?
- [ ] в пакете `postgres`, рядом с реализацией, как в Java
- [x] в пакете `api`, который им пользуется
- [ ] в отдельном пакете `interfaces`, общем для всех
- [ ] интерфейс не нужен: `api` должен зависеть от `postgres` напрямую
--- why
В Go реализация не объявляет, что «implements», поэтому интерфейс может жить у потребителя. Так `api` зависит только от нужных ему методов, в тестах легко подставить фейк, а `postgres` не знает о своих потребителях. Общий пакет `interfaces` — антипаттерн: он связывает всех со всеми.
:::

## ООП в Go — коротко для собеса:
- **инкапсуляция** — через пакеты: заглавная буква экспортирует, строчная скрывает
- **полиморфизм** — через интерфейсы с неявной реализацией (утиная типизация, проверяемая компилятором)
- **наследования нет** — вместо него встраивание (композиция): методы встроенного типа поднимаются наверх, но тип-обёртка не становится встроенным типом
- методы можно объявить у любого своего типа, не только у структуры: `type Rubles int`

## Дженерики:
С Go 1.18 функции и типы могут иметь **параметры типа**:
```go
func Max[T cmp.Ordered](a, b T) T {   // T — любой упорядочиваемый тип
    if a > b {
        return a
    }
    return b
}

type Set[T comparable] map[T]struct{}  // обобщённый тип
```
- **ограничение** (constraint) — интерфейс, описывающий допустимые типы: `any`, `comparable`, `cmp.Ordered` или свой: `interface{ ~int | ~float64 }`
- `~int` значит «int и любые типы на его основе», например `type Rubles int`
- тип обычно выводится сам: `Max(3, 7)`, а не `Max[int](3, 7)`
- у методов не может быть своих параметров типа, только у типа целиком

**Когда нужны:** контейнеры и алгоритмы, одинаковые для разных типов (`slices`, `maps`, кэш, множество). **Когда не нужны:** если разным типам нужно разное *поведение*, это работа интерфейсов.

::: quiz output q72-6
Какой тип выведется?
```go
package main

import (
	"cmp"
	"fmt"
)

func Max[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}

func main() {
	fmt.Println(Max(3, 7), Max("go", "python"))
	fmt.Println(Max(3, 2.5))
}
```
--- answer
7 python
3
--- why
Строки сравниваются лексикографически: «p» > «g». Во втором вызове оба аргумента — нетипизированные константы, поэтому Go выбирает общий тип float64, и `Max(3.0, 2.5)` возвращает `3`. Будь там переменная `x := 3` типа int, код бы не скомпилировался.
:::

## Паттерн functional options:
Как сделать конструктор с кучей необязательных параметров, если нет значений по умолчанию и именованных аргументов? Через функции-опции:
```go
type Client struct {
    timeout time.Duration
    retries int
}

type Option func(*Client)

func WithTimeout(d time.Duration) Option {
    return func(c *Client) { c.timeout = d }
}

func NewClient(opts ...Option) *Client {
    c := &Client{timeout: 5 * time.Second, retries: 3} // значения по умолчанию
    for _, opt := range opts {
        opt(c)
    }
    return c
}

c := NewClient(WithTimeout(time.Second))
```
Новую настройку можно добавить, не ломая уже написанные вызовы. Так устроены gRPC, zap и многие другие библиотеки.

## Вопросы с собеседования по уроку:
::: quiz open q72-7 собес
Как устроена map в Go?
--- answer
Map — хеш-таблица. От ключа считается хеш, младшие биты выбирают бакет, старшие (tophash) хранятся в бакете для быстрого сравнения. В бакете до 8 пар, при переполнении цепляется overflow-бакет — так обрабатываются коллизии. Когда средняя загрузка превышает 6.5 элемента на бакет, таблица растёт вдвое, а элементы переносятся постепенно при последующих операциях (эвакуация). С Go 1.24 используются Swiss Tables: группы по 8 слотов с управляющими байтами и несколько независимо растущих таблиц. Поиск в среднем O(1), в худшем случае при множестве коллизий — O(n). Порядок обхода случайный, map не потокобезопасна.
--- points
- хеш-таблица, бакеты по 8 элементов
- tophash для быстрого сравнения
- коллизии — overflow-бакеты
- рост при load factor 6.5 с постепенной эвакуацией
- с Go 1.24 — Swiss Tables
- O(1) в среднем, порядок случайный, не потокобезопасна
:::

::: quiz open q72-8 собес
Какие типы могут быть ключом map? Можно ли взять указатель на значение в map?
--- answer
Ключом может быть любой сравнимый тип: числа, строки, bool, указатели, каналы, интерфейсы, массивы и структуры, все поля которых сравнимы. Нельзя использовать слайсы, map и функции. Если ключ — интерфейс, а внутри лежит несравнимый тип (например, слайс), будет panic во время выполнения.

Указатель на значение взять нельзя (`&m[k]` не компилируется): при росте таблицы значения переезжают в памяти, и указатель стал бы невалидным. По той же причине нельзя присвоить полю структуры в map. Решение — хранить указатели (`map[K]*V`) или перезаписывать значение целиком.
--- points
- ключ должен быть comparable
- нельзя слайсы, map, функции
- интерфейсный ключ с несравнимым значением — panic
- &m[k] не компилируется, потому что значения переезжают
- решение — map[K]*V или перезапись целиком
:::

::: quiz open q72-9 собес
Почему интерфейс может быть не равен nil, хотя внутри лежит nil-указатель?
--- answer
Значение интерфейса состоит из двух частей: информации о типе (itab или type) и указателя на данные. Интерфейс равен nil, только если обе части nil. Если присвоить интерфейсу nil-указатель конкретного типа, тип становится известен, и интерфейс уже не nil, хотя данные — nil. Типичная ошибка — вернуть из функции с результатом `error` переменную типа `*MyErr`, равную nil: вызывающий получит `err != nil`. Поэтому при отсутствии ошибки нужно явно возвращать `nil`.
--- points
- интерфейс = тип + данные
- nil, только если обе части nil
- nil-указатель конкретного типа делает интерфейс не nil
- пример с error, решение — явный return nil
:::

::: quiz open q72-10 собес
Что такое дженерики в Go и когда их стоит применять?
--- answer
Дженерики — параметры типа у функций и типов (с Go 1.18). Параметр ограничивается constraint'ом — интерфейсом, описывающим допустимые типы: `any`, `comparable`, `cmp.Ordered` или объединение вида `~int | ~float64`. Тип обычно выводится из аргументов. Применять стоит для кода, который одинаково работает с разными типами: контейнеры (множество, кэш, очередь), алгоритмы над слайсами и map, утилиты. Если разным типам нужно разное поведение, лучше подходят интерфейсы. Ограничения: у методов не может быть собственных параметров типа.
--- points
- параметры типа и constraints
- any / comparable / cmp.Ordered / ~int
- вывод типов
- для контейнеров и алгоритмов
- для разного поведения — интерфейсы
:::
