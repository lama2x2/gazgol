Раздел 1

Что такое Go и как он работает

1.1 Что такое Go. Первая программа

Введение:

Go — компилируемый язык со статической типизацией, его сделали в Google в 2009 году. Программа на Go сначала целиком переводится в машинный код (один исполняемый файл), а уже потом запускается. Поэтому многие ошибки ловятся до запуска, и программа работает быстро.

На Go пишут бэкенды, CLI-утилиты и инфраструктуру: Docker, Kubernetes, Terraform написаны на нём.

Что необходимо для программирования на Go?

  • Go: go.dev/dl (на маке — brew install go)
  • редактор: VS Code с расширением Go или GoLand
  • терминал — Go-разработчик живёт в нём

Проверка установки: go version

Модуль — это проект:

Любой проект на Go — это модуль. Его создаёт команда go mod init имя, она пишет файл go.mod. Это как pyproject.toml: имя проекта, версия Go и зависимости.

1.1 Что такое Go. Первая программа

Первая программа:

package main          // исполняемая программа всегда в пакете main

import "fmt"          // пакет для ввода-вывода

func main() {           // точка входа, как if __name__ == "__main__"
    fmt.Println("Привет, Go!")
}
  • go run main.go — скомпилировать и сразу запустить
  • go build — собрать исполняемый файл
  • go fmt ./... — отформатировать код (споров о стиле в Go нет)

Базовые функции пакета fmt:

fmt.Println(a, b): выводит значения через пробел и переводит строку.
fmt.Printf("%s: %d\n", s, n): выводит по шаблону.
fmt.Sprintf(...): то же, но возвращает строку, а не печатает.

Главные «глаголы» шаблона: %d целое, %s строка, %f дробное (%.1f — с одним знаком после запятой), %v что угодно, %q строка в кавычках, %02d целое с ведущим нулём до 2 знаков.

Как это было в Python:

Python
name = "Гоша"
print(f"Привет, {name}!")
Go
name := "Гоша"
fmt.Printf("Привет, %s!\n", name)

1.2 Переменные и типы данных

Переменные:

В Go у каждой переменной есть тип, и поменять его нельзя. Объявить переменную можно тремя способами:

var price int = 5000   // полностью
var title = "Диван"    // тип выведется сам: string
count := 3             // короткая форма, только внутри функций

var sold bool           // без значения → нулевое значение: false

Нулевое значение. Неинициализированных переменных в Go не бывает: 0 у чисел, "" у строк, false у bool, nil у срезов, map и указателей.

Константы: const MaxPhotos = 10. Изменить нельзя.

Несколько сразу: a, b := 1, 2. Обмен значений — одной строкой: a, b = b, a.

Типы данных:

  • int — целые числа (а также int8…int64, uint)
  • float64 — дробные числа
  • string — строка, неизменяемая
  • bool — true / false
  • rune — один символ Unicode (подробно в 3.2)

Типы сами не смешиваются: int + float64 — ошибка компиляции. Нужно явное приведение: float64(n), int(x).

Арифметические операторы: + - * / %

a := 16 / 3        // 5 — у целых деление целочисленное, как // в Python
b := 16 % 3        // 1 — остаток
c := 16.0 / 3      // 5.333… — если хоть одно дробное
d := float64(a) / 2 // 2.5
// оператора ** нет — есть math.Pow(2, 6)
1.2 Коллекции: срезы и словари

Срез (slice) — аналог списка:

prices := []int{100, 250, 700}
prices = append(prices, 900)  // добавить: append возвращает новый срез!
len(prices)                    // 4

Все элементы среза одного типа: []int, []string.

Пустой срез: []int{}. Срез нужной длины из нулей: make([]int, 5) → [0 0 0 0 0].

Индекс и срезы:

Индекс — номер элемента слева направо, начиная с 0. Отрицательных индексов нет: последний элемент — s[len(s)-1].

s := []int{10, 20, 30, 40}
s[0]     // 10
s[1:3]   // [20 30] — с 1 по 3, не включая 3
s[:2]    // [10 20]
s[2:]    // [30 40]
s[10]    // panic: index out of range — как IndexError

Словарь (map):

stock := map[string]int{"чайник": 3}
stock["диван"] = 1          // добавить или изменить
delete(stock, "чайник")     // удалить
n, ok := stock["лампа"]     // 0, false — ключа нет, KeyError не будет

Приём v, ok := m[key] («comma ok») отличает «ключа нет» от «значение равно нулю».

Функция тоже может вернуть два значения: в заголовке пишут (int, bool), в теле — return v, ok.

Как это было в Python:

list → срез []T · dict → map[K]V · set → своего типа нет, делают map[T]bool · tuple → нет, вместо него несколько возвращаемых значений или структура.

1.2 Переменные, типы, коллекции

Возможные ошибки:

  • Ошибки компиляции — программа даже не запустится: неиспользованная переменная или импорт, несовпадение типов, опечатка в имени. В Python такое всплыло бы только при запуске.
  • panic — падение во время работы: выход за границы среза, запись в nil-map, деление целого на 0.
  • Ошибки-значения (error) — ожидаемые проблемы вроде «пользователь ввёл буквы вместо числа». Их функция возвращает, а не бросает. Об этом урок 2.2.

таймер ЧЧ:ММ:СС

func FormatDuration(total int) string {
    h := total / 3600
    m := total % 3600 / 60   // остаток от часов → в минуты
    s := total % 60
    return fmt.Sprintf("%02d:%02d:%02d", h, m, s)
}

Это задача из домашки, решение можно посмотреть. Остальные пиши сам.

Домашка 1.2

Как решать

Как решать. Перепиши формулу из условия: c*9/5 + 32. Параметр уже float64, поэтому и результат получится дробным.

Подвох. Будь c типа int, выражение 9/5 дало бы 1, а не 1.8. Ради этого тип и сделан float64.

Как решать

Как решать. Сложи три числа (это int), переведи сумму в float64 и только потом раздели на 3.

Подвох. float64((a+b+c)/3) неверно: деление уже прошло в целых числах, и дробная часть потеряна.

Как решать

Как решать. Разобрана в конспекте. Повтори её, не подглядывая: часы total/3600, минуты — остаток от часов, делённый на 60, секунды total%60. %02d добавит ведущий ноль.

Подвох. Минуты — не total/60: это минуты с учётом часов, для 3723 получится 62.

Как решать

Как решать. Первый элемент имеет индекс 0, последний — len(nums)-1. Нужен срез с 1 по последний, не включая его. Это одна строка.

Подвох. Правая граница среза не включается, поэтому nums[1:len(nums)-1] уже отбрасывает последний элемент.

Как решать

Как решать. Приём comma ok: v, ok := prices[item], потом return v, ok.

Подвох. Товар «даром» стоит 0 и при этом есть в словаре. По одной цене его не отличить от отсутствующего, поэтому и нужен ok.

Раздел 2

Условные и логические операторы

2.1 Условные и логические операторы. Условные конструкции

Высказывания:

Высказывание — утверждение, которое может быть истинным или ложным. В Go у него тип bool. В отличие от Python, «пустое» не равно «ложному»: if len(s) не скомпилируется, нужно if len(s) > 0.

Операторы:

  • сравнения: == != < > <= >=
  • логические: && (и), || (или), ! (не) — вместо and / or / not

Вычисление ленивое, как в Python: в a && b b не проверяется, если a уже false.

Условный оператор if / else if / else:

if price == 0 {
    fmt.Println("Отдам даром")
} else if price < 1000 {
    fmt.Println("Дёшево")
} else {
    fmt.Println("Норм цена")
}
  • скобки вокруг условия не пишутся, фигурные — обязательны
  • else пишется на той же строке, что и }
  • блок кода задают { }, а не отступы
2.1 Условные и логические операторы. Условные конструкции

if с коротким объявлением:

if n, ok := stock["диван"]; ok {
    fmt.Println("в наличии:", n)
}
// n и ok живут только внутри if

Примеры комбинации операторов:

age, hasLicense := 25, true
if age >= 18 && hasLicense {
    fmt.Println("Можно за руль")
}
if !(age >= 18) || !hasLicense {
    fmt.Println("Нельзя")
}

Если в одном выражении есть и &&, и ||, первым выполняется &&. Если сомневаешься, ставь скобки.

оценка по баллам

func Grade(score int) string {
    if score < 0 || score > 100 {   // сначала отсекаем мусор
        return "ошибка"
    }
    if score >= 90 {
        return "отлично"
    }
    // … дальше сам: порядок проверок важен
}

Приём «ранний return»: в Go стараются не вкладывать if друг в друга, а сразу выходить из функции.

Домашка 2.1

Как решать

Как решать. Сначала отсеки мусор (score < 0 || score > 100), потом проверяй пороги сверху вниз: >= 90, >= 75, >= 60, иначе «плохо».

Подвох. Если начать снизу (>= 60 первым), то 95 попадёт в «удовлетворительно»: сработает первое подходящее условие.

Как решать

Как решать. Переведи условие в код дословно: «делится на 4» → year%4 == 0, «но не на 100» → && year%100 != 0, «или на 400» → || year%400 == 0. Верни выражение сразу, без if.

Подвох. Проверь в уме 1900 (не високосный) и 2000 (високосный): на них ломаются почти все неверные решения.

Как решать

Как решать. Взять машину можно двумя путями: обычным (21+ и стаж от 2) и с инструктором (19+, стаж от 1 и инструктор). Права нужны в обоих случаях. Получается: hasLicense && (обычный || с инструктором).

Подвох. Скобки обязательны: && выполняется раньше ||, и без скобок права будут проверяться только у одного из путей.

2.2 switch. Ошибки как значения

switch — вместо длинной цепочки if:

switch status {
case "new":
    fmt.Println("Новое")
case "sold", "archived":      // несколько значений через запятую
    fmt.Println("Неактивно")
default:
    fmt.Println("Непонятно")
}

break писать не нужно: выполняется только одна ветка.

switch {                       // switch без выражения = цепочка if
case price == 0:   fmt.Println("даром")
case price < 1000: fmt.Println("дёшево")
}

Ошибки — это значения:

Исключений и try/except в Go нет. Функция, которая может не справиться, возвращает два значения: результат и error. Если всё хорошо, ошибка равна nil.

n, err := strconv.Atoi("42abc")
if err != nil {
    fmt.Println("не число:", err)
    return
}
fmt.Println(n + 1)

if err != nil — самая частая строка в любом Go-проекте. Это нормально.

2.2 switch. Ошибки как значения

Как создать свою ошибку:

var ErrNotFound = errors.New("объявление не найдено")  // ошибка-«константа»

func FindPrice(prices map[string]int, title string) (int, error) {
    price, ok := prices[title]
    if !ok {
        return 0, ErrNotFound
    }
    return price, nil
}

// проверка конкретной ошибки — как except KeyError
if errors.Is(err, ErrNotFound) { … }

// ошибка с подробностями
fmt.Errorf("возраст %d вне диапазона", n)

Как это было в Python:

Python
try:
    n = int(s)
except ValueError:
    print("не число")
Go
n, err := strconv.Atoi(s)
if err != nil {
    fmt.Println("не число")
}

Пакеты strconv и strings:

Функции для работы со строками в Go — не методы строки, а функции из пакетов стандартной библиотеки:

  • strconv.Atoi("42") → 42, nil — строка в число, как int()
  • strconv.Itoa(42) → "42" — число в строку, как str()
  • strings.TrimSpace(s) — как s.strip()
  • strings.ToLower(s), strings.ToUpper(s)
  • strings.Fields(s) — как s.split() без аргументов
  • strings.Split(s, ","), strings.Join(parts, "-")
  • strings.Contains(s, "go") — как "go" in s

Домашка 2.2

Как решать

Как решать. switch day с двумя case: в первом пять значений через запятую, во втором два. Для всего остального — default.

Подвох. "Пн" с большой буквы — другая строка, поэтому ответ «неизвестно».

Как решать

Как решать. Сначала проверь b == 0 и верни 0, ErrDivByZero. Иначе return a / b, nil.

Подвох. Возвращай именно переменную ErrDivByZero. Новая errors.New с тем же текстом не пройдёт: errors.Is сравнивает саму ошибку, а не текст.

Как решать

Как решать. Три шага: strings.TrimSpace, затем strconv.Atoi с проверкой err, затем проверка диапазона 0..150. Если на каком-то шаге проблема, сразу return 0, ошибка.

Подвох. "12.5" и "" отдельно ловить не нужно: на них Atoi сам вернёт ошибку.

Как решать

Как решать. switch без выражения, case проверяются сверху вниз. Первым — «не существует»: любая сторона <= 0 или сумма двух сторон <= третьей (три пары). Потом «все равны», потом «хотя бы две равны», в default — разносторонний.

Подвох. Порядок важен: если проверку существования поставить не первой, то (1, 1, 10) окажется «равнобедренным».

Циклы

3.1 Цикл for

Циклы в Go:

Цикл повторяет блок кода несколько раз. В Go для этого есть одно ключевое слово, for, но у него три формы. Отдельного while нет.

1. Классический for со счётчиком:

for i := 0; i < 5; i++ {   // старт; условие; шаг
    fmt.Println(i)           // 0 1 2 3 4 — как for i in range(5)
}

2. for с условием — это while:

n := 12345
for n > 0 {
    n /= 10                  // отрезаем последнюю цифру
}

3. Бесконечный цикл:

Работает, пока его явно не прервут через break или return. Так устроены серверы и игровые циклы. Если забыть про выход, программа зависнет.

for {
    line := readLine()
    if line == "exit" {
        break
    }
}
3.1 Цикл for

Другие операторы в циклах:

  • break — прерывает цикл, даже если условие ещё истинно
  • continue — пропускает остаток итерации и переходит к следующей
for i := 1; i <= 10; i++ {
    if i%2 == 0 {
        continue       // чётные пропускаем
    }
    if i > 7 {
        break          // дальше 7 не идём
    }
    fmt.Println(i)     // 1 3 5 7
}

простое ли число

func IsPrime(n int) bool {
    if n < 2 {
        return false
    }
    for i := 2; i*i <= n; i++ {   // до корня из n
        if n%i == 0 {
            return false          // нашли делитель → выходим сразу
        }
    }
    return true
}

Почему до корня: если у n есть делитель больше √n, то в паре с ним есть и делитель меньше √n, и его мы уже проверили.

Домашка 3.1

Как решать

Как решать. sum := 0, цикл i от 1 до n включительно, внутри sum += i.

Подвох. При n <= 0 цикл ни разу не выполнится и вернётся 0. Отдельная проверка не нужна.

Как решать

Как решать. Как SumTo, только начальное значение 1 и умножение вместо сложения.

Подвох. Если начать с 0, всё умножится на ноль. Случай 0! = 1 получится сам: цикл не выполнится, и вернётся 1.

Как решать

Как решать. Если число отрицательное, сделай его положительным: n = -n. Потом цикл-как-while: пока n >= 10, дели на 10 и увеличивай счётчик. Счёт начинай с 1.

Подвох. С условием «пока n > 0» и счётом с 0 у нуля получится 0 цифр, а должна быть одна.

Как решать

Как решать. Разобрана в конспекте, напиши заново по памяти. Всё, что меньше 2, — не простое. Затем ищи делитель от 2, пока i*i <= n.

Подвох. Условие именно <=. С < число 25 окажется простым: делитель 5 не проверится.

Как решать

Как решать. Цикл «пока n != 1». Внутри if/else по чётности и steps++.

Подвох. Проверь на 6 вручную: 6 → 3 → 10 → 5 → 16 → 8 → 4 → 2 → 1, это 8 шагов.

3.2 for range. Перебор коллекций

for range — перебор последовательности:

items := []string{"чайник", "диван"}
for i, item := range items {     // как for i, item in enumerate(items)
    fmt.Println(i, item)
}
for _, item := range items { … } // индекс не нужен → _
for i := range items { … }       // нужен только индекс

for name, qty := range stock { … } // map: ключ и значение
for i := range 5 { … }             // 0..4, с Go 1.22

Порядок обхода map случайный, и это сделано намеренно. Если нужен порядок, сортируй ключи.

Строки, байты и руны:

Строка в Go — это байты в UTF-8. Латинская буква занимает 1 байт, кириллическая — 2.

s := "Гоша"
len(s)                 // 8 — байт, а не букв!
len([]rune(s))         // 4 — букв (rune = символ)
for _, r := range s {   // range по строке отдаёт руны — это правильно
    fmt.Printf("%c ", r)
}

Срез рун можно менять, как любой срез. Обратно в строку: string(runes).

Сборка нового среза:

Списковых выражений вида [x for x in ...] в Go нет. Пишут обычный цикл с append:

cheap := []int{}
for _, p := range prices {
    if p < 1000 {
        cheap = append(cheap, p)
    }
}
3.2 for range. Перебор коллекций

Обработка ошибок в циклах:

Аналог try/except внутри цикла. Обычно на ошибке либо пропускают элемент через continue, либо останавливаются и возвращают ошибку с контекстом:

for i, line := range lines {
    n, err := strconv.Atoi(line)
    if err != nil {
        return nil, fmt.Errorf("строка %d: %w", i+1, err)
    }
    result = append(result, n)
}

%w «заворачивает» исходную ошибку внутрь новой: снаружи видно, где сломалось, а errors.Is по-прежнему находит исходную причину.

частотный словарь

counts := map[string]int{}
for _, w := range strings.Fields(text) {
    counts[strings.ToLower(w)]++   // нет ключа → 0, потом +1
}

Нулевое значение спасает: defaultdict не нужен.

Домашка 3.2

Как решать

Как решать. Заведи пустой срез result := []int{}, пройди range, чётные (v%2 == 0) добавляй через append.

Подвох. Отрицательные тоже бывают чётными: -2 % 2 == 0. А -3 % 2 равно -1, а не 1, поэтому проверяй чётность через == 0.

Как решать

Как решать. Разобрана в конспекте. Словарь map[string]int{}, цикл по strings.Fields(text), счётчик counts[strings.ToLower(w)]++.

Подвох. Если вернуть nil-map, тест на непустом тексте не пройдёт. Создай словарь заранее.

Как решать

Как решать. r := []rune(s), затем цикл i от 0 до len(r)/2: меняй местами r[i] и r[len(r)-1-i] через a, b = b, a. В конце string(r).

Подвох. Если переворачивать байты, а не руны, кириллица превратится в мусор: каждая буква занимает 2 байта.

Как решать

Как решать. for i, line := range lines. Пустую строку пропускай через continue. При ошибке Atoi сразу return nil, fmt.Errorf("строка %d: %w", i+1, err).

Подвох. Номер строки — i+1 из range, а не отдельный счётчик: пропущенные пустые строки тоже входят в нумерацию.

Как решать

Как решать. seen := map[int]bool{} и новый срез. Для каждого v: если seen[v], пропусти, иначе добавь в результат и запиши seen[v] = true.

Подвох. Для отсутствующего ключа map вернёт false, это нулевое значение. Поэтому if seen[v] работает без проверки comma ok.

Функции и указатели

4.1 Свои функции

Функция:

Функция — именованный блок кода, который выполняется при вызове. У параметров и результата всегда указаны типы.

func Add(a, b int) int {           // одинаковые типы можно объединить
    return a + b
}

func Split(total int) (int, int) {  // несколько результатов
    return total / 60, total % 60
}
min, sec := Split(125)               // 2, 5

Значений по умолчанию и именованных аргументов нет. Если параметров слишком много, передают структуру.

Переменное число аргументов (variadic):

func Sum(nums ...int) int { … }   // внутри nums — это []int
Sum(1, 2, 3)
Sum(prices...)                      // распаковать срез, как *prices

Рекурсивная функция вызывает сама себя:

func Factorial(n int) int {
    if n <= 1 {
        return 1                // базовый случай — без него бесконечная рекурсия
    }
    return n * Factorial(n-1)
}
4.1 Свои функции

Функции — тоже значения:

Функцию можно положить в переменную, передать в другую функцию или вернуть из неё. Аналог lambda — анонимная функция:

double := func(n int) int { return n * 2 }
double(4)  // 8

func Apply(f func(int) int, x int) int { return f(x) }

Замыкание:

Анонимная функция запоминает переменные, которые были вокруг неё при создании, и может их менять:

func NewID() func() int {
    last := 0
    return func() int {
        last++                 // это та же last, а не копия
        return last
    }
}
next := NewID()
next(); next()             // 1, 2

В чём смысл функций?

Тот же, что в Python: не повторять код, дать куску логики понятное имя и проверять его отдельно. Тесты к домашкам как раз проверяют каждую функцию по отдельности.

Домашка 4.1

Как решать

Как решать. mn, mx := a, a, потом сравни с b и c и обнови. В конце return mn, mx.

Подвох. Проверь случай, где минимум последний: (3, 2, 1).

Как решать

Как решать. Внутри функции nums — обычный срез. Если len(nums) == 0, верни 0, false. Иначе за начальный максимум возьми nums[0] и пройди range.

Подвох. Если начать с максимума 0, решение сломается на одних отрицательных числах: (-5, -2, -9).

Как решать

Как решать. Базовый случай: if n < 2 { return n }, он покрывает и 0, и 1. Иначе return Fib(n-1) + Fib(n-2).

Подвох. Без базового случая рекурсия бесконечна, и программа упадёт с переполнением стека.

Как решать

Как решать. Внутри NewCounter объяви count := 0 и верни анонимную функцию, которая делает count++ и возвращает count.

Подвох. Если объявить count вне функции (на уровне пакета), все счётчики станут общими. Тест это проверяет.

Как решать

Как решать. f — обычная переменная, функцию вызывают как f(x). Результат первого вызова передай во второй.

Подвох. Решается одной строкой.

4.2 Указатели. defer, panic, recover

Указатель — адрес значения:

В Python все переменные — ссылки, и об этом можно не думать. В Go аргументы копируются: функция получает копию значения. Если нужно изменить оригинал, передают указатель — адрес переменной в памяти.

price := 5000
p := &price          // & — взять адрес. p имеет тип *int
*p = 4500            // * — пойти по адресу. Теперь price == 4500

func Discount(p *int) { *p = *p * 9 / 10 }
Discount(&price)     // меняет price у вызывающего
  • Нулевое значение указателя — nil. Если разыменовать nil, будет panic, поэтому сначала проверяют if p != nil
  • Арифметики указателей, как в C, нет: это безопасные указатели

Что копируется, а что нет:

  • int, string, bool, структуры, массивы [3]int копируются целиком
  • срез, map и канал при копировании передают «заголовок», а данные внутри остаются общими. Поэтому s[i] = … внутри функции видно снаружи
  • но append внутри функции может создать новый массив, и снаружи его не увидят. Поэтому append всегда возвращает срез: s = append(s, x)
4.2 Указатели. defer, panic, recover

defer — «сделай при выходе из функции»:

Аналог with и finally из Python. Вызов после defer выполнится, когда функция завершится, как бы она ни завершилась: обычным return, по ошибке или через panic.

f, err := os.Open("ads.csv")
if err != nil {
    return err
}
defer f.Close()          // закрытие пишут сразу после открытия
// … работаем с файлом …

Если defer несколько, они выполняются в обратном порядке, как стек: последний отложенный срабатывает первым.

panic и recover:

panic — аварийная остановка: выход за границы среза, nil-указатель, деление целого на 0. Это не замена ошибкам. Panic означает баг в программе, а обычные проблемы передают через error.

recover() внутри defer «ловит» panic. Его используют на границах системы: например, веб-сервер не должен падать целиком из-за одного запроса.

func Safe(f func()) (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("паника: %v", r)  // меняем именованный результат
        }
    }()
    f()
    return nil
}

Домашка 4.2

Как решать

Как решать. a и b — адреса, сами числа достаются через *a и *b. Обменяй их одной строкой: *a, *b = *b, *a.

Подвох. a, b = b, a поменяет только локальные копии указателей, а числа у вызывающего останутся прежними.

Как решать

Как решать. Если p == nil, верни def. Иначе верни *p.

Подвох. Указатель на 0 — не nil. Ноль по адресу — нормальное значение, его и нужно вернуть.

Как решать

Как решать. Пройди по индексам (for i := range nums) и пиши nums[i] *= 2.

Подвох. В for _, v := range nums { v *= 2 } меняется копия v, а не элемент среза.

Как решать

Как решать. Первой строкой поставь defer func() { ... }(), а внутри if r := recover(); r != nil присвой res = 0 и err = fmt.Errorf("%v", r). Дальше обычный return a / b, nil.

Подвох. Работает только с именованными результатами (res int, err error): defer меняет их уже после return.

Как решать

Как решать. В цикле: log = append(log, "open "+name), затем defer func() { log = append(log, "close "+name) }(). В конце return log.

Подвох. Все defer срабатывают не в конце каждой итерации, а при выходе из функции, в обратном порядке. Так и получается «close» задом наперёд.

ООП в Go

5.1 Структуры, методы, инкапсуляция

ООП без классов:

Классов в Go нет, но три идеи ООП остаются:

  • инкапсуляция — через видимость имён в пакете (этот урок)
  • полиморфизм — через интерфейсы (5.2)
  • наследования нет — вместо него встраивание и композиция (5.2)

Структура — свой тип данных:

type Ad struct {
    Title string
    price int      // с маленькой буквы: скрыто от других пакетов
    sold  bool
}
ad := Ad{Title: "Диван"}  // пропущенные поля получают нулевые значения

Методы:

Метод — функция, привязанная к типу. Тип пишется в скобках перед именем метода, это «получатель», аналог self:

func (a Ad) Price() int { return a.price }  // получатель-значение: копия
func (a *Ad) MarkSold()  { a.sold = true }  // получатель-указатель: оригинал

Правило: если метод меняет поля, получатель должен быть *Ad, иначе изменится копия. На практике, если хоть один метод типа принимает указатель, указатель делают у всех.

5.1 Структуры, методы, инкапсуляция

Пакеты и инкапсуляция:

Пакет — это папка с .go-файлами, у которых одинаковая строка package имя. Импорт идёт по пути от имени модуля: import "gazgol/course/lesson51".

  • Имя с большой буквы (NewAd, Title) видно снаружи пакета
  • Имя с маленькой (price) — только внутри пакета. В Python _price — просто договорённость, а в Go это проверяет компилятор

Конструктор:

Специального __init__ нет. Принято писать функцию NewТип, которая проверяет данные и возвращает указатель:

func NewAd(title string, price int) (*Ad, error) {
    if price < 0 {
        return nil, errors.New("цена не может быть отрицательной")
    }
    return &Ad{Title: title, price: price}, nil
}

Раз price скрыто, снаружи нельзя написать ad.price = -100. Цену можно поменять только через методы, которые проверяют правила. В этом и смысл инкапсуляции.

Как это было в Python:

class Ad: → type Ad struct · def __init__ → func NewAd · self → получатель (a *Ad) · __str__ → метод String() string · @property → геттер Price() без приставки Get.

Как решать

Как решать. Если strings.TrimSpace(title) == "" или price < 0, верни nil и ошибку. Иначе return &Ad{Title: title, price: price}, nil.

Подвох. Цена 0 допустима: «отдам даром» — нормальное объявление.

Как решать

Как решать. По одной строке в каждом методе: вернуть поле. Смысл задачи в том, что снаружи пакета поле price недоступно, а метод Price() доступен.

Подвох. Get в названии не пишут: Price(), а не GetPrice().

Как решать

Как решать. Одна строка: a.sold = true.

Подвох. Ответ на вопрос из условия: с получателем Ad изменилась бы копия, и объявление осталось бы непроданным.

Как решать

Как решать. Сначала все проверки (percent вне 1..90 или a.sold, тогда return ошибку), и только потом a.price -= a.price * percent / 100.

Подвох. Если поменять цену до проверок, то при ошибке она уже испорчена. Тест это ловит.

Как решать

Как решать. Основу собери через fmt.Sprintf("%s — %d ₽", ...), и если a.sold, допиши " (продано)".

Подвох. Тире длинное (—) и окружено пробелами. Скопируй его из условия.

5.2 Встраивание и интерфейсы

Встраивание вместо наследования:

Если в структуру положить другой тип без имени поля, его поля и методы «поднимаются» наверх. Получается композиция: Seller содержит User, а не является им.

type User struct { Name string }
func (u User) Hello() string { return "Я " + u.Name }

type Seller struct {
    User              // встроили
    Phone string
}
s := Seller{User: User{"Гоша"}, Phone: "+7…"}
s.Name; s.Hello()     // работает, как будто это поля Seller
s.User.Hello()        // явный вызов «родителя», аналог super()

Важно: Seller нельзя передать туда, где ждут User. Это разные типы. Общее поведение описывают интерфейсами.

Интерфейс — набор методов:

type Delivery interface {
    Name() string
    Cost(km int) int
}

Если получатель внутри метода не нужен, имя можно не писать: func (Pickup) Cost(km int) int { return 0 }.

Любой тип, у которого есть эти методы, автоматически реализует интерфейс. Слова implements нет. Это утиная типизация, как в Python, только проверяет её компилятор.

5.2 Встраивание и интерфейсы

Полиморфизм:

Функция принимает интерфейс и работает с любым типом, который его реализует. Конкретные типы ей знать не нужно:

func PrintPrices(opts []Delivery, km int) {
    for _, d := range opts {
        fmt.Println(d.Name(), d.Cost(km))   // у каждого типа своя Cost
    }
}
PrintPrices([]Delivery{Pickup{}, Courier{PerKm: 30}}, 10)

Интерфейсы, которые уже встречались:

  • error — это интерфейс с одним методом Error() string
  • fmt.Stringer — String() string. Его ищет fmt.Println
  • any — пустой интерфейс, ему подходит любое значение

Правило Go: интерфейсы делают маленькими, на 1–2 метода, и объявляют там, где их используют, а не там, где реализуют.

Узнать конкретный тип (type switch):

switch x := v.(type) {
case int:          fmt.Println("число", x+1)
case fmt.Stringer: fmt.Println(x.String())
case nil:          fmt.Println("пусто")
}
d, ok := v.(Delivery)   // проверка одного типа, как isinstance

Как решать

Как решать. fmt.Sprintf("%s (★%.1f)", u.Name, u.Rating). %.1f оставит один знак после запятой: 4.83 → 4.8, 5 → 5.0.

Подвох. Звёздочку ★ скопируй из условия, на клавиатуре её нет.

Как решать

Как решать. Вызови s.User.Contact() и допиши ", тел. " + s.Phone.

Подвох. Если внутри написать s.Contact(), метод Seller будет вызывать сам себя бесконечно.

Как решать. Заполни шесть однострочных методов. У курьера ставку бери из получателя: c.PerKm. У почты km / 100 — целое деление, полные сотни.

Подвох. Для почты на 250 км две полные сотни: 350 + 2·50 = 450.

Как решать. Пустой срез → nil и ошибка. Иначе best := options[0], пройди остальные и заменяй best, если Cost строго меньше.

Подвох. С <= при равной цене выберется последний вариант, а нужен первый.

Подвох. Срабатывает первый подходящий case. time.Second тоже Stringer и даст "1s", а обычная строка "строка" — не Stringer, для неё ответ «неизвестно».

Раздел 6

Конкурентность

6.1 Горутины и каналы

Горутина:

Горутина — функция, которая выполняется одновременно с остальным кодом. Достаточно написать go перед вызовом. Горутины очень лёгкие: можно запустить сотни тысяч, и Go сам распределит их по ядрам процессора. В Python ближайший аналог — asyncio, но там нет настоящего параллелизма из-за GIL, а здесь он есть.

go sendEmail(user)       // запустили и пошли дальше, не ждём
go func() {
    fmt.Println("я в горутине")
}()

Когда завершается main, программа завершается целиком, даже если горутины ещё работают. Поэтому их нужно дожидаться: через каналы или WaitGroup (6.2).

Канал — труба между горутинами:

ch := make(chan int)      // небуферизованный: отправитель ждёт получателя
go func() { ch <- 42 }()   // отправить
v := <-ch                  // получить (ждёт, пока придёт значение)

buf := make(chan int, 10) // буферизованный: до 10 значений без ожидания
close(ch)                  // «больше ничего не будет»
for v := range ch { … }   // читать, пока канал не закроют

Девиз Go: «не общайтесь через общую память, делитесь памятью через общение». Вместо общих переменных с блокировками данные передают по каналам.

6.1 Горутины и каналы

Конвейер (pipeline):

func Generate(n int) <-chan int {   // <-chan: канал только для чтения
    ch := make(chan int)
    go func() {
        defer close(ch)               // закрывает тот, кто пишет
        for i := 1; i <= n; i++ {
            ch <- i
        }
    }()
    return ch
}

Каждая стадия — горутина, которая читает из одного канала и пишет в другой. Стадии работают одновременно.

select — ждать несколько каналов сразу:

select {
case v := <-results:
    fmt.Println("ответ:", v)
case <-time.After(2 * time.Second):
    fmt.Println("слишком долго")
}

select выполняет ту ветку, канал которой готов первым. Так делают таймауты и отмену операций.

Типичные ошибки:

  • deadlock — все горутины ждут друг друга. Go пишет all goroutines are asleep
  • утечка горутины — она навсегда застряла на отправке в канал, который никто не читает
  • отправка в закрытый канал вызывает panic

Домашка 6.1

Как решать

Как решать. Пример есть в конспекте, напиши его заново не глядя: создай канал, запусти горутину, которая отправит 1..n и закроет канал (defer close(ch)), и сразу верни канал.

Подвох. Если отправлять без горутины, функция зависнет: в небуферизованный канал некому читать.

Как решать

Как решать. Та же схема, что у Generate: новый канал и горутина. Внутри for v := range in { out <- v * v }, после цикла close(out).

Подвох. Если забыть закрыть out, читатель будет ждать вечно. Тест в этом случае покажет -999.

Как решать

Как решать. Если parts < 1, сделай parts = 1. Размер куска: (len(nums) + parts - 1) / parts (деление с округлением вверх). Иди по срезу шагом size, на каждый кусок запускай горутину, которая отправит сумму в канал. Запомни, сколько горутин запустил, и столько же раз прочитай канал.

Подвох. Последний кусок бывает короче: ограничь правую границу через len(nums). При пустом срезе size равен 0, и шаг 0 даст бесконечный цикл. Такой случай проверь отдельно.

Как решать

Как решать. Канал с буфером на 1, горутина пишет в него f(). Затем select с двумя case: пришёл результат → v, true; сработал time.After(d) → 0, false.

Подвох. Без буфера опоздавшая горутина навсегда застрянет на отправке, потому что читать уже некому.

6.2 sync: WaitGroup и Mutex

WaitGroup — дождаться группу горутин:

var wg sync.WaitGroup
for _, url := range urls {
    wg.Add(1)                 // +1 к счётчику ДО запуска
    go func() {
        defer wg.Done()       // −1 при выходе
        fetch(url)
    }()
}
wg.Wait()                     // ждём, пока счётчик станет 0

Гонка данных и Mutex:

Если две горутины одновременно меняют одну переменную, получается гонка данных: n++ на самом деле состоит из трёх шагов (прочитать, прибавить, записать), и часть увеличений теряется. Mutex пропускает к данным только одну горутину за раз:

type Counter struct {
    mu sync.Mutex
    n  int
}
func (c *Counter) Inc() {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.n++
}

Гонки ищет детектор: go test -race. Проверка домашек раздела 6 запускается с ним.

6.2 sync: WaitGroup и Mutex

Пул воркеров:

Если запустить горутину на каждую из миллиона задач, можно перегрузить базу или чужой API. Пул ограничивает параллелизм: N воркеров берут задачи из общего канала.

jobs := make(chan int)
for range workers {             // запускаем N воркеров
    wg.Add(1)
    go func() {
        defer wg.Done()
        for j := range jobs { … }  // берут задачи, пока канал не закроют
    }()
}
for _, j := range all { jobs <- j }
close(jobs)
wg.Wait()

Когда что использовать:

  • передать данные или сигнал между горутинами — канал
  • дождаться завершения группы — sync.WaitGroup
  • защитить общее состояние (кэш, счётчик) — sync.Mutex

Домашка 6.2

Как решать

Как решать. В обоих методах: c.mu.Lock(), defer c.mu.Unlock(), потом работа с c.n.

Подвох. Value тоже должен брать блокировку: чтение во время записи — тоже гонка, и -race её найдёт.

Как решать

Как решать. results := make([]int, len(urls)), WaitGroup. Для каждого url: wg.Add(1) и горутина с defer wg.Done(), внутри results[i] = fetch(url). В конце wg.Wait().

Подвох. wg.Add вызывай до go, а не внутри горутины. Иначе Wait может завершиться раньше, чем горутины успеют стартовать.

Как решать

Как решать. Схема из конспекта: канал индексов, workers горутин читают его через range и пишут results[i] = f(jobs[i]). Отправь все индексы, закрой канал, дождись wg.Wait().

Подвох. Если не закрыть канал, воркеры будут ждать вечно, и Wait не вернётся.
